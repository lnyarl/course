컨테이너 네트워크

지금까지의 컨테이너는 호스트와 같은 네트워크 스택을 썼습니다. 같은 IP, 같은 포트 공간, 같은 방화벽 규칙을 공유하니 두 컨테이너가 모두 8080을 열 수 없었습니다. 이 장에서는 컨테이너마다 자기만의 네트워크 스택을 주고, 가상 이더넷 케이블(veth)과 가상 스위치(bridge)로 연결한 뒤, NAT로 바깥에 나갈 길을 엽니다. docker run의 기본 네트워크가 실제로 하는 일이 정확히 이것입니다.

학습 목표

  • 네트워크 네임스페이스가 격리하는 것(장치, 주소, 경로, 방화벽, 포트)을 설명할 수 있다.
  • veth 쌍과 브리지로 컨테이너와 호스트를 연결하는 구조를 그리고, ip 명령으로 조립할 수 있다.
  • 패킷이 컨테이너에서 인터넷까지 가는 경로(브리지, 라우팅, FORWARD, MASQUERADE, conntrack)를 따라갈 수 있다.
  • 5장의 파이프 장벽에 네트워크 준비 단계를 더하고, 새 네트워크 네임스페이스를 누가 설정할 수 있는지(소유 user 네임스페이스) 설명할 수 있다.
  • myctr run --rootfs ./rootfs --net none|host|bridge를 구현해 누적 기준(root 필수 54개, rootless 37개)을 통과시킨다.
이 장은 5장 참조 구현에서 이어집니다 3~5장의 rootfs·새 /proc·/dev·ID 매핑·파이프 장벽·cgroup을 유지하고 네트워크를 더합니다. 부모의 ip·nsenter는 호스트 도구이고, exec 뒤의 ip·curl은 rootfs에 설치한 Alpine 도구입니다. bridge 모드는 호스트에 장치와 방화벽 규칙을 만들어야 하므로 sudo가 필요하고, rootless로는 none과 host만 쓸 수 있습니다(4절).

2. 네트워크 네임스페이스

CLONE_NEWNET으로 만든 네트워크 네임스페이스는 네트워크 스택 전체의 복사본이 아니라 빈 스택에서 시작합니다. 마운트 네임스페이스가 부모의 목록을 복사하는 것과 다릅니다. 새 네임스페이스에 있는 것은 꺼진 loopback 하나뿐입니다.

3. veth와 브리지

빈 네임스페이스를 바깥과 잇는 도구는 두 가지입니다.

  • veth 쌍: 양 끝이 있는 가상 이더넷 케이블입니다. 한쪽으로 들어간 프레임은 반드시 반대쪽으로 나옵니다. 한쪽 끝을 컨테이너 네임스페이스로 옮기면 두 세계를 잇는 통로가 됩니다. 한쪽을 지우면 쌍 전체가 사라집니다.
  • 브리지: 커널 안의 가상 L2 스위치입니다. 여러 veth의 호스트 쪽 끝을 브리지에 꽂으면 컨테이너끼리 같은 LAN에 있는 것처럼 통신합니다. 브리지 자신에게 IP(10.88.0.1)를 주면 호스트도 그 LAN의 한 구성원, 즉 게이트웨이가 됩니다.

실제로 실행 중인 컨테이너를 양쪽에서 본 결과입니다. 이름 뒤의 @ifN은 짝의 인터페이스 번호입니다. 컨테이너의 eth0(15번)은 16번을, 호스트의 veth58(16번)은 15번을 가리킵니다.

host$ ip -br link show master myctr0
veth58@if15      UP             ee:7f:4f:97:f6:20 <BROADCAST,MULTICAST,UP,LOWER_UP>
host$ sudo nsenter -t <컨테이너 PID> -n ip -d link show eth0
15: eth0@if16: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP ...
    link/ether c2:4d:cf:76:e5:b2 brd ff:ff:ff:ff:ff:ff link-netnsid 0 ...
    veth ...
bridge 모드 조립 과정
참조 구현의 setup_bridge_net이 실행하는 명령을 한 줄씩 따라갑니다. 각 명령이 어느 네임스페이스에서 실행되는지 주목하세요.

4. 누가 꾸미나: 파이프 장벽과 소유권

컨테이너 쪽 eth0에 주소를 주는 일은 컨테이너 네임스페이스 안에서 해야 하지만, veth를 만들고 브리지에 꽂는 일은 호스트에서 해야 합니다. 둘 다 할 수 있는 쪽은 부모(myctr)입니다. 부모는 호스트에 있고, nsenter -t <자식 PID> -n으로 자식의 네트워크 네임스페이스에 잠깐 들어갈 수 있습니다(2장의 setns).

타이밍 문제는 5장에서 이미 풀었습니다. 자식은 파이프에서 1바이트를 받을 때까지 exec하지 않고, 부모는 cgroup 배치와 ID 매핑을 끝낸 뒤 1바이트를 보냅니다. 이 장은 그 사이에 네트워크 단계 하나를 끼워 넣을 뿐입니다. 네트워크를 매핑 뒤, 마지막에 두는 이유는 호스트에 흔적(veth, 브리지, 방화벽 규칙)을 남기는 단계이기 때문입니다. 앞의 값싼 단계가 실패하면 호스트를 건드리기 전에 끝납니다.

새 네트워크 네임스페이스의 주인

clone에 CLONE_NEWUSER와 CLONE_NEWNET을 함께 주면, 커널은 user 네임스페이스를 먼저 만들고 나머지 네임스페이스를 그 user 네임스페이스의 소유로 만듭니다. 네트워크 네임스페이스를 설정하려면 그 소유 user 네임스페이스 안에서 CAP_NET_ADMIN 같은 권한이 있어야 합니다. 그래서 모드마다 부모가 들어가는 방법이 달라집니다.

실행net ns의 주인부모가 들어가는 방법bridge
sudo myctr run --rootfs ./rootfs최상위 user nsnsenter -t PID -n가능
sudo myctr run --rootfs ./rootfs-range --userns-base 100000자식의 user nsnsenter -t PID -n. 호스트 root는 조상 user ns의 권한자라 하위 ns에도 권한이 있다가능
myctr run --rootfs ./rootfs-user (rootless)자식의 user nsnsenter -t PID -U --preserve-credentials -n. 그 user ns를 만든 사용자라 그 안에서는 권한이 있지만, 호스트에서는 없다불가: 호스트 쪽 veth·브리지·iptables는 최상위 net ns를 바꾸는 일

실제로 일반 사용자로 확인한 결과입니다.

$ myctr run --rootfs ./rootfs-user sleep 100 &                                  # rootless, --net none
$ nsenter -t $(pgrep -x sleep) -n ip -br link show lo
nsenter: reassociate to namespace 'ns/net' failed: Operation not permitted
$ nsenter -t $(pgrep -x sleep) -U -n ip -br link show lo
nsenter: setgroups failed: Operation not permitted          ← 5장의 setgroups=deny
$ nsenter -t $(pgrep -x sleep) -U --preserve-credentials -n ip -br link show lo
lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP>
$ myctr run --rootfs ./rootfs-user sh -c 'ip link add vX type veth peer name vY && echo 안에서는 됨'
안에서는 됨                                                 ← 자기 net ns 안에서는 권한이 있다
$ ip link add vX type veth peer name vY                      # 호스트에서 같은 사용자로
RTNETLINK answers: Operation not permitted
$ myctr run --rootfs ./rootfs-user --net bridge true
Error: --net bridge는 root로 실행할 때만 쓸 수 있습니다

두 번째 실패가 5장의 흔적입니다. nsenter -U는 기본적으로 들어간 뒤 보조 그룹을 비우려고 setgroups를 부르는데, rootless 컨테이너는 5장에서 setgroups를 deny로 막아 두었습니다. --preserve-credentials는 자격 증명을 바꾸지 않고 들어가게 합니다.

rootless 컨테이너는 어떻게 인터넷에 나가나 호스트에 장치를 만들 수 없으니, Podman 같은 rootless 런타임은 사용자 공간 네트워크 스택을 씁니다. slirp4netns나 pasta가 컨테이너 net ns 안에 tap 장치를 만들고, 그 장치로 나오는 패킷을 일반 사용자 권한의 소켓 호출(connect, sendto)로 바꿔 대신 내보냅니다. 커널의 NAT 대신 프로세스가 중계하는 셈이라 느리지만 root가 필요 없습니다.

5. 바깥으로: 포워딩과 NAT

브리지까지만 연결하면 컨테이너끼리, 그리고 컨테이너와 호스트는 통신할 수 있지만 인터넷은 안 됩니다. 10.88.0.x는 사설 주소라 바깥 라우터가 응답을 돌려보낼 방법이 없기 때문입니다. 세 가지가 더 필요합니다.

설정명령 (참조 구현)하는 일
IP 포워딩echo 1 > /proc/sys/net/ipv4/ip_forward호스트가 한 인터페이스(myctr0)로 들어온 패킷을 다른 인터페이스(eth0)로 넘겨주는 "라우터"가 되도록 허락
FORWARD 허용iptables -A FORWARD -i myctr0 -j ACCEPT
iptables -A FORWARD -o myctr0 -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT		넘겨주는 패킷을 방화벽이 통과시키도록. 컨테이너가 시작한 연결과 그 응답만 허용
MASQUERADEiptables -t nat -A POSTROUTING -s 10.88.0.0/24 ! -o myctr0 -j MASQUERADE나가는 패킷의 출발 주소를 호스트의 주소로 바꿔 씀(SNAT). 응답이 호스트로 돌아오면 커널이 기억해 둔 대로 되돌려 컨테이너에 전달

"기억해 둔 대로"가 conntrack(연결 추적)입니다. 컨테이너에서 curl http://1.1.1.1을 한 직후 호스트의 conntrack 표를 실제로 확인한 결과입니다.

host$ grep 10.88 /proc/net/nf_conntrack
ipv4 2 tcp 6 59 CLOSE_WAIT src=10.88.0.62 dst=1.1.1.1 sport=41586 dport=80 src=1.1.1.1 dst=172.17.0.3 sport=80 dport=41586 [ASSURED] ...
conntrack 항목 읽기
한 줄에 방향이 두 개 들어 있습니다. 앞쪽은 원래 방향(컨테이너가 보낸 그대로), 뒤쪽은 응답 방향(바깥에서 돌아올 모습)입니다. 주황색이 MASQUERADE가 바꾼 부분입니다.
응답 방향의 목적지가 컨테이너(10.88.0.62)가 아니라 호스트의 eth0 주소(172.17.0.3)입니다. 바깥 세상은 호스트하고만 대화한다고 믿습니다. 응답 패킷이 172.17.0.3:41586으로 돌아오면, 커널은 이 항목을 찾아 목적지를 10.88.0.62:41586으로 되돌려 브리지로 보냅니다.
호스트에 Docker나 ufw가 있다면 Docker는 설치될 때 FORWARD 체인의 기본 정책을 DROP으로 바꾸고, ufw도 기본적으로 포워딩을 막습니다. 그래서 참조 구현은 포워딩을 허용하는 규칙을 명시적으로 넣습니다. 그래도 컨테이너에서 바깥으로 나가지 못하면 sudo iptables -S FORWARD로 우리 규칙보다 앞에서 막는 규칙이 없는지 확인하세요. 같은 이유로 myctr는 Docker의 대역(172.17.0.0/16)과 겹치지 않는 10.88.0.0/24를 씁니다.

7. 주소 배정과 DNS

주소 배정 (IPAM)

참조 구현은 myctr의 PID로 주소를 정합니다. 10.88.0.(2 + PID % 253). 상태 파일 없이 동작하는 가장 단순한 방법이지만, PID가 253 차이 나는 두 컨테이너는 같은 주소를 받습니다. 실제 런타임은 IPAM(IP Address Management)이 할당 상태를 파일이나 데이터베이스에 기록합니다. 동시에 몇 개를 띄우면 충돌이 날 만한지 계산해 보세요.

컨테이너는 rootfs 안의 /etc/resolv.conf로 이름을 해석합니다. 실행마다 별도 resolver 파일을 준비해 bind하므로 공유 rootfs의 원본 파일은 덮어쓰지 않습니다. bridge 모드에서 호스트의 127.0.0.53을 그대로 쓰면 컨테이너 자신의 loopback을 가리켜 실패합니다. 사용할 upstream resolver를 명시하거나 호스트의 실제 upstream 설정을 확인해야 합니다.

resolvectl status | grep 'DNS Servers'   # 실제 상위 DNS 서버

이 장에서 rootfs와 네트워크를 함께 연결합니다. bridge에는 그 namespace에서 도달 가능한 DNS 주소가 필요합니다. 지정한 DNS는 파일 구성에 쓰이며 서버를 자동 실행하는 옵션은 아닙니다. 로컬 DNS·HTTP fixture로 동작을 확인하고, 외부 인터넷 검사는 별도로 표시합니다.

/// "64M", "1G", "512K", "1048576" 을 바이트 수로
fn parse_bytes(s: &str) -> Result<u64, String> {
    let (num, mul) = match s.chars().last() {
        Some('K' | 'k') => (&s[..s.len() - 1], 1 << 10),
        Some('M' | 'm') => (&s[..s.len() - 1], 1 << 20),
        Some('G' | 'g') => (&s[..s.len() - 1], 1 << 30),
        _ => (s, 1),
    };
    num.parse::<u64>().map(|n| n * mul).map_err(|e| format!("{s}: {e}"))
}

fn run(rootfs: PathBuf, 
    hostname: String,
    init: bool,
    argv: Vec<CString>,
    limits: &Limits,
    userns_base: Option<u32>,
    net: Net,
    dns: Vec<IpAddr>,
) -> Result<i32> {
    let rootless = !Uid::effective().is_root();
    let idmap = match (rootless, userns_base) {
        (true, Some(_)) => bail!("--userns-base는 root로 실행할 때만 쓸 수 있습니다"),
        (true, None) => Some(IdMap::rootless()),
        (false, Some(base)) => {
            if base.checked_add(USERNS_RANGE - 1).is_none_or(|last| last == u32::MAX) {
                bail!("--userns-base는 0..4294901759 범위여야 합니다 (65536개 ID, UID/GID -1 제외)");
            }
            Some(IdMap::range(base))
        },
        (false, None) => None,
    };
    if rootless && net == Net::Bridge {
        // veth·브리지·iptables는 호스트(최상위) 네트워크 네임스페이스를 바꾸는 일이다
        bail!("--net bridge는 root로 실행할 때만 쓸 수 있습니다");
    }
    let resolver = Resolver::prepare(&rootfs, net, &dns)?;
    let cgroup = if rootless {
        if limits.any() {
            bail!("rootless 모드에서는 --memory/--cpus/--pids를 쓸 수 없습니다 (cgroup 위임이 필요합니다)");
        }
        None
    } else {
        Some(Cgroup::create(&format!("ctr-{}", std::process::id()), limits)?)
    };

    // O_CLOEXEC: 사용자 프로그램으로 새지 않게
    let (sync_rd, sync_wr) = pipe2(OFlag::O_CLOEXEC).context("pipe")?;
    let cfg = Config { rootfs, resolver: resolver.path.clone(),
        hostname, init, argv,
        sync: (sync_rd.as_raw_fd(), sync_wr.as_raw_fd()),
        userns: idmap.is_some(),
        // 특권 range 모드에서는 상속한 호스트 보조 그룹을 남기지 않는다.
        // rootless는 setgroups=deny이므로 변경할 수 없다.
        clear_groups: idmap.as_ref().is_some_and(|map| !map.deny_setgroups),
    };

    let mut flags = CloneFlags::CLONE_NEWUTS | CloneFlags::CLONE_NEWPID | CloneFlags::CLONE_NEWNS;
    if idmap.is_some() {
        flags |= CloneFlags::CLONE_NEWUSER;
    }
    if net != Net::Host {
        flags |= CloneFlags::CLONE_NEWNET;
    }
    let mut stack = vec![0u8; STACK_SIZE];
    let cb = Box::new(|| container_main(&cfg));
    let child = unsafe { clone(cb, &mut stack, flags, Some(Signal::SIGCHLD as i32)) }
        .context("clone 실패")?;
    drop(sync_rd);

    // 준비 실패 시 먼저 파이프를 닫는다. 자식은 EOF를 받고 종료하며,
    // 부모는 반드시 wait로 회수한 뒤 cgroup을 정리한다.
    let mut veth_guard = None;
    let prepared = (|| -> Result<()> {
        if let Some(cg) = &cgroup {
            cg.add(child)?;
        }
        if let Some(map) = &idmap {
            map.write(child)?;
        }
        // 매핑까지 끝난 뒤에 네트워크. 자식은 아직 파이프에서 기다린다
        let ns = NetnsEnter { child, via_userns: rootless };
        match net {
            Net::Host => {}
            Net::None => ns.run(&["ip", "link", "set", "lo", "up"])?,
            Net::Bridge => { veth_guard = Some(setup_bridge_net(&ns, std::process::id())?); },
        }
        unsafe { signal(Signal::SIGINT, SigHandler::SigIgn) }
            .context("signal 설정 실패")?;
        write(&sync_wr, &[1]).context("자식 깨우기")?;
        Ok(())
    })();
    drop(sync_wr);
    if let Err(error) = prepared {
        // EOF로 종료한 PID 1을 회수하기 전에 Cgroup::drop이 실행되면
        // cgroup.procs가 비어 있지 않아 정리가 실패할 수 있다.
        wait_exit_code(child).context("준비 실패한 자식 회수")?;
        return Err(error);
    }
    let code = wait_exit_code(child)?;
    if cgroup.as_ref().is_some_and(|cg| cg.oom_kills() > 0) {
        eprintln!("myctr: 메모리 상한을 넘어 OOM killer가 프로세스를 종료했습니다");
    }
    Ok(code)
}

fn wait_exit_code(child: Pid) -> Result<i32> {
    loop {
        match waitpid(child, None) {
            Ok(WaitStatus::Exited(_, code)) => return Ok(code),
            Ok(WaitStatus::Signaled(_, sig, _)) => return Ok(128 + sig as i32),
            Ok(other) => bail!("예상하지 못한 상태: {other:?}"),
            Err(Errno::EINTR) => continue,
            Err(error) => return Err(error).context("waitpid 실패"),
        }
    }
}

/// 외부 명령을 실행하고 실패하면 stderr를 에러에 담는다
fn sh(args: &[&str]) -> Result<()> {
    let out = Cmd::new(args[0])
        .args(&args[1..])
        .output()
        .with_context(|| format!("{} 실행", args[0]))?;
    if !out.status.success() {
        bail!("{}: {}", args.join(" "), String::from_utf8_lossy(&out.stderr).trim());
    }
    Ok(())
}

/// 성공 여부만 본다 (규칙이 이미 있는지 확인할 때)
fn sh_ok(args: &[&str]) -> bool {
    Cmd::new(args[0]).args(&args[1..]).output().is_ok_and(|o| o.status.success())
}

/// 자식의 네트워크 네임스페이스 안에서 명령을 실행하는 방법
struct NetnsEnter {
    child: Pid,
    /// rootless: 호스트에서 권한이 없으므로 자식의 user 네임스페이스를 거쳐 들어간다
    via_userns: bool,
}

impl NetnsEnter {
    fn run(&self, args: &[&str]) -> Result<()> {
        let target = self.child.to_string();
        let mut full = vec!["nsenter", "-t", target.as_str()];
        if self.via_userns {
            // 5장의 setgroups=deny 때문에 nsenter가 자격 증명을 바꾸지 않게 한다
            full.extend_from_slice(&["-U", "--preserve-credentials"]);
        }
        full.push("-n");
        full.extend_from_slice(args);
        sh(&full)
    }
}

/// 브리지, 포워딩, NAT. 모든 컨테이너가 공유하므로 없을 때만 만든다
fn ensure_bridge() -> Result<()> {
    if !sh_ok(&["ip", "link", "show", BRIDGE]) {
        sh(&["ip", "link", "add", BRIDGE, "type", "bridge"])?;
        sh(&["ip", "addr", "add", &format!("{GATEWAY}/24"), "dev", BRIDGE])?;
    }
    sh(&["ip", "link", "set", BRIDGE, "up"])?;
    fs::write("/proc/sys/net/ipv4/ip_forward", "1").context("ip_forward 켜기")?;
    let rules: [&[&str]; 3] = [
        &["-t", "nat", "POSTROUTING", "-s", SUBNET, "!", "-o", BRIDGE, "-j", "MASQUERADE"],
        &["-t", "filter", "FORWARD", "-i", BRIDGE, "-j", "ACCEPT"],
        &["-t", "filter", "FORWARD", "-o", BRIDGE, "-m", "conntrack", "--ctstate", "RELATED,ESTABLISHED", "-j", "ACCEPT"],
    ];
    for rule in rules {
        // iptables -t <표> -C <체인> ... 로 있는지 보고, 없으면 -A
        let (table, rest) = rule.split_at(2);
        let mut check = vec!["iptables"];
        check.extend_from_slice(table);
        check.push("-C");
        check.extend_from_slice(rest);
        if !sh_ok(&check) {
            check[3] = "-A";
            sh(&check)?;
        }
    }
    Ok(())
}

struct VethGuard { name: String }
impl Drop for VethGuard {
    fn drop(&mut self) { let _ = sh(&["ip", "link", "del", &self.name]); }
}

fn setup_bridge_net(ns: &NetnsEnter, id: u32) -> Result<VethGuard> {
    ensure_bridge()?;
    // 인터페이스 이름은 15자 제한. 컨테이너 쪽은 옮긴 뒤 eth0으로 바꾼다
    let host_if = format!("veth{id}");
    let peer_if = format!("ceth{id}");
    // 간단한 주소 배정: 10.88.0.2 ~ 10.88.0.254
    let ip = format!("10.88.0.{}/24", 2 + id % 253);

    sh(&["ip", "link", "add", &host_if, "type", "veth", "peer", "name", &peer_if])?;
    let guard = VethGuard { name: host_if.clone() };
    sh(&["ip", "link", "set", &host_if, "master", BRIDGE, "up"])?;
    sh(&["ip", "link", "set", &peer_if, "netns", &ns.child.to_string()])?;

    ns.run(&["ip", "link", "set", "lo", "up"])?;
    ns.run(&["ip", "link", "set", &peer_if, "name", "eth0"])?;
    ns.run(&["ip", "addr", "add", &ip, "dev", "eth0"])?;
    ns.run(&["ip", "link", "set", "eth0", "up"])?;
    ns.run(&["ip", "route", "add", "default", "via", GATEWAY])?;
    Ok(guard)
}

/// 실행마다 별도 resolver 파일. 자식을 회수한 뒤 삭제된다.
struct Resolver { path: PathBuf }
impl Resolver {
    fn prepare(rootfs: &Path, net: Net, dns: &[IpAddr]) -> Result<Self> {
        let content = if dns.is_empty() {
            let text = fs::read_to_string("/etc/resolv.conf").context("호스트 resolver 읽기")?;
            let loopback = text.lines().any(|line| {
                let mut words = line.split_whitespace();
                words.next() == Some("nameserver") && words.next()
                    .and_then(|v| v.parse::<IpAddr>().ok()).is_some_and(|ip| ip.is_loopback())
            });
            if net == Net::Bridge && loopback {
                bail!("호스트 resolver가 loopback입니다. bridge에서 접근 가능한 --dns ADDRESS를 지정하세요");
            }
            text
        } else {
            dns.iter().map(|ip| format!("nameserver {ip}\n")).collect()
        };
        let target = rootfs.join("etc/resolv.conf");
        match fs::symlink_metadata(&target) {
            Ok(meta) if !meta.is_file() => bail!("rootfs/etc/resolv.conf는 일반 파일이어야 합니다"),
            Ok(_) => {},
            Err(error) if error.kind() == std::io::ErrorKind::NotFound => {
                OpenOptions::new().write(true).create_new(true).open(&target)
                    .context("resolv.conf 마운트 대상 만들기")?;
            },
            Err(error) => return Err(error).context("resolv.conf 대상 확인"),
        }
        let path = std::env::temp_dir().join(format!("myctr-resolv-{}", std::process::id()));
        let mut file = OpenOptions::new().write(true).create_new(true).mode(0o644).open(&path)
            .context("전용 resolver 파일 만들기")?;
        let resolver = Self { path };
        file.write_all(content.as_bytes()).context("resolver 쓰기")?;
        Ok(resolver)
    }
}
impl Drop for Resolver {
    fn drop(&mut self) { let _ = fs::remove_file(&self.path); }
}

/// user 네임스페이스의 UID/GID 매핑
struct IdMap {
    uid_map: String,
    gid_map: String,
    /// 비특권 프로세스가 gid_map을 쓰려면 먼저 setgroups를 막아야 한다
    deny_setgroups: bool,
}

impl IdMap {
    /// 컨테이너 root(0) 하나를 나 자신에게
    fn rootless() -> Self {
        IdMap {
            uid_map: format!("0 {} 1", Uid::effective()),
            gid_map: format!("0 {} 1", Gid::effective()),
            deny_setgroups: true,
        }
    }

    /// 컨테이너의 0..65535 를 호스트의 base..base+65535 로
    fn range(base: u32) -> Self {
        IdMap {
            uid_map: format!("0 {base} {USERNS_RANGE}"),
            gid_map: format!("0 {base} {USERNS_RANGE}"),
            deny_setgroups: false,
        }
    }

    fn write(&self, pid: Pid) -> Result<()> {
        let proc = PathBuf::from(format!("/proc/{pid}"));
        if self.deny_setgroups {
            fs::write(proc.join("setgroups"), "deny").context("setgroups 막기")?;
        }
        fs::write(proc.join("uid_map"), &self.uid_map)
            .with_context(|| format!("uid_map 쓰기 ({})", self.uid_map))?;
        fs::write(proc.join("gid_map"), &self.gid_map)
            .with_context(|| format!("gid_map 쓰기 ({})", self.gid_map))?;
        Ok(())
    }
}

struct Cgroup {
    path: PathBuf,
}

impl Cgroup {
    fn create(name: &str, limits: &Limits) -> Result<Self> {
        let parent = Path::new(CGROUP_ROOT).join(CGROUP_PARENT);
        fs::create_dir_all(&parent).with_context(|| format!("{} 만들기", parent.display()))?;
        // 부모에서 컨트롤러를 켜야 자식 cgroup에 memory.max 같은 파일이 생긴다
        fs::write(parent.join("cgroup.subtree_control"), "+memory +cpu +pids")
            .context("컨트롤러 활성화 (상위 cgroup의 cgroup.subtree_control에 memory cpu pids가 켜져 있나요?)")?;

        let path = parent.join(name);
        fs::create_dir(&path).with_context(|| format!("{} 만들기", path.display()))?;
        let cg = Cgroup { path };
        if let Some(bytes) = limits.memory {
            cg.write("memory.max", &bytes.to_string())?;
            // 스왑으로 도망가지 못하게. 스왑 계정이 꺼진 커널에는 파일이 없다
            if cg.path.join("memory.swap.max").exists() {
                cg.write("memory.swap.max", "0")?;
            }
        }
        if let Some(cpus) = limits.cpus {
            let quota = (cpus * CPU_PERIOD_US as f64) as u64;
            cg.write("cpu.max", &format!("{quota} {CPU_PERIOD_US}"))?;
        }
        if let Some(n) = limits.pids {
            cg.write("pids.max", &n.to_string())?;
        }
        Ok(cg)
    }

    fn write(&self, file: &str, value: &str) -> Result<()> {
        fs::write(self.path.join(file), value)
            .with_context(|| format!("{}/{file} 에 {value} 쓰기", self.path.display()))
    }

    /// 프로세스를 이 cgroup으로 옮긴다 (호스트 PID)
    fn add(&self, pid: Pid) -> Result<()> {
        self.write("cgroup.procs", &pid.to_string())
    }

    /// memory.events 의 oom_kill 카운터
    fn oom_kills(&self) -> u64 {
        fs::read_to_string(self.path.join("memory.events"))
            .ok()
            .and_then(|s| {
                s.lines()
                    .find_map(|l| l.strip_prefix("oom_kill ").and_then(|n| n.parse().ok()))
            })
            .unwrap_or(0)
    }
}

impl Drop for Cgroup {
    fn drop(&mut self) {
        // 프로세스가 남아 있으면 EBUSY. PID 1이 끝나면 네임스페이스 전체가 정리되므로 비어 있다
        if let Err(e) = fs::remove_dir(&self.path) {
            eprintln!("myctr: cgroup 정리 실패 {}: {e}", self.path.display());
        }
    }
}

/// clone된 자식. 새 네임스페이스 안의 PID 1이다.
fn container_main(cfg: &Config) -> isize {
    // 부모가 cgroup, ID 매핑, 네트워크를 끝낼 때까지 기다린다.
    // 쓰는 쪽을 닫아 두어야 부모가 죽었을 때 read가 EOF(0)로 깨어난다
    let _ = close(cfg.sync.1);
    let mut buf = [0u8; 1];
    loop {
        match read(cfg.sync.0, &mut buf) {
            Ok(1) => break,
            Err(Errno::EINTR) => continue,
            _ => {
                eprintln!("myctr: 부모가 준비를 마치지 못했습니다");
                return 1;
            }
        }
    }
    let _ = close(cfg.sync.0);

    if let Err(e) = setup(cfg) {
        eprintln!("myctr: {e:#}");
        return 1;
    }
    if cfg.init { mini_init(&cfg.argv) } else { exec(&cfg.argv) }
}

/// fork와 exec 사이에서 컨테이너의 모양을 만든다
fn setup(cfg: &Config) -> Result<()> {
    if cfg.userns {
        // 매핑은 ID의 대응표만 만든다. 특히 range 모드에서 host UID 0은
        // 매핑 밖이므로, 새 namespace의 ID 0으로 자격 증명을 옮긴다.
        if cfg.clear_groups {
            setgroups(&[]).context("보조 그룹 비우기")?;
        }
        setgid(Gid::from_raw(0)).context("컨테이너 GID 0으로 전환")?;
        setuid(Uid::from_raw(0)).context("컨테이너 UID 0으로 전환")?;
    }
    sethostname(&cfg.hostname).context("sethostname")?;
    setup_rootfs(&cfg.rootfs, &cfg.resolver)?;
    Ok(())
}

/// 실습 중 호스트 /를 rootfs로 지정하거나 준비를 빠뜨리는 실수를 막는다.
/// 신뢰하는 Alpine 입력을 전제로 하며 악성 rootfs 검증기는 아니다.
fn validate_rootfs(rootfs: &Path) -> Result<()> {
    if rootfs == Path::new("/") || !rootfs.is_dir() {
        bail!("rootfs는 호스트 /가 아닌 디렉터리여야 합니다");
    }
    if !fs::symlink_metadata(rootfs.join("bin/sh")).is_ok_and(|meta| meta.is_file() || meta.file_type().is_symlink())
        || !rootfs.join("proc").is_dir() || !rootfs.join("dev").is_dir() {
        bail!("rootfs에 bin/sh와 proc·dev 디렉터리를 준비하세요");
    }
    Ok(())
}

fn setup_rootfs(rootfs: &Path, resolver: &Path) -> Result<()> {
    // 1. 이후의 마운트가 호스트로 전파되지 않도록 모든 마운트를 private으로
    mount(None::<&str>, "/", None::<&str>, MsFlags::MS_REC | MsFlags::MS_PRIVATE, None::<&str>)
        .context("/ 를 rprivate으로 바꾸기")?;

    // 2. pivot_root의 new_root는 마운트 지점이어야 하므로 자기 자신에게 bind
    mount(Some(rootfs), rootfs, None::<&str>, MsFlags::MS_BIND | MsFlags::MS_REC, None::<&str>)
        .context("rootfs bind mount")?;

    // 3. 루트를 바꾼다. 이전 루트는 /.oldroot 에 걸린다
    let old_root = rootfs.join(OLD_ROOT);
    fs::create_dir_all(&old_root).context(".oldroot 만들기")?;
    pivot_root(rootfs, &old_root).context("pivot_root")?;
    chdir("/").context("chdir /")?;

    // 4. 이 PID 네임스페이스 기준의 procfs
    mount(
        Some("proc"),
        "/proc",
        Some("proc"),
        MsFlags::MS_NOSUID | MsFlags::MS_NODEV | MsFlags::MS_NOEXEC,
        None::<&str>,
    )
    .context("/proc 마운트")?;

    // 5. 최소한의 /dev. 장치 파일은 아직 붙어 있는 이전 루트에서 bind로 빌려 온다
    setup_dev().context("/dev 구성")?;

    // 이 실행 전용 DNS 파일을 붙인다. 공유 rootfs의 기존 내용은 덮어쓰지 않는다.
    let source = format!("/{OLD_ROOT}{}", resolver.display());
    mount(Some(source.as_str()), "/etc/resolv.conf", None::<&str>, MsFlags::MS_BIND, None::<&str>)
        .context("전용 resolv.conf bind")?;
    mount(None::<&str>, "/etc/resolv.conf", None::<&str>,
          MsFlags::MS_BIND | MsFlags::MS_REMOUNT | MsFlags::MS_RDONLY, None::<&str>)
        .context("resolv.conf 읽기 전용")?;

    // 6. 이전 루트를 떼어 내고 흔적을 지운다
    let old = format!("/{OLD_ROOT}");
    umount2(old.as_str(), MntFlags::MNT_DETACH).context("이전 루트 분리")?;
    fs::remove_dir(&old).context(".oldroot 지우기")?;
    Ok(())
}

fn setup_dev() -> Result<()> {
    mount(
        Some("tmpfs"),
        "/dev",
        Some("tmpfs"),
        MsFlags::MS_NOSUID | MsFlags::MS_STRICTATIME,
        Some("mode=755,size=65536k"),
    )?;
    for dev in DEVICES {
        let target = format!("/dev/{dev}");
        File::create(&target).with_context(|| format!("{target} 만들기"))?;
        let source = format!("/{OLD_ROOT}/dev/{dev}");
        mount(Some(source.as_str()), target.as_str(), None::<&str>, MsFlags::MS_BIND, None::<&str>)
            .with_context(|| format!("{target} bind"))?;
    }
    for (link, to) in [
        ("/dev/fd", "/proc/self/fd"),
        ("/dev/stdin", "/proc/self/fd/0"),
        ("/dev/stdout", "/proc/self/fd/1"),
        ("/dev/stderr", "/proc/self/fd/2"),
    ] {
        symlink(to, link).with_context(|| format!("{link} 링크"))?;
    }
    Ok(())
}

/// 성공하면 돌아오지 않는다. 돌아오면 127.
fn exec(argv: &[CString]) -> isize {
    if let Err(e) = unsafe { signal(Signal::SIGPIPE, SigHandler::SigDfl) } {
        eprintln!("myctr: SIGPIPE 복원 실패: {e}");
        return 1;
    }
    let err = execvp(&argv[0], argv).unwrap_err();
    eprintln!("myctr: {}: {err}", argv[0].to_string_lossy());
    127
}

/// PID 1로 남아 명령을 PID 2로 띄우고, 입양된 고아까지 거두다가
/// 명령이 끝나면 그 종료 코드로 끝난다.
fn mini_init(argv: &[CString]) -> isize {
    let main_child = match unsafe { fork() } {
        Ok(ForkResult::Child) => unsafe { libc::_exit(exec(argv) as i32) },
        Ok(ForkResult::Parent { child }) => child,
        Err(e) => {
            eprintln!("myctr-init: fork: {e}");
            return 1;
        }
    };
    loop {
        match waitpid(None, None) {
            Ok(WaitStatus::Exited(pid, code)) if pid == main_child => return code as isize,
            Ok(WaitStatus::Signaled(pid, sig, _)) if pid == main_child => return 128 + sig as isize,
            Ok(_) => continue,
            Err(Errno::EINTR) => continue,
            Err(e) => {
                eprintln!("myctr-init: waitpid: {e}");
                return 1;
            }
        }
    }
}

핵심 요약

  • 네트워크 네임스페이스는 장치, 주소, 경로, 방화벽, 포트 공간을 격리하며 빈 스택(꺼진 lo)에서 시작합니다.
  • veth 쌍은 두 네임스페이스를 잇는 가상 케이블이고, 브리지는 여러 veth를 묶는 가상 스위치입니다. 브리지의 IP가 컨테이너들의 게이트웨이가 됩니다.
  • 호스트와 컨테이너 양쪽을 꾸밀 수 있는 것은 부모입니다. 5장의 파이프 장벽에 네트워크 단계를 더해, 자식은 매핑과 네트워크가 끝난 뒤 rootfs를 준비하고 exec합니다.
  • 새 net ns는 함께 만든 user ns의 소유입니다. 호스트 root는 nsenter -n으로 들어갈 수 있고, rootless 사용자는 -U --preserve-credentials로 자기 user ns를 거쳐야 합니다. 호스트 쪽 장치를 만들 수 없으므로 rootless bridge는 불가능합니다.
  • 인터넷으로 나가려면 ip_forward, FORWARD 허용, MASQUERADE가 필요합니다. conntrack이 원래 방향과 응답 방향을 기억해 응답을 컨테이너로 되돌립니다.
  • veth는 네트워크 네임스페이스와 함께 (비동기로) 사라지고, 브리지와 iptables 규칙은 공유 자원이라 남습니다.
  • ip 명령은 netlink 소켓(NETLINK_ROUTE)으로 커널과 대화합니다. 실제 런타임은 netlink를 직접 씁니다.

확인 문제

CLONE_NEWNET으로 만든 직후의 네트워크 네임스페이스에 있는 것은?
네트워크 네임스페이스는 빈 스택에서 시작합니다. lo는 있지만 꺼져 있어서, none 모드에서도 ip link set lo up을 해 줘야 127.0.0.1을 쓸 수 있습니다.
자식이 파이프의 쓰는 쪽을 닫지 않았다. 부모가 네트워크 설정 중 에러로 종료하면?
파이프의 read는 쓰는 쪽 fd가 모두 닫혀야 EOF를 받습니다. clone으로 복사된 자식 자신의 쓰는 쪽이 열려 있으면 그 조건이 영원히 충족되지 않습니다.
MASQUERADE 규칙만 지우면 어떤 통신이 끊기나?
MASQUERADE는 사설 주소(10.88.0.x)를 호스트 주소로 바꿔 줍니다. 이 규칙이 없으면 패킷은 나가지만 바깥은 10.88.0.x로 응답할 방법이 없습니다. 같은 브리지 안이나 호스트와의 통신은 NAT를 거치지 않으므로 영향이 없습니다.
conntrack 항목 src=10.88.0.62 dst=1.1.1.1 ... src=1.1.1.1 dst=172.17.0.3에서 172.17.0.3은 무엇인가?
응답 방향 튜플의 목적지가 MASQUERADE가 바꿔 쓴 주소입니다. 바깥은 호스트(172.17.0.3)와 대화한다고 믿고, 커널은 이 항목으로 응답을 10.88.0.62에 되돌립니다.
통합 구현은 호스트 resolv.conf에 127.0.0.53이 있으면 bridge 시작 전에 --dns를 요구합니다. 이유는?
127.0.0.53은 호스트 네트워크 네임스페이스의 loopback에서만 의미가 있습니다. 컨테이너의 loopback에는 리졸버가 없습니다. 통합 구현은 이를 clone 전에 감지해 오류로 알립니다. bridge에서 도달 가능한 서버를 --dns ADDRESS로 지정하세요.
ip link add를 strace하면 보이는, 커널과 대화하는 통로는?
iproute2는 RTM_NEWLINK 같은 rtnetlink 메시지를 netlink 소켓으로 보내고, 응답(NLMSG_ERROR, error=0이면 성공)을 recvmsg로 받습니다. 예전의 ifconfig는 ioctl을 썼습니다.
일반 사용자로 myctr run --rootfs ./rootfs-user sleep 100(rootless, none)을 띄웠다. 같은 사용자가 nsenter -t <pid> -n으로 그 네트워크 네임스페이스에 들어가려 하면?
실제 결과는 reassociate to namespace 'ns/net' failed: Operation not permitted였습니다. 호스트(최상위 user ns)에서는 권한이 없고, 자기가 만든 user ns 안에서만 권한이 있습니다. 5장의 setgroups=deny 때문에 --preserve-credentials도 함께 필요합니다.

실습 과제

  1. 네트워크 완성. 9절 단계 A~E를 구현하고 bash check.sh rootful를 통과시킨 뒤 git tag ch06. 기대: root 필수 54 / 54, rootless 37 / 37. 외부 HTTP 1개는 별도 선택 검사.
  2. 컨테이너 두 개. 아래 bridge 예제는 호스트 resolver가 컨테이너에서 도달 가능한 환경을 전제로 합니다. loopback resolver 환경이면 접근 가능한 DNS 주소를 --dns ADDRESS로 함께 지정하세요. 터미널 1에서 sudo ./target/debug/myctr run --rootfs ./rootfs --net bridge --hostname web python3 -m http.server 8000. 터미널 2에서 sudo nsenter -t $(pgrep -x python3) -n ip -4 -br addr show eth0로 주소를 확인한 뒤, sudo ./target/debug/myctr run --rootfs ./rootfs --net bridge curl -s -o /dev/null -w '%{http_code}\n' http://<주소>:8000/. 기대: 200. 이어서 bridge fdb show br myctr0로 브리지가 학습한 MAC을 확인하세요.
  3. 규칙 하나씩 빼 보기. MASQUERADE 규칙을 -D로 지우고 bridge 모드에서 curl http://1.1.1.1이 어떻게 되는지(기대: 시간 초과), tcpdump -ni eth0 host 1.1.1.1(호스트에서)로 나가는 패킷의 출발 주소가 10.88.0.x인지 확인하세요. 다시 myctr를 실행하면 규칙이 복구되는지도 보세요(기대: 복구됨, -C로 확인 후 추가하므로).
  4. netlink 관찰. sudo strace -f -e trace=socket,sendmsg -o /tmp/net.trace ./target/debug/myctr run --rootfs ./rootfs --net bridge true 후 grep -c NETLINK /tmp/net.trace로 컨테이너 하나를 띄우는 데 netlink 소켓이 몇 번 열렸는지 세어 보세요. 외부 명령 하나가 소켓 하나입니다.
  5. rootless에서 들여다보기. 일반 사용자로 ./target/debug/myctr run --rootfs ./rootfs-user sleep 100 & 후, nsenter -t $(pgrep -x sleep) -n ip -br link, -U -n, -U --preserve-credentials -n을 차례로 실행해 4절의 결과(EPERM, setgroups 실패, 성공)를 재현하세요. 같은 사용자로 호스트에서 ip link add vX type veth peer name vY도 시도해 보세요(기대: Operation not permitted).
  6. 도전: 포트 공개 -p 8080:80. 호스트의 8080으로 들어온 연결을 컨테이너의 80으로 보내는 옵션을 추가하세요. 힌트: iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination <컨테이너IP>:80(바깥에서 들어오는 경우)와 -A OUTPUT(호스트 자신이 localhost가 아닌 주소로 접속하는 경우). 컨테이너가 끝나면 규칙을 지워야 합니다. 어디서 지우는 것이 안전할까요?
  7. 도전: IPAM. PID 기반 주소 대신 /run/myctr/ipam 파일에 사용 중인 주소를 기록하고, flock으로 동시 실행을 막으며 빈 주소를 고르게 바꾸세요. 컨테이너가 끝나면 주소를 반납합니다.
  8. 도전: netlink 직접 쓰기. rtnetlink 크레이트(tokio 기반)로 ip 명령 호출을 바꿔 보세요. 컨테이너 쪽 설정은 setns로 자식의 네트워크 네임스페이스에 들어간 스레드에서 해야 한다는 점이 까다로운 부분입니다.
