선수 장 · 기존 9장 · 결정론과 seed

12장의 내보내기는 설정과 seed로 새 마을을 시작합니다. 문제 발생 직전 tick 50의 상태로 돌아가려면 설정만으로는 부족합니다. 현재 욕구·실행 중 행동·예약·난수 진행 위치·외부 입력의 적용 순서를 포함하는 snapshot과 replay 계약을 정의합니다.

seed와 진행 중 PRNG 상태의 차이

난수 fixture를 [0.1,0.8,0.3,0.9]로 고정하고 두 번 사용한 뒤 snapshot을 찍었다고 합시다. 올바른 복원은 cursor=2에서 다음 값 0.3을 내야 합니다. seed만 다시 넣어 cursor=0으로 시작하면 0.1을 사용합니다. 선택 경계가 0.2인 두 후보라면 원래는 B, 잘못된 복원은 A를 고를 수 있습니다.

현재 UAI.rng는 내부 상태가 closure 안에 있으며 seed 필드를 저장하는 것만으로 중간 상태가 복원되지 않습니다. 확장 serializer는 PRNG의 명시적 export/import 상태 또는 입력 난수 trace를 관리해야 합니다. snapshot에는 시간·tick·주민 갱신 순서·욕구·위치·current·cooldown·오브젝트 사용 수·진행 중 예약처럼 미래를 바꾸는 권위 상태를 포함합니다.

참조 복원과 외부 이벤트 순서를 검사하기

current.target을 통째로 중복 복사하면 월드 오브젝트와 다른 인스턴스가 되어 대상 동일성 비교가 달라질 수 있습니다. 안정 ID로 저장하고 로드 시 실제 객체에 다시 연결하세요. 함수와 closure를 포함한 world 전체를 JSON.stringify 또는 structuredClone 한 번으로 완전한 실행 snapshot으로 만들 수 있다고 가정하지 않습니다. 설정 정의와 실행 상태, 캐시·진단 trace를 구분해야 합니다.

늑대 생성·시설 제거 같은 외부 이벤트에는 tick과 같은 tick 안의 sequence를 붙이고, tick 처리 전/후 중 한 적용 경계를 정합니다. 재생 검사는 snapshot50 이후 이벤트를 같은 순서로 적용해 60까지 진행한 권위 상태와, 중단 없이 60까지 진행한 상태를 비교합니다. 첫 불일치 tick에서 입력·난수 cursor·행동 전환·대상 ID를 나란히 출력하면 원인 범위를 좁힐 수 있습니다.

실습과 예상 관찰

fixture의 난수를 두 번 사용한 상태에서 다음 값을 예측한 뒤 조건을 선택하세요. 확장 실습은 월드 사본의 tick50 snapshot을 저장하고 이벤트 목록을 고정해 tick60의 값과 trace를 대조합니다. 초기 seed 재시작과 중간 snapshot 복원을 서로 다른 명령으로 표시하세요.

cursor=2까지 함께 복원

다음 난수는 0.3입니다. 0.2 경계 모형에서는 후보 B를 고릅니다.

seed만 복원하고 cursor=0으로 재시작

다음 난수는 0.1이며 같은 경계에서는 후보 A를 고릅니다. 설정 재시작을 중간 상태 복원으로 오해한 반례입니다.

대상 ID 대신 별도 객체로 current.target 복사

좌표가 같아도 참조 비교나 사용 수 갱신이 다른 객체에 적용될 수 있습니다. 안정 ID 재연결과 상태 비교가 필요합니다.
