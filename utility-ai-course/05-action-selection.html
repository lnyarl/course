행동 선택 전략과 Dual Utility

04장까지 우리는 모든 행동에 0~1 점수를 매기는 법을 배웠다. 그런데 점수표가 손에 들어온 순간 새 질문이 생긴다. "그래서 무엇을 할 것인가?" 항상 1등을 고르면 주민이 로봇처럼 보이고, 점수 비례로 제비를 뽑으면 가끔 터무니없는 짓을 한다. 이 장은 그 사이에 놓인 전략들을 하나씩 실험하고, Kevin Dill의 dual utility(rank + weight)로 마무리한다.

학습 목표

  • 최고점 선택(absolute utility)과 가중 랜덤(relative utility)의 장단점을 확률로 설명한다.
  • 가중 랜덤의 "총합 → 난수 → 빼기" 알고리즘을 손으로 따라가고, 왜 점수 비례 확률이 되는지 이해한다.
  • 상위 N개, 최고점 대비 % 이내 필터가 "바보 같은 선택"을 어떻게 줄이는지, 어떤 경우에 실패하는지 안다.
  • Dual utility의 4단계(weight ≤ 0 제거 → 최고 rank → % 필터 → 가중 랜덤)를 구현하고, Zoo Tycoon 2의 rank 설계를 해석한다.
  • 게임 종류에 따라 어떤 전략이 맞는지 판단하고, 시드 고정 RNG가 왜 필요한지 설명한다.
엔진 부품 UAI.select(cands, opt, rng) UAI.rng(seed) — 점수표에서 실행할 행동 하나를 고르는 마지막 단계와, 같은 시드면 같은 결과를 내는 난수 발생기.

1. 점수표 다음의 한 걸음: 선택

Hamlet 마을의 정오. 아리의 Reasoner가 04장 Consideration 결합을 거쳐 다음 점수표를 내놓았다고 하자 (값은 설명용 예시).

행동점수왜 이 점수인가
빵집에서 식사0.80배고픔이 꽤 찼고 빵집이 가깝다
집에서 낮잠0.72밤새 선술집에 있어서 기력이 낮다
우물가 수다0.60이웃 두 명이 우물가에 있다
선술집0.35재미는 괜찮지만 낮이라 손님이 없다
마을 산책0.15할 일 없을 때의 기본 행동
밭일0.05오늘 밭일은 이미 끝냈다

여기서 무엇을 실행할지 정하는 규칙이 선택 전략이다. 점수 계산과 분리된 독립 부품이라서, 같은 점수표라도 전략에 따라 아리가 전혀 다른 성격으로 보인다. 엔진에서는 UAI.select() 한 함수가 이 일을 맡고, Reasoner.decide()는 점수를 다 매긴 뒤 이 함수를 호출할 뿐이다.

Dill이 거듭 강조한 한 가지 Kevin Dill은 Dual-Utility Reasoning 장의 첫머리에서 각 옵션의 효용을 게임 안에서, 실행 시간에 계산하는 것이 무엇보다 중요하다고 못 박는다. 행동마다 고정 가중치를 미리 정해 두는 것만으로는 부족하고, 결정하는 그 순간의 상황으로 평가해야 효용 AI가 약속하는 반응성이 나온다는 것이다. 이 장의 모든 전략은 "점수가 매 결정마다 새로 계산된다"는 전제 위에서만 의미가 있다.

2. 최고점 선택 (absolute utility)

가장 단순한 전략이다. 점수가 가장 높은 행동을 고른다. Dill은 이것을 절대 효용(absolute utility)이라 부른다.

chosen = argmaxO UO

위 점수표라면 아리는 언제나 빵집으로 간다. 같은 상황에서는 같은 행동을 하니 디자이너가 결과를 예측하고 테스트하기 쉽다. 게임 AI 문헌에서도 이 방식이 기본값으로 자주 등장한다.

  • David Graham(Game AI Pro 1, 9장)은 체스 AI라면 반드시 최고점 수를 골라야 하고, 전략 게임도 그럴 수 있다고 쓴다.
  • Guild Wars 2: Heart of Thorns의 AI(Mike Lewis, GAP3 13장)는 think cycle마다 모든 DSE를 점수화하고 최고점 DSE를 실행한다. Lewis는 최고점 선택을 "강력히 추천(highly recommended)"한다고 괄호로 덧붙였다.
  • Dragon Age: Inquisition의 BDS(Hanlon·Watts, GAP3 31장)도 합법 행동을 열거하고 점수를 매긴 뒤 점수 내림차순 정렬의 첫 번째를 실행하는 탐욕적 구조다.

문제는 Graham이 지적한 대로 로봇 같다는 점이다. The Sims 같은 게임에서는 같은 상황에서 늘 같은 행동을 하는 캐릭터가 기계처럼 느껴진다. Dill도 절대 효용은 "가장 적절한 행동을 보장하지만 예측 가능해진다"고 정리한다. Hamlet 주민 여섯 명이 같은 시각 같은 욕구 상태라면 여섯 명이 전부 같은 빵집으로 줄을 서는 장면이 나온다.

    const maxS = Math.max(...pool.map(c => c.score));
    if (st === "best") {
      const best = pool.find(c => c.score === maxS);
      return { chosen: best, pool: [{ cand: best, p: 1 }] };
    }
동점 처리도 설계다 엔진은 pool.find를 쓰므로 동점이면 목록에서 먼저 나온 행동이 이긴다. UE5 StateTree의 "Try Select Children with Highest Utility"도 동점이면 첫 번째 자식을 고른다. 그래서 행동 정의 순서가 은근히 우선순위 역할을 한다. 점수가 0~1로 정규화되고 커브가 계단형(스위치)이면 동점이 생각보다 자주 생기니, 순서를 의도적으로 정하거나 아주 작은 tie-breaker를 더하자. 또 하나, best는 난수를 한 번도 쓰지 않는다. 8절에서 이 사실이 디버깅 함정이 된다.

3. 가중 랜덤 (relative utility)과 룰렛

반대편 극단은 점수를 확률의 비율로 쓰는 것이다. Dill의 상대 효용(relative utility), 흔히 weight-based random 또는 룰렛 휠 선택이라 부른다. 옵션 O가 뽑힐 확률은 자기 점수를 전체 점수 합으로 나눈 값이다 (GAP2 식 3.1).

PO = UO / Σi=1..n Ui

아리의 점수표에 적용하면 총합은 2.67이고 식사 30.0%, 낮잠 27.0%, 수다 22.5%, 선술집 13.1%, 산책 5.6%, 밭일 1.9%다. 가장 좋은 행동이 가장 자주 나오지만 매번은 아니다. 주민마다, 날마다 다른 일과가 생긴다.

구현: 총합 → 난수 → 빼기

Dill은 이 확률을 정렬이나 누적 배열 없이 구현하는 3단계 절차를 제시한다.

  1. 유효한 옵션(weight > 0)의 weight를 모두 더한다.
  2. 0과 그 총합 사이의 난수를 하나 뽑는다.
  3. 유효한 옵션을 차례로 돌며 난수에서 그 옵션의 weight를 뺀다. 결과가 0 이하가 되면 그 옵션을 고르고, 아니면 다음으로 넘어간다.

원판을 점수 비율대로 나누고 바늘을 무작위 각도로 던지는 것과 같다. 바늘 위치 x에서 조각 크기를 하나씩 빼 나가다 0 이하가 되는 순간이 곧 "바늘이 그 조각 안에 있다"는 뜻이다. 아래 위젯으로 직접 돌려 보자.

룰렛 휠: weight-based random 단계별로 보기
"새 난수"를 누르면 시드 고정 RNG로 난수 하나를 뽑는다. ▶ 재생 또는 다음 ▶을 누르며 총합 계산 → 바늘 던지기 → 한 조각씩 빼기를 따라가 보자. 바깥 주황 호는 지금까지 뺀 양이다. 호가 바늘을 넘는 조각이 당첨된다. 마지막 단계에서는 같은 시드로 UAI.select를 직접 호출한 결과와 비교한다.
왜 빼기만으로 점수 비례 확률이 나오나 (그리고 더 빠른 방법)

옵션 순서대로 점수를 이어 붙이면 길이 S인 선분이 구간 [0, U₁), [U₁, U₁+U₂), … 로 나뉜다. x를 [0, S)에서 균등하게 뽑으면 x가 i번째 구간에 떨어질 확률은 구간 길이 / S = Ui/S다. "x에서 앞 구간 길이들을 빼다가 0 이하가 되는 첫 i"는 정확히 x가 속한 구간의 번호다. 옵션 순서는 확률에 아무 영향이 없다.

비용은 결정 1회당 O(n)이다. 주민 한 명이 행동 수십 개 중 하나를 고르는 데는 충분하다. 같은 분포에서 수천 번 뽑아야 한다면 누적합 배열 + 이진 탐색(O(log n))이나 Walker의 alias 방법(O(1))을 쓰지만, 효용 AI에서는 점수가 결정마다 바뀌므로 미리 만든 표를 재사용할 일이 드물다.

엔진 구현은 x = r() * sum에서 시작해 x -= c.score를 반복하고 x <= 0이면 반환한다. 부동소수 오차로 끝까지 0 이하가 안 되는 경우를 대비해 마지막 후보를 돌려주는 안전장치가 있다.

대가: 가끔 터무니없는 선택

Graham은 이 방식의 반대급부를 이렇게 요약한다. 에이전트는 대부분 합리적으로 행동하지만 가끔 완전히 바보 같은 것을 고른다. Dill도 상대 효용은 좋은 옵션을 선호할 뿐이어서 효용이 아주 낮은 옵션이 뽑힐 확률이 늘 남고, 그것이 AI를 쉽게 멍청해 보이게 만든다고 쓴다.

확률이 작아 보여도 결정 횟수를 곱하면 이야기가 달라진다. 위 점수표에서 "최고점의 절반 미만"(선술집·산책·밭일)을 바보 선택이라 하면 그 합은 0.55/2.67 ≈ 20.6%다. 주민 한 명이 하루 60번 결정한다면 하루 약 12번, 마을 여섯 명이면 약 74번이다. 플레이어는 그중 한 번만 봐도 "왜 배고픈데 밭에 가지?"라고 생각한다.

점수 스케일과 확률 가중 랜덤의 확률은 점수의 비율에만 의존한다. 모든 점수에 2를 곱해도 확률은 그대로다. 반면 모든 점수에 같은 상수를 더하면 비율이 1에 가까워져 분포가 평평해진다(바보 선택이 늘어난다). 04장에서 결합 방식(product·mean·compensated)을 바꾸면 점수의 분산이 달라지니, 결합과 선택은 함께 튜닝해야 한다. Dill은 낮은 weight가 뽑힐 확률을 줄이려고 weight를 제곱하거나 최하위를 걸러내는 방법을 언급하면서도, 이것이 "완벽히 맞추기 어렵고 유지하기는 더 어려운 줄타기"가 된다고 경고한다.

4. 절충안: 상위 N개, 최고점 대비 % 이내

Graham의 처방은 "두 세계의 장점"을 취하는 것이다. 점수 상위의 부분집합만 남기고 그 안에서 가중 랜덤을 한다. 부분집합을 정하는 방법은 두 가지다.

전략남기는 후보엔진 옵션약점
상위 N개점수 순 상위 N개 (Graham의 예: 상위 5개){strategy:"topN", n}점수 차이를 보지 않는다. 1등 0.9, 2등 0.1이어도 2등이 남는다. 후보가 N개 이하면 그냥 가중 랜덤이 된다.
최고점 대비 % 이내최고점의 일정 비율 이상 (Graham의 예: 10% 이내){strategy:"topPct", pct}
score ≥ max·(1−pct)		기준이 상대적이다. 모든 점수가 0.05 근처로 낮아도 "최고점 근처"면 통과한다. 절대 수준을 모른다.
    if (st === "topN") pool = [...pool].sort((a, b) => b.score - a.score).slice(0, opt.n || 3);
    if (st === "topPct" || (st === "dual" && opt.pct)) pool = pool.filter(c => c.score >= maxS * (1 - (opt.pct || 0.1)));
    const sum = pool.reduce((a, c) => a + c.score, 0);
    const probs = pool.map(c => ({ cand: c, p: c.score / sum }));
    let x = r() * sum;
    for (const c of pool) { x -= c.score; if (x <= 0) return { chosen: c, pool: probs }; }
    return { chosen: pool[pool.length - 1], pool: probs };

필터는 후보를 줄이기만 하고, 마지막 뽑기는 3절의 빼기 알고리즘을 그대로 쓴다. 남은 후보끼리의 확률은 다시 정규화된다. 이제 다섯 전략을 같은 점수표에 걸어 보자.

선택 전략 실험실: 1000번 뽑아 보기
점수 슬라이더와 전략을 바꾸면 이론 막대(UAI.select가 돌려준 확률)가 즉시 바뀐다. "1000번 뽑기"는 시드 고정 UAI.rng로 실제 선택을 1000번 반복하며 관측 막대를 채운다. 빨간 테두리는 "바보 기준" 아래의 행동이다. 그 행동이 얼마나 자주 나오는지 보자. 가중 지수 k는 Dill이 언급한 "weight 제곱" 보완책을 흉내 낸 이 장의 교육용 변형이다(엔진 밖에서 scorek를 넘긴다).

5. 범주가 필요한 순간: 버킷팅

상위 N개나 % 필터는 대부분의 경우 문제를 해결한다. 하지만 Graham은 어떤 행동 집합은 상황상 완전히 부적절해서 점수를 매길 필요조차 없을 때가 있다고 지적한다. 그가 든 두 예는 이렇다.

  • FPS 경비병: 평소에는 커피 가지러 가기, 동료와 잡담하기, 옷의 보풀 확인하기 같은 행동을 고른다. 플레이어가 총을 쏘면 이런 행동은 고려 대상조차 되면 안 되고, 전투 행동만 점수를 매겨야 한다.
  • The Sims의 굶어 죽기 직전인 심: Fun 욕구를 채우는 행동을 고려할 이유가 없다.

Graham이 소개하는 해법이 버킷팅(bucketing)이다. 그는 이것이 Dill이 말한 dual utility AI와 같은 개념이라고 밝힌다. 행동을 버킷으로 나누고 버킷마다 우선순위를 준다. 높은 버킷에 유효한(점수 > 0) 행동이 하나라도 있으면 항상 그 안에서만 고른다. 경비병이라면 전투 버킷이 잡담 버킷보다 위에 있고, 유효한 전투 행동이 없을 때만 한가한 행동을 고른다.

The Sims에서는 버킷의 우선순위 자체가 상황에 따라 바뀐다. 욕구(motive)를 효용 값으로 버킷에 나누고, 가장 높은 버킷의 욕구를 채우는 행동만 점수를 매긴다. 버킷 점수는 디자이너가 만든 반응 커브로 정해진다. Graham의 그림 9.7을 그대로 옮기면 다음과 같다.

버킷이 없으면 TV 보기(30)가 식탁에서 식사(20)를 이긴다. 최고점 전략에서는 굶어 죽기 직전인 심이 100% TV 앞에 앉는다. 가중 랜덤에서도 Fun 행동 세 개의 합(73)이 Hunger 행동의 합(25)보다 커서 약 74.5% 확률로 놀러 간다. 행동 단위 점수만 보면 TV가 더 매력적이라는 것이 문제의 핵심이다. 행동 점수는 "그 행동이 얼마나 재미있나 / 배부르게 하나"를 재고, 욕구 사이의 긴급도 순서는 담지 못한다.

6. Dual Utility: rank와 weight

Kevin Dill(Game AI Pro 2, 3장)은 버킷팅을 일반화한 dual-utility reasoning을 제안한다. 핵심은 옵션마다 효용 값을 두 개 주는 것이다.

  • rank: 절대 효용. 옵션을 범주로 나누고, 가장 좋은 범주에서만 고른다.
  • weight: 범주 안에서의 상대 효용. 최고 rank 범주 안에서 weight-based random으로 고른다.

Dill은 이 조합으로 "절대 효용의 예측 가능성과 상대 효용의 가끔 나오는 엉터리 선택을 둘 다 피하면서, 디자이너에게 더 많은 유연성과 표현력을 준다"고 정리한다. 선택 알고리즘은 네 단계다.

  1. weight ≤ 0인 옵션 제거. 어차피 가중 랜덤에서 뽑힐 수 없는 옵션이고, 지금 빼면 이후가 단순해진다. 더 중요한 것은 디자이너가 "지금 상황에서 무효"를 표시하는 편리한 수단이 된다는 점이다. Dill의 표현대로 옵션을 선택되지 않게 하려면 weight를 0으로 두면 되고, 그러면 rank와 무관하게 탈락한다.
  2. 남은 옵션 중 최고 rank를 찾고, 그보다 낮은 rank를 제거. 가장 중요한 범주를 찾는 단계다.
  3. (선택) 남은 옵션 중 최고 weight를 찾고, 그 일정 비율 미만의 옵션을 제거. 비율은 결정마다 설정할 수 있어야 한다. "그다지 적절하지 않은" 옵션을 난수가 굳이 고르지 못하게 막는다.
  4. 남은 옵션에서 weight-based random으로 선택.

단계 순서에도 이유가 있다. ①이 ②보다 먼저인 덕분에 rank가 아무리 높아도 weight가 0이면 범주를 차지하지 못한다. 그래서 "죽음" 같은 옵션을 rank 1,000,000으로 늘 목록에 넣어 두고, 살아 있는 동안은 weight 0으로 잠가 둘 수 있다. 순서가 반대라면 최고 rank 범주가 전부 weight 0인 빈 범주가 되어 아무것도 못 고르는 사고가 난다.

  UAI.select = function (cands, opt, rng) {
    opt = opt || {};
    const r = rng ? rng.next : Math.random;
    let pool = cands.filter(c => c.score > 0);
    if (!pool.length) return { chosen: null, pool: [] };
    const st = opt.strategy || "best";
    if (st === "dual") {
      const top = Math.max(...pool.map(c => c.rank || 0));
      pool = pool.filter(c => (c.rank || 0) === top);
    }

엔진에서 Dill의 weight는 후보의 score(매 결정마다 consideration으로 계산한 값)이고, rank는 rank다. 행동 정의의 action.weight는 점수에 곱하는 정적 배율일 뿐 Dill의 weight와는 다르다. ③의 비율은 opt.pct로 주며, 엔진은 "최고 weight × (1 − pct) 미만 제거"로 해석한다. Hamlet 기본 Reasoner는 strategy: "dual", pct: 0.15, 즉 최고 weight의 85% 미만을 제거한다.

7. 트레이드오프: 예측 가능성 vs 다양성

지금까지의 전략을 한 줄에 늘어놓으면 다음과 같다. 왼쪽으로 갈수록 디자이너가 결과를 예측하기 쉽고, 오른쪽으로 갈수록 행동이 다양하지만 엉뚱한 선택의 위험이 커진다. Dual utility는 이 축 위의 한 점이 아니라 축을 두 층으로 나눈 것이다. 범주 사이에서는 맨 왼쪽(최고점), 범주 안에서는 원하는 위치를 고른다.

Lewis와 Dill은 왜 다른 결론을 내렸나

Mike Lewis(GAP3 13장)는 최고점 선택을 강력히 추천한다. Kevin Dill(GAP2 3장)은 dual utility를 제안한다. 둘 중 하나가 틀린 것이 아니라 무엇을 보여 주는 게임이냐가 다르다.

  • Guild Wars 2: Heart of Thorns의 전투 AI는 플레이어가 읽고 대응해야 하는 상대다. Lewis는 행동의 개성을 선택 단계의 랜덤이 아니라 consideration과 반응 커브(체력이 많으면 위험 지역 회피 점수를 낮춰 "맞아 가며 공격하는" 성격을 만드는 식)로 표현한다. 다양성은 입력이 매 순간 다르다는 데서 자연스럽게 나온다.
  • Zoo Tycoon 2의 동물과 관람객, The Sims의 심은 구경하는 대상이다. 같은 상황의 여러 캐릭터가 똑같이 움직이면 금방 티가 난다. 그래서 범주 안의 랜덤이 가치가 있고, 범주(rank)가 그 랜덤이 넘지 말아야 할 선을 긋는다.

또 하나 기억할 것: Lewis는 최고점 선택에서도 비슷한 점수의 두 결정이 번갈아 이기는 진동(ping-pong)이 생길 수 있다고 경고한다. 랜덤을 빼는 것이 안정성을 보장하지는 않는다. 이것이 06장의 주제다.

8. 시드 고정 RNG와 재현성

랜덤이 들어간 전략을 쓰는 순간 새 문제가 생긴다. 테스터가 "은솔이 늑대가 오는데도 수다를 떨었다"고 보고한다. 같은 상황을 다시 만들 수 없다면 이 버그는 고칠 수 없다. JavaScript의 Math.random()은 시드를 지정할 수 없어서 실행할 때마다 다른 수열을 낸다. 그래서 엔진은 시드를 받는 작은 RNG(mulberry32)를 직접 갖고 있다.

  // 시드 고정 RNG(mulberry32): 같은 시드면 같은 시뮬레이션 → 재현 가능한 디버깅 (09장)
  UAI.rng = function (seed) {
    let a = seed >>> 0 || 1;
    const next = () => {
      a = (a + 0x6d2b79f5) >>> 0;
      let t = a;
      t = Math.imul(t ^ (t >>> 15), t | 1);
      t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
      return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
    };

같은 시드로 만든 RNG는 같은 순서로 같은 수를 낸다. UAI.World는 생성 시 UAI.rng(opt.seed || 7) 하나를 만들고 모든 주민의 결정이 그것을 공유한다. 시드와 플레이어 입력 기록만 있으면 마을 전체를 한 틱 단위까지 다시 재생할 수 있다.

그런데 하나의 난수 흐름을 공유한다는 점이 함정이다. 3절에서 본 대로 가중 랜덤은 결정마다 난수를 하나 쓰고, 최고점 전략은 하나도 쓰지 않는다. 아리 한 명의 전략만 바꿔도 그 뒤 보람이 받는 난수가 전부 밀린다. 아리를 고쳤는데 보람의 행동이 바뀌는 것이다.

같은 시드 = 같은 하루 (그리고 공유 난수의 함정)
아리와 보람이 번갈아 12번씩 결정한다. 둘 다 하나의 RNG를 공유한다(엔진의 World와 같은 구조). 보람의 선택 줄만 보여 주며, 비교 기준 줄과 다른 칸은 주황으로 표시한다.
09장으로 이어지는 설계 원칙 ① 시뮬레이션 안의 모든 랜덤은 Math.random이 아니라 World의 RNG를 쓴다(엔진의 UAI.select는 rng를 받지 않으면 Math.random으로 대체하니, 시뮬레이션 코드에서는 반드시 넘긴다). ② 디버그 로그에 시드를 함께 남긴다. ③ 주민별로 독립적인 재현이 필요하면 주민마다 RNG를 따로 만든다(예: 월드 시드 + 주민 번호). 그러면 한 주민의 변경이 다른 주민의 난수를 밀어내지 않는다. 09장에서 World.tick 루프와 함께 다시 다룬다.

핵심 요약

  • 선택 전략은 점수 계산과 분리된 부품이다. 같은 점수표라도 전략에 따라 NPC의 성격이 달라진다.
  • 최고점(absolute)은 적절하고 예측 가능하지만 로봇 같다. 동점이면 엔진은 목록의 첫 행동을 고른다.
  • 가중 랜덤(relative)은 PO = UO/ΣUi. "총합 → 난수 → 빼기"로 O(n)에 구현한다. 낮은 점수 행동의 확률이 남아 결정 횟수가 쌓이면 바보 같은 선택이 반드시 보인다.
  • 상위 N과 최고점 대비 % 이내는 후보를 줄인 뒤 가중 랜덤을 한다. 전자는 점수 차이를, 후자는 절대 수준을 보지 않는다.
  • 범주 간 긴급도는 행동 점수 하나에 담을 수 없다. 버킷이 없으면 굶주린 심이 TV(30)를 식사(20)보다 먼저 고른다.
  • Dual utility = rank(범주, 절대) + weight(범주 안, 상대). 4단계: weight ≤ 0 제거 → 최고 rank → (선택) % 필터 → 가중 랜덤. Zoo Tycoon 2는 욕구 0, 나무 위 ~5, 쇼 98–102, 죽음 1,000,000.
  • 랜덤 전략에는 시드 고정 RNG가 필수다. 공유 난수 흐름에서는 한 에이전트의 변경이 다른 에이전트의 난수를 밀어낸다.

확인 문제

점수가 0.6, 0.3, 0.1인 세 행동을 가중 랜덤으로 고른다. 0.1짜리 행동이 뽑힐 확률은?
P = 0.1 / (0.6 + 0.3 + 0.1) = 0.1 / 1.0 = 10%. 하루 100번 결정한다면 열 번쯤은 이 행동을 한다. 제곱(k=2)하면 0.01/(0.36+0.09+0.01) ≈ 2.2%로 줄지만 0은 아니다.
Dual utility에서 A(rank 5, weight 0.2), B(rank 5, weight 0.8), C(rank 10, weight 0), D(rank 0, weight 0.9)가 있다. % 필터는 쓰지 않는다. 결과는?
① weight ≤ 0인 C가 먼저 빠진다(rank와 무관). ② 남은 A·B·D 중 최고 rank는 5이므로 D가 빠진다. ④ A·B 사이 가중 랜덤: 0.2/1.0 = 20%, 0.8/1.0 = 80%. ③ 필터를 "최고 weight의 50% 미만 제거"로 켰다면 A(0.2 < 0.4)도 빠져 B가 100%가 된다.
엔진의 {strategy: "topPct", pct: 0.1}로 점수 0.50, 0.46, 0.44, 0.20을 고를 때 0.46이 뽑힐 확률은?
기준은 max·(1 − pct) = 0.50 × 0.9 = 0.45. 0.44는 아깝게 탈락한다. 남은 0.50과 0.46의 합은 0.96이므로 0.46/0.96 ≈ 47.9%. % 필터는 경계 근처에서 이렇게 날카롭게 작동하므로 점수가 경계에서 흔들리면 후보 집합이 매번 바뀔 수 있다.
Dual utility가 "weight ≤ 0 제거"를 "최고 rank 찾기"보다 먼저 하는 가장 중요한 이유는?
Dill은 이 단계가 "지금 상황에서 무효/부적절"을 표시하는 편리한 방법이라고 설명한다. 죽음(rank 1,000,000)을 늘 목록에 두고 평소에는 weight 0으로 잠가 두는 설계가 이 순서 덕분에 가능하다. 순서를 바꾸면 죽음 범주만 남고 그 안에 뽑을 것이 없어진다.
World의 RNG 하나를 공유하는 시뮬레이션에서 아리의 전략을 weighted에서 best로 바꿨더니, 아무것도 안 건드린 보람의 행동이 달라졌다. 왜인가?
UAI.select는 best일 때 r()을 부르지 않고 반환한다. weighted일 때는 결정마다 하나씩 쓴다. 그래서 아리가 쓰지 않은 난수를 보람이 대신 받는다. 시뮬레이션 전체는 여전히 결정적이고 재현 가능하지만, "한 곳만 고쳤는데 다른 곳이 바뀌는" 현상이 생긴다. 주민별 RNG가 해법이다(8절 위젯).
가중 랜덤에서 모든 행동 점수에 0.5를 더하면 선택 분포는 어떻게 되나?
곱하기는 비율을 보존하지만 더하기는 비율을 1에 가깝게 만든다. 0.8과 0.1(8:1)이 1.3과 0.6(약 2.2:1)이 된다. 점수 0이던 행동도 0.5가 되어 후보가 된다. 결합 방식이나 make-up 보정(04장)이 점수 바닥을 끌어올리면 선택 분포도 함께 평평해진다는 뜻이다.
다음 장으로 이 장의 전략은 모두 "한 번의 결정"만 본다. 하지만 엔진은 매 틱 다시 고른다. Graham이 든 예처럼 "공격"과 "도망"이 둘 다 0.5 근처라면 최고점 전략에서도 프레임마다 승자가 바뀌어 총 두어 발 쏘고 도망치다 다시 쏘는 발작적인 병사가 나온다. 가중 랜덤이라면 더 심하다. 06장에서는 현재 행동 가중(inertia), 쿨다운, 행동이 끝날 때까지 결정 보류, 그리고 rank를 이용한 인터럽트로 이 진동을 잡는다.
