API 통합 테스트와 배포 리허설

선수 장 · 테스트의 증거 범위

가짜 저장소의 테스트가 통과해도 배포된 Kestrel에서 인증·DB·worker가 이어지는지는 알 수 없습니다. 테스트가 지나간 경로를 실제 요청과 배포 산출물로 연결합니다.

테스트 호스트와 실제 전송 경로

WebApplicationFactory<Program>로 앱을 구성하고 CreateClient로 접수·조회·권한·취소를 검사합니다. 외부 의존성 중 무엇을 대체했는지 적고 관계형 제약을 검증하려면 실제 테스트 DB와 마이그레이션을 포함합니다. 응답만 아니라 저장 결과와 Outbox/작업 상태도 같은 ID로 확인합니다.

기본 TestServer는 실제 Kestrel 소켓·TLS·프록시 경로를 지나지 않습니다. 게시한 앱을 로컬 Kestrel로 실행한 smoke test와 브라우저 쿠키/CORS 검사는 별도입니다. 인증을 fake로 교체했다면 실제 자격 증명 검증이 빠졌다는 범위를 유지합니다.

신구 호환성과 종료를 리허설하기

새 컬럼 추가 → 신구 버전이 함께 읽고 쓰기 → 새 코드로 전환 → 오래된 필드 제거 순서를 표로 만듭니다. 앱만 이전 버전으로 되돌려도 새 데이터 형식이 읽히는지 검사해야 합니다. 데이터 변환을 되돌리지 못하는데 배포 롤백을 완료했다고 쓰지 않습니다.

진행 중 요청과 worker 작업을 만든 뒤 신규 접수 중단·readiness 전환·drain·종료를 순서대로 관측합니다. 호스트 timeout과 플랫폼 종료 유예 안에 끝내지 못한 일은 영속 상태로 복구해야 합니다. deploy 로그, 정상 요청 성공, 중단 후 복구를 서로 다른 증거로 제출합니다.

실습과 예상 관찰

동일 입력과 작업 ID로 단위 테스트, WebApplicationFactory+테스트 DB, 실제 Kestrel 요청의 검증 표를 만드세요. 자기 로컬 앱 두 버전을 같은 호환 스키마로 실행하고 진행 중 작업이 있는 상태에서 한 버전을 종료합니다. 누락·재전달·권한 결과와 rollback 뒤 조회를 확인하세요.

테스트 호스트와 fake 의존성만 통과

업무 규칙과 가짜 계약에 대한 증거입니다. 실제 SQL·소켓·쿠키·프록시 성공까지 확대할 수 없습니다.

실제 저장과 종료 후 복구까지 관측

해당 버전·환경·입력의 연결 경로를 입증합니다. 모든 부하와 장애에서 안전하다는 일반 보증은 아닙니다.

실습의 경계와 다음 장

운영 배포를 이 실험의 일부로 자동 수행하지 않습니다. 최종 설계 문서는 요구·선택·관측·미검증을 구분하고 측정된 병목을 기준으로 다음 최적화를 정합니다.
