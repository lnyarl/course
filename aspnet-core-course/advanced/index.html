코스 목록

ASP.NET Core 구조와 동작 심화

기존 요청·DI·SQL·권한·운영 설명을 실제 수명과 실패 경계로 확장합니다. 코드 흐름과 로컬 실험 절차를 제공하며 가상 예상 결과를 실행 완료 기록으로 취급하지 않습니다.

기존 코스 목차

  1. Kestrel·Pipelines와 스트리밍 업로드

    큰 파일을 요청당 byte 배열 하나로 읽으면 동시 업로드 수만큼 메모리가 늘어납니다. 서버의 바이트 처리 경계에서 버퍼를 누가 소유하고 언제 돌려주는지 따라갑니다.

  2. 라우팅·binding·validation·filter의 실행 경로

    같은 잘못된 입력도 라우트가 맞지 않은 경우와 DTO 검증이 실패한 경우의 응답이 다릅니다. 미들웨어 순서에서 endpoint 내부의 처리 단계로 내려갑니다.

  3. EF Core 저장·트랜잭션·경합 실험

    한 요청에서 저장이 성공해도 두 요청이 같은 버전을 갱신하면 다른 문제가 생깁니다. LINQ와 SQL의 연결을 실제 제약조건과 충돌 결과까지 확인합니다.

  4. 인증 scheme·리소스 policy·키 수명

    로그인한 사용자만 허용한 뒤에도 다른 사람의 작업을 읽을 수 있다면 리소스 정책이 빠진 것입니다. 테스트용 신원과 실제 자격 증명 검증을 분리해 범위를 확인합니다.

  5. HttpClient 연결 수명과 복원력

    비동기 외부 호출을 해도 연결이 고갈되거나 이름 변경이 늦게 반영될 수 있습니다. await 계약에서 연결 풀과 전체 호출 예산으로 범위를 넓힙니다.

  6. 영속 접수·Outbox·worker 복구

    202를 반환한 직후 프로세스가 끝나면 메모리 Channel의 접수는 사라질 수 있습니다. 요청이 끝난 시점과 복구할 근거가 생긴 시점을 일치시킵니다.

  7. Rate limiting·timeout·과부하 제어

    느려진 서버가 모든 요청을 받아들이면 처리한 결과도 클라이언트 timeout 뒤에 도착할 수 있습니다. 유한 큐의 원리를 HTTP 입장 정책으로 연결합니다.

  8. API 통합 테스트와 배포 리허설

    가짜 저장소의 테스트가 통과해도 배포된 Kestrel에서 인증·DB·worker가 이어지는지는 알 수 없습니다. 테스트가 지나간 경로를 실제 요청과 배포 산출물로 연결합니다.
