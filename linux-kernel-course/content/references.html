책에서 원리를, 문서에서 현재 구현을

자료의 나이와 역할을 구분합니다. 특정 버전의 구현을 읽고, 실행 환경에서 실제로 활성화된 기능을 확인합니다.

기준은 Linux 6.18 LTS입니다

2026-11-10에 확인한 kernel.org의 장기 지원 목록에 6.18이 포함되어 있습니다. 이 과정은 6.18 LTS 계열을 학습 대상으로 삼고, 소스 링크는 v6.18 태그로 고정합니다. 최신 mainline 전체를 설명한다는 뜻은 아닙니다. 안정화 패치와 배포판 백포트가 내부 동작을 바꿀 수 있으므로, 실습 보고서에는 uname -r, 아키텍처, libc 버전, 커널 설정을 기록합니다.

EEVDF는 일반 작업 스케줄링의 흐름으로 설명합니다. MGLRU, PREEMPT_RT, BPF, huge page는 기능 존재와 활성화를 구분합니다. 4 KiB 페이지와 비 RT 커널을 일반 도식의 기본 가정으로 쓰지만, 이를 모든 Linux의 고정 속성으로 외우면 안 됩니다. Apple Silicon 호스트에서 ARM64 VM을 쓰는 경우 x86-64 시스템 콜 레지스터 설명은 아키텍처 비교로 읽으세요.

아티클에서 가져온 학습 방식

Ben M. Andrew, What is malloc doing, anyway?는 작은 할당에서 출발해 사용자 공간의 메모리 관리와 커널 경계를 연결합니다. 이 교재의 malloc 특별 실험실은 별도로 설계한 청크 모델과 C 관측 실습으로 같은 질문을 탐구합니다. 원문의 벤치마크 수치와 구현 세부를 Linux 전체의 성질로 일반화하지 않습니다.

Nabil Omi, A primer on GPUs and kernel optimization의 kernel은 GPU 연산 프로그램입니다. 여기에서는 GPU·CUDA 내용을 다루지 않고, 흐름을 눈으로 추적하고 실제 측정으로 가설을 검증하는 학습 접근을 참고했습니다.

USE Method는 자원마다 사용률·포화·오류를 확인하는 출발점을 제공합니다. 사용률만으로 원인을 확정하지 않고, 대기와 실행의 증거를 함께 보는 종합 실습에 연결합니다.

시뮬레이션과 실제 측정의 경계

브라우저 실험은 설명용 결정 모델입니다. 실제 커널을 실행하거나 성능을 측정하지 않습니다. EEVDF 실험은 한 선택 시점, I/O 모델은 고정된 서비스 조건 등 각 실험에 한계를 명시했습니다. 실제 Linux 실습은 별도 VM에서 실행하도록 제공합니다. 이 교재 제작 과정의 브라우저 검증이 Linux 런타임 검증을 대신하지 않습니다.
