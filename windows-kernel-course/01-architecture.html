Part I · Chapter 01

윈도우 아키텍처 개관

Windows NT 커널을 이루는 큰 그림. 이후 모든 챕터는 이 지도 위의 한 구역을 확대하는 과정입니다.

입문⏱ 약 60분선수: C, 운영체제 기초

학습 목표

  • CPU 특권 수준(Ring)과 유저/커널 모드의 실제 차이를 하드웨어 관점에서 설명할 수 있다.
  • NT 아키텍처의 계층(서브시스템 DLL → ntdll → Executive → Kernel → HAL)과 각 구성요소의 책임을 구분할 수 있다.
  • 커널 함수 이름의 접두사만 보고 어느 구성요소 소속인지, 공개/내부 함수인지 판단할 수 있다.
  • CreateFileW 한 번의 호출이 커널을 거쳐 파일 시스템 드라이버까지 가는 경로를 그릴 수 있다.

왜 커널인가

애플리케이션이 하는 거의 모든 일 — 파일 열기, 메모리 할당, 스레드 생성, 네트워크 송신 — 은 결국 커널에 대한 요청입니다. 커널은 하드웨어를 독점적으로 다루고, 여러 프로세스가 서로를 침범하지 못하도록 격리하며, 한정된 CPU와 메모리를 배분하는 중재자입니다.

커널 전문가는 크게 세 갈래에서 활약합니다. 드라이버/시스템 개발(디바이스, 파일 시스템 필터, 가상화), 장애 분석(블루스크린, 행, 성능 저하의 근본 원인), 보안(EDR, 취약점 연구, 익스플로잇 완화). 세 분야 모두 같은 기반 지식 — 이 코스에서 다루는 내부 구조 — 위에 서 있습니다.

전문가 관점

Windows 커널은 소스가 공개되어 있지 않습니다. 그래서 전문가의 핵심 역량은 "공개 심볼 + 디버거 + 문서 + 리버싱"으로 사실을 검증하는 습관입니다. 이 코스의 모든 구조체·함수는 WinDbg에서 dt, x, u로 직접 확인할 수 있으니, 읽기만 하지 말고 반드시 대조해 보세요.

유저 모드와 커널 모드

"커널 모드"는 소프트웨어 개념이 아니라 CPU 상태입니다. x86-64 CPU는 현재 코드 세그먼트의 하위 2비트, 즉 CPL(Current Privilege Level)로 특권 수준을 판단합니다. Windows는 4개 링 중 Ring 0(커널)과 Ring 3(유저) 두 개만 사용합니다.

유저 모드 (CPL=3)

특권 명령 실행 불가. 페이지 테이블의 U/S=1인 페이지만 접근. 크래시해도 해당 프로세스만 종료.

커널 모드 (CPL=0)

모든 명령·모든 메모리 접근 가능. 커널 코드의 버그는 시스템 전체를 멈춤 → 버그체크(BSOD).

중요: 커널 모드는 "커널 프로세스"가 아닙니다. 대부분의 커널 코드는 요청한 유저 스레드의 문맥에서 실행됩니다. 스레드가 syscall을 실행하면 같은 스레드가 CPL 0으로 전환되어 커널 코드를 수행하고 다시 돌아옵니다.

NT 아키텍처 전체 지도

아래 도식은 Windows의 주요 구성요소를 계층으로 나타낸 것입니다. 각 상자를 클릭하면 역할, 실제 파일, 대표 함수가 표시됩니다. 유저 모드의 모든 경로는 결국 ntdll.dll로 모이고, 거기서 시스템 콜 경계를 넘어 커널로 들어갑니다.

ntoskrnl.exe 하나에 Executive와 Kernel이 함께 있다

도식에서 Executive와 Kernel은 별개의 상자지만 같은 바이너리(ntoskrnl.exe) 안에 있습니다. 계층은 논리적 구분이며, NT는 순수 마이크로커널이 아닌 하이브리드(모놀리식에 가까운) 설계입니다. 모든 Executive 구성요소가 같은 주소 공간에서 함수 호출로 소통하므로 빠르지만, 한 구성요소의 버그가 전체를 무너뜨릴 수 있습니다.

NT의 설계 원칙

객체 기반

모든 리소스를 객체 + 핸들로 다룬다. 이름 공간·보안·참조 관리가 일관된다.

이식성

HAL과 아키텍처 의존 코드를 분리. x86, x64, ARM64를 같은 코드베이스로 지원.

대칭형 다중처리(SMP)

커널 코드가 모든 CPU에서 동시에 실행된다. 그래서 동기화(07장)가 핵심이다.

선점형 커널

커널 모드 스레드도 더 높은 우선순위 스레드에 선점될 수 있다(IRQL이 DISPATCH 미만일 때).

비동기 I/O 중심

모든 I/O는 본질적으로 비동기. 동기 I/O는 비동기 I/O + 대기로 구현된다.

보안 내재화

모든 객체 열기는 SRM의 접근 검사를 거친다(C2 인증 설계 목표).

특수 "프로세스"들

작업 관리자의 System(PID 4)은 커널 시스템 스레드를 담는 컨테이너 프로세스이고, Idle(PID 0)은 CPU당 하나씩 유휴 스레드를 가진 가상 프로세스입니다. Registry는 레지스트리 하이브를, Memory Compression은 압축된 페이지를 보관하는 최소(minimal) 프로세스입니다. VBS가 켜져 있으면 Secure System도 보입니다.

함수 접두사 읽는 법

커널 함수 이름은 <접두사><동작><대상> 규칙을 따릅니다. 예: Ke+Wait+ForSingleObject. 접두사 뒤에 i가 붙거나(Ke→Ki, Mm→Mi) p가 붙으면(Io→Iop, Ps→Psp) 내부(비공개) 함수입니다. 덤프 분석에서 콜스택을 읽을 때 이 규칙만 알아도 "어느 구성요소에서 문제가 났는지" 바로 감이 옵니다.

커널 코드가 ZwCreateFile을 호출하면 시스템 콜 진입 경로(KiServiceInternal)를 거치면서 스레드의 PreviousMode가 KernelMode로 설정됩니다. 그래서 인자 검증(프로브)과 접근 검사가 완화됩니다. 커널에서 NtCreateFile을 직접 호출하면 PreviousMode가 그대로(유저 요청 처리 중이라면 UserMode) 남아 커널 버퍼가 거부되거나, 반대로 보안 검사가 잘못 생략될 수 있습니다. 드라이버는 원칙적으로 Zw 버전을 씁니다. → 02장에서 자세히

확인 문제

유저 스레드가 ReadFile을 호출해 커널 코드가 실행되는 동안, 그 커널 코드는 어느 문맥에서 실행되나요?

  1. System 프로세스(PID 4)의 커널 스레드
  2. 호출한 바로 그 유저 스레드 (CPL만 0으로 바뀜)
  3. 커널 전용 프로세스의 워커 스레드
  4. 하이퍼바이저
시스템 콜은 스레드 전환이 아니라 같은 스레드의 모드 전환입니다. 스레드는 유저 스택과 별도로 커널 스택을 가지고 있으며, syscall 시 커널 스택으로 바꿔 실행합니다. 그래서 커널 코드에서 "현재 프로세스"는 호출한 프로세스입니다.

콜스택에 nt!MiDeleteVirtualAddresses가 보입니다. 올바른 해석은?

  1. Mi = Microsoft 내부 유틸리티
  2. 공개 문서화된 메모리 관리자 API
  3. 메모리 관리자(Mm)의 내부(비공개) 함수
  4. Minifilter 관련 함수
접두사의 두 번째 글자가 i로 바뀐 형태(Mm→Mi, Ke→Ki)는 내부 함수입니다. 미니필터는 Flt 접두사를 씁니다.

Executive와 Kernel(Ke)에 대한 설명으로 옳은 것은?

  1. Executive는 ntoskrnl.exe, Kernel은 hal.dll에 있다
  2. 둘 다 ntoskrnl.exe에 있으며, Kernel은 스케줄링·동기화·트랩 같은 저수준 메커니즘을 제공한다
  3. Executive는 유저 모드에서 실행된다
  4. Kernel 계층은 마이크로커널로서 별도 주소 공간에서 실행된다
둘은 같은 바이너리의 논리적 계층입니다. Executive(Io, Mm, Ps, Ob, Se…)가 정책과 서비스를, Kernel(Ke)이 메커니즘을 제공합니다.

GUI 함수(예: NtUserGetMessage)의 시스템 콜이 처리되는 곳은?

  1. ntoskrnl.exe의 SSDT(KiServiceTable)
  2. win32k 계열 드라이버 — Shadow SSDT를 통해
  3. csrss.exe 프로세스
  4. user32.dll 내부에서 처리되어 커널로 가지 않음
win32u.dll의 스텁은 0x1000 이상의 시스템 콜 번호를 사용하며, 커널은 번호의 비트 12로 두 번째 서비스 테이블(win32k)을 선택합니다. → 02장

드라이버가 커널 내부에서 파일을 열 때 NtCreateFile 대신 ZwCreateFile을 써야 하는 이유는?

  1. Zw 버전이 더 빠르다
  2. Nt 버전은 유저 모드에만 존재한다
  3. Zw는 PreviousMode를 KernelMode로 설정해, 커널 버퍼를 정상적인 커널 요청으로 처리하게 한다
  4. Zw는 IRQL을 자동으로 낮춰준다
PreviousMode는 "이 요청이 어디서 왔는가"를 나타내며 인자 프로브·접근 검사 여부를 결정합니다. 잘못 쓰면 정상 동작 실패나 보안 취약점(권한 검사 우회)으로 이어집니다.

핵심 요약

  • 유저/커널 모드는 CPU의 CPL 상태이며, Windows는 Ring 3와 Ring 0만 쓴다. VBS가 켜지면 하이퍼바이저가 그 아래에 있다.
  • Win32 API → 서브시스템 DLL → ntdll → syscall → KiSystemCall64 → Executive 서비스 순으로 내려간다.
  • ntoskrnl.exe = Executive(Io/Mm/Ps/Ob/Se/Cm/Cc/Po…) + Kernel(Ke). HAL이 하드웨어 차이를 숨긴다.
  • 드라이버는 커널과 같은 권한·주소 공간을 공유한다 — 드라이버 버그는 곧 시스템 크래시다.
  • 함수 접두사(+i/+p 규칙)만으로 콜스택의 구성요소를 판별할 수 있다.
