HTTP/2와 HTTP/3의 흐름 제어

선수 장 · 8장 HTTP 버전과 스트리밍

다중화 연결에서 일부 스트림만 멈추거나 전체 DATA가 멈추는 시점을 별도 전송 예산으로 설명합니다.

스트림과 연결 예산

HTTP/2에서는 DATA를 보내려면 스트림과 연결의 흐름 제어 예산이 둘 다 있어야 합니다. 한 스트림의 남은 예산이 0이어도 다른 스트림과 연결에 여유가 있으면 다른 DATA는 전송할 수 있습니다.

HTTP/3는 QUIC 스트림을 이용해 TCP의 연결 단위 순서 대기를 줄입니다. 연결 전체 흐름 제어와 혼잡 제어는 공유되므로 스트림이 서로 완전히 격리되는 것은 아닙니다.

압축 상태와 연결 이동

HTTP/2는 HPACK을 사용합니다. QPACK은 QUIC 스트림 순서에 맞춰 별도 인코더 스트림에 동적 테이블 상태를 보내고, 아직 받지 못한 상태를 참조한 스트림은 설정 범위에서 복호를 기다릴 수 있습니다.

GOAWAY 뒤에는 버전의 식별자 의미를 확인해 새 요청을 다른 연결로 보냅니다. 이미 시작한 요청의 완료와 재시도를 나눠 기록하고 상태 변경 요청은 멱등성 조건을 점검합니다.

실습과 예상 관찰

연결과 스트림 A/B에 남은 바이트 값을 적습니다. A는 4바이트, B는 6바이트를 보내려고 합니다.

A 스트림 예산만 0, 연결과 B의 여유 충분

B는 자신의 DATA를 보낼 수 있고 A는 스트림 예산이 다시 열릴 때까지 기다립니다.
