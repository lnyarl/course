인증서 회전과 mTLS 신원

선수 장 · 7장 TLS와 인증서

종료 지점 A와 B 중 한 곳만 새 인증서를 사용합니다. 성공한 연결 한 건으로는 회전 완료를 판정할 수 없습니다.

종료 지점과 이름 검증

SNI는 서버가 구성을 고르는 입력이고, 클라이언트 이름 검증은 서버 인증서의 신원이 요청과 맞는지 보는 검사입니다. 체인이 유효해도 SAN에 요청 이름이 빠지면 실패할 수 있습니다.

회전 성공을 볼 때는 기존 연결 재사용과 새 핸드셰이크를 분리합니다. 종료 지점별 실제 연결에서 인증서 일련번호와 만료, 체인 결과를 기록합니다.

클라이언트 신원과 인가

mTLS에서 서버는 클라이언트 인증서의 신뢰 사슬과 소유 증명을 검증합니다. 검증된 워크로드가 어느 서비스 동작을 호출할 수 있는지는 애플리케이션 정책이 따로 결정합니다.

앞단 종료와 뒤쪽 재암호화가 있으면 홉마다 상대 신원이 다릅니다. 어떤 컴포넌트가 사용자 신원과 워크로드 신원을 제공하고 API가 어디에서 검증하는지 표시합니다.

실습과 예상 관찰

A/B에 SAN, 유효 기간, 일련번호를 적고 새 연결마다 적용된 검사를 예측하세요.

체인 유효, SAN에 요청 이름 없음

서비스 이름 검증에서 실패하며 HTTP 처리 결과를 논할 단계에 도달하지 않습니다.

A만 새 인증서, B의 이전 인증서도 유효

응답은 둘 다 성공할 수 있습니다. 일련번호를 비교해야 B의 회전 미완료가 드러납니다.

유효한 클라이언트 인증서, 경로 권한 없음

TLS 성공 후 앱 인가 단계가 요청을 거절할 수 있습니다.

실습의 경계와 다음 장

카드는 구성 차이를 보여 줍니다. 실제 운영 증거에는 종료 지점과 새 연결을 명시하고, 9장의 홉별 신뢰 모델로 이어갑니다.
