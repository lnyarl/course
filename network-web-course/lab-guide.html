실제 요청으로
확인하는 실습 환경

교재는 파일로 열어도 동작합니다. 실제 HTTP 요청 실습에는 Python 표준 라이브러리 서버를 사용합니다.

1. 교재 열기

network-web-course/index.html을 브라우저로 열거나, 교재 폴더에서 아래 정적 서버를 실행하세요. 두 서버는 목적과 포트가 다릅니다.

cd network-web-course
python3 -m http.server 8088 --bind 127.0.0.1
# 브라우저: http://127.0.0.1:8088/

정적 교재는 서버 없이도 본문·그림·시뮬레이터·문제가 작동합니다. 외부 원전 링크와 example.com 실습은 인터넷 연결이 필요합니다.

2. 실제 HTTP 실습 서버

별도 터미널에서 실행하세요. 의존성 설치는 필요하지 않습니다. Python 3가 필요합니다. 기존 8765 포트를 쓰고 있다면 --port 8877처럼 바꿀 수 있으며 명령의 포트도 함께 바꿔야 합니다. 종료는 Ctrl+C입니다.

cd network-web-course
python3 tools/lab_server.py
# 브라우저: http://127.0.0.1:8765/
경로직접 관찰할 결과
/inspect메서드, 경로, 헤더, 본문을 JSON으로 반환
/cacheETag: "v1", max-age=60. 조건 일치 시 304
/redirect302 + Location: /inspect
/delay?ms=800응답 헤더 전 최대 5000ms 대기
/status?code=503지정한 교육용 HTTP 오류 응답
/cors?mode=allow 또는 deny허용 모드에서 로컬 Origin을 명시적으로 허용
이 서버는 HTTP/1.1 교육 도구입니다. 실제 TLS·HTTP/2·HTTP/3·DNS·프록시·방화벽을 구현하지 않습니다. /status의 502·504는 상태 코드만 만든 합성 응답이며 실제 업스트림 장애를 증명하지 않습니다.

3. 메서드와 리다이렉트

curl -i http://127.0.0.1:8765/inspect
curl -i -H 'Content-Type: application/json' \
  --data '{"lesson":"http"}' http://127.0.0.1:8765/inspect
curl -i http://127.0.0.1:8765/redirect
curl -i -L http://127.0.0.1:8765/redirect

--data는 이 예제에서 POST를 선택합니다. /inspect 결과의 method와 body를 비교하세요. -L이 없으면 302에서 멈추고, 있으면 새 대상의 응답까지 따라갑니다. -i는 응답 헤더를 표시합니다.

4. 실제 304 확인

curl -i http://127.0.0.1:8765/cache
curl -i -H 'If-None-Match: "v1"' http://127.0.0.1:8765/cache

첫 요청은 200과 JSON 본문, 두 번째는 304와 본문 없음이 예상됩니다. curl이 브라우저처럼 자동 캐시한 결과가 아닙니다. 여러분이 저장 응답의 검증자를 직접 넣어 조건부 요청을 만든 것입니다. 브라우저 자동 캐시는 Network 탭과 함께 관찰하세요.

5. 타임아웃과 서버 작업 분리

curl -sS -o /dev/null -w 'first=%{time_starttransfer}s total=%{time_total}s\n' \
  'http://127.0.0.1:8765/delay?ms=800'
curl --max-time 0.2 'http://127.0.0.1:8765/delay?ms=800'

첫 명령은 약 0.8초 이상 첫 바이트를 기다립니다. 정확한 시간은 환경에 따라 달라집니다. 두 번째는 약 0.2초에 클라이언트 타임아웃 오류가 예상됩니다. 서버는 이미 시작한 대기를 계속할 수 있습니다. 클라이언트 포기와 서버 취소는 같은 사건이 아닙니다.

6. 실제 브라우저 CORS 비교

  1. http://127.0.0.1:8765/를 브라우저에서 엽니다. 개발자 도구 Network·Console을 켭니다.
  2. CORS 허용 없음 버튼을 누릅니다. 기본 GET은 서버까지 도달할 수 있지만 JS 응답 읽기는 차단됩니다.
  3. CORS 허용 버튼을 누릅니다. 다른 origin의 응답을 JS에서 읽을 수 있습니다.
  4. X-Demo를 켜고 반복합니다. 허용 없음이면 OPTIONS 후 실제 GET이 전송되지 않는지 확인하세요.

127.0.0.1과 localhost는 같은 장치로 연결되어도 origin의 호스트 이름이 다릅니다. 이 실습은 실제 fetch 동작을 관찰하며 교재의 CORS 시뮬레이터와 구분됩니다. HTTP를 사용하므로 HTTPS 쿠키 보안이나 TLS 검증을 실습한 것은 아닙니다.

도구 차이와 결과 해석

macOS/Linux의 curl·dig·openssl 예제를 사용합니다. Windows는 WSL 등 해당 도구가 있는 환경에서 실행하세요. curl -V로 프로토콜·TLS 지원을 먼저 확인하세요. openssl 옵션은 구현과 버전에 따라 다릅니다. dig +trace는 시스템이나 브라우저가 실제 사용한 리졸버·DoH 경로를 그대로 재현하지 않습니다.

인증서·DNS·상태 코드·타이밍은 외부 환경에서 달라집니다. 교재의 예시 출력은 관찰할 필드와 의미를 안내합니다. 명령이 실패하면 오류 문구와 어느 단계까지 완료됐는지 먼저 기록하세요.
