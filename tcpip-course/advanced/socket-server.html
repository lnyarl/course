논블로킹 소켓과 메시지 수명

선수 장 · 6장 응용 계층과 소켓

6장의 소켓 서버에 클라이언트가 본문을 여러 번 나눠 보내면, 서버는 읽기 통지와 메시지 완료를 구분해야 합니다.

연결별 프레이밍 상태

연결마다 헤더 처리 여부, 기대 길이, 처리하지 않은 바이트를 유지합니다. 읽기 준비 신호는 바이트를 읽어 볼 수 있다는 뜻입니다. 요청 한 건의 처리 권한은 전체 프레임이 모인 뒤에 생깁니다.

EAGAIN은 현재 읽을 데이터가 없어 다시 대기하라는 신호입니다. EOF는 상대가 자신의 송신을 끝냈다는 뜻입니다. 마지막 메시지의 본문이 부족하면 잘린 프레임을 완료로 넘기지 않습니다.

쓰기 오프셋과 종료

쓰기 호출이 요청한 크기보다 적게 전송하면 오프셋을 전진시킨 뒤 나머지를 재개합니다. 미전송 데이터가 있을 때만 쓰기 이벤트를 기다리면 항상 쓰기 가능한 연결의 바쁜 반복을 줄입니다.

엣지 트리거에서는 EAGAIN까지 읽는 패턴을 사용합니다. 공정성 때문에 중간에 처리 예산을 끊을 때는 남은 읽기를 명시적으로 재예약할 방법이 필요합니다.

실습과 예상 관찰

본문 5바이트를 2와 3으로, 응답 6바이트를 2와 4로 나눕니다. 각 호출 뒤의 남은 바이트와 메시지를 넘긴 횟수를 적으세요.

부분 읽기 두 번 완료

첫 호출 후 3바이트 보류, 두 번째 호출 후 요청 1건 전달. 응답은 앞 2바이트를 제외한 나머지 4바이트만 이어서 씁니다.

부분 본문 뒤 EOF

정상 요청은 0건입니다. 이미 완성된 다른 요청의 응답 송신 가능 여부는 상대가 여전히 읽는지에 달려 있습니다.
