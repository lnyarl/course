프로그래머의 모나드 정의

실패할 수 있는 계산 둘을 일반 함수 합성으로 바로 연결할 수는 없습니다. bind는 중간 구조를 처리하고 다음 계산으로 연결하여 효과가 있는 화살표의 범주를 만듭니다.

1. 문제에서 출발하기

문자열을 숫자로 읽고, 0이 아니면 역수를 계산하는 코드를 생각해 봅시다. 첫 함수가 Option<int>를 반환하면 다음 int→Option<double> 함수의 인자와 맞지 않습니다. 매번 Some/None 분기를 손으로 쓰는 대신 동일한 연결 규칙을 정의할 수 있습니다.

모나드의 핵심은 “값을 상자에 넣는다”는 비유만이 아닙니다. 효과가 있는 함수의 합성을 결합적이고 항등이 있는 연산으로 만드는 법입니다. Option은 실패, List는 여러 결과, Writer는 로그를 연결하지만 같은 합성 형식을 공유합니다.

2. 정의와 타입

이 장의 프로그래머 모형에서 M은 순수 전함수 범주의 자기함자입니다. pure_A:A→M(A), bind:M(A)×(A→M(B))→M(B)를 갖습니다. Kleisli 합성은 f:A→M(B), g:B→M(C)에 대해 (g⋆f)(a)=bind(f(a),g)이며 항등은 pure입니다.

법칙은 모든 유효한 a,m,f,g에 대해 bind(pure(a),f)=f(a), bind(m,pure)=m, bind(bind(m,f),g)=bind(m,a↦bind(f(a),g))입니다. 함수 인스턴스의 참조가 아니라 같은 입력에서 같은 결과를 낸다는 의미입니다. 법칙이 있어야 합성의 괄호를 바꿔도 프로그램 의미가 유지됩니다.

join : M(M(A)) → M(A)
bind(m,f)=join(map(f,m))
map(h,m)=bind(m,a↦pure(h(a)))

3. 계산에서 일반 논증으로

Option에서 pure(a)=Some(a), bind(None,f)=None, bind(Some(a),f)=f(a)로 정합니다. 좌항등은 Some 분기 대입으로 성립합니다. 우항등은 None일 때 None이고 Some(a)일 때 Some(a)입니다. 결합 법칙은 m=None이면 양쪽이 None, m=Some(a)이면 양쪽이 bind(f(a),g)로 같아집니다. 임의 f(a)의 결과를 별도 검사할 필요도 없습니다.

예를 들어 half(8)=Some(4), half(4)=Some(2)로 성공합니다. half(6)=Some(3) 뒤 half(3)=None으로 실패하면 이후 함수가 실행되지 않습니다. bind는 실패를 임의 성공값으로 바꾸는 복구 정책이 아닙니다. 복구는 별도의 연산으로 설계해야 합니다.

List의 bind는 각 원소가 만든 리스트들을 원래 순서대로 연결합니다. map만 사용하면 List<List<B>>가 되고 join이 한 층을 없애야 합니다. 순서가 있는 리스트에서 결과 순서를 임의 정렬하면 원래 리스트 모나드가 아닙니다.

4. 직접 조작하는 세 실험

1. Option 계산의 실패 전파

half(n)는 짝수일 때 Some(n/2), 홀수일 때 None입니다. 두 번째 계산을 선택해 bind 경로를 추적합니다.

2. 결합 법칙 양 경로

m=Some(n) 또는 None, f=half, g(x)=Some(x+3)입니다. 괄호를 달리해 같은 Option을 얻습니다.

3. 우항등과 잘못된 bind

정상 bind와 성공 결과에 1을 덧붙이는 잘못된 bind를 비교합니다. 우항등 m≫=pure=m이 깨지는지 확인합니다.

5. 실행 가능한 C#

아래는 C# 12 / .NET 8 전체 프로그램입니다. BCL만 사용하며 examples/Ch20에서 실행할 수 있습니다. JavaScript 실험은 이 계산을 시각화한 별도 모형입니다.

Option<int> m = new Option<int>.Some(8);
Option<int> Half(int n) => n % 2 == 0
    ? new Option<int>.Some(n / 2)
    : new Option<int>.None();
var result = m.Bind(Half).Bind(Half);
Console.WriteLine(Show(result));
Console.WriteLine(Show(new Option<int>.Some(6).Bind(Half).Bind(Half)));
Console.WriteLine(Show(m.Bind(x => new Option<int>.Some(x))));
static string Show(Option<int> x) => x switch
{
    Option<int>.Some s => $"Some({s.Value})",
    _ => "None"
};
abstract record Option<A>
{
    public sealed record Some(A Value) : Option<A>;
    public sealed record None : Option<A>;
    public Option<B> Bind<B>(Func<A, Option<B>> f) => this switch
    {
        Some s => f(s.Value),
        _ => new Option<B>.None()
    };
}

기대 표준 출력:

Some(2)
None
Some(8)

6. 모형의 경계

C#의 async/await 문법이 있다는 이유만으로 Task를 이 장의 순수하고 전역적인 lawful 모나드라고 단정하지 않습니다. 실행 시작 시점, 예외, 취소, 스케줄링과 관찰 가능한 시간에 대한 동등성 기준을 먼저 정해야 합니다. LINQ SelectMany도 이름만으로 모나드 법칙을 보장하지 않습니다.

예제의 Option은 null이 아닌 Some/None과 순수하고 종료하는 f에 제한합니다. C#에는 HKT가 없으므로 모든 M을 받는 범용 Monad<M> 타입을 가상 문법으로 만들지 않았습니다. 모나드는 예외를 숨기는 마법이 아니라 명시적으로 정한 효과와 합성 규칙입니다.

7. 확인 문제

bind와 map의 차이는?
map(f)는 M(M(B))를 만들고 join이 한 층을 없앱니다.
Kleisli 항등사상은?
A에서 M(A)로 가는 Kleisli 타입이 필요합니다.
결합 법칙이 허용하는 것은?
순서는 유지하고 합성 괄호만 바꿉니다.
Some(6)에서 half를 두 번 적용하면?
6→Some(3), 3은 홀수여서 None입니다.

8. 구현 실습

실습 A · List bind

[1,2]의 각 x를 [x,−x]로 바꾸고 한 층을 펼치세요.

기대 출력:

1,-1,2,-2
True
힌트

SelectMany는 이 구체 리스트 모형에서 map 후 연결을 수행합니다.

해답 · 별도 Program.cs 전체
int[] xs = [1, 2];
var result = xs.SelectMany(x => new[] { x, -x }).ToArray();
Console.WriteLine(string.Join(",", result));
Console.WriteLine(xs.SelectMany(x => new[] { x }).SequenceEqual(xs));

결과 순서를 유지하며 우항등을 원소별로 확인했습니다.

실습 B · Option 결합 법칙

nullable int를 실패 모형으로 제한해 Some(8), Some(7), None에서 half 후 +3을 양쪽 괄호로 계산하세요.

기대 출력:

7:True
None:True
None:True
힌트

Bind는 HasValue이면 f를 호출하고 아니면 null을 반환합니다.

해답 · 별도 Program.cs 전체
static int? Bind(int? m, Func<int,int?> f)
    => m.HasValue ? f(m.Value) : null;
static int? Half(int x) => x % 2 == 0 ? x / 2 : null;
static int? Add(int x) => x + 3;
foreach (int? m in new int?[] { 8, 7, null })
{
    var a = Bind(Bind(m, Half), Add);
    var b = Bind(m, x => Bind(Half(x), Add));
    Console.WriteLine($"{a?.ToString() ?? "None"}:{a == b}");
}

이 조각은 int?라는 한 타입의 사례입니다. 모든 타입의 Option 모나드를 선언한 것은 아닙니다.

9. 핵심 정리

  • 모나드는 효과 있는 함수의 결합적 합성과 항등을 제공합니다.
  • bind는 순수 값을 받는 다음 계산과 구조 속 값을 연결합니다.
  • 법칙은 좌항등·우항등·결합성으로, 순서 교환 법칙이 아닙니다.
  • map+join, bind, Kleisli 합성은 법칙 아래 서로 변환할 수 있습니다.
