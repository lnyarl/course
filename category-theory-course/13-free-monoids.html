1. 필요한 법칙만 적용하기

생성자 집합 X에서 원소들을 곱해 새 원소를 만들고 싶다고 합시다. 괄호가 다른 곱은 결합법칙으로 같게 보고, 항등원 e를 끼워 넣은 것은 항등법칙으로 제거합니다. 그 밖의 등식은 추가하지 않습니다. 남는 표준 형태는 X 원소의 유한한 리스트입니다.

이를 X 위의 자유 모노이드 X*라고 합니다. 연산은 리스트 연결, 항등원은 빈 리스트입니다. “자유”는 원소들의 순서를 교환해도 된다는 뜻이 아닙니다. [a,b]와 [b,a]는 다르고, 생성자 6을 포함하는 경우 [2,3]과 [6]도 다른 단어입니다.

2. 단어의 연결과 표시 한도

리스트 연결은 괄호를 어떻게 묶어도 동일한 원소 시퀀스를 주며 빈 리스트는 양쪽에서 아무 원소도 추가하지 않습니다. 그래서 모노이드 법칙이 성립합니다. 생성자 집합이 비어 있으면 빈 단어 하나만 있고, 원소가 하나라도 있으면 임의 길이의 단어가 있어 전체 자유 모노이드는 무한합니다.

최대 길이 n까지의 목록은 관찰용 유한 접두 목록입니다. 두 목록 원소를 연결하면 길이가 n을 넘을 수 있으므로 이 잘린 목록 자체가 연결 연산 아래 닫힌 모노이드는 아닙니다. 아래 재생기는 선택한 단어를 한 글자씩 만들고 작은 길이 목록의 개수도 셉니다.

3. 모노이드 준동형

모노이드 사이의 사상으로 구조를 보존하는 함수를 고르면 Mon이라는 범주를 얻습니다. 준동형 h:M→N은 h(e_M)=e_N과 h(a⋆_M b)=h(a)⋆_N h(b)를 모두 만족해야 합니다. 합성과 항등 함수도 이 성질을 보존합니다.

h(e_M)=e_N
h(a⋆b)=h(a)⋆h(b)

원소들의 집합만 남기는 망각 함자 U:Mon→Set은 모노이드의 연산·항등원 구조를 잊습니다. 준동형도 바탕 집합 사이의 함수로 옮깁니다. X의 생성자 이미지를 후보 모노이드의 바탕 집합에서 고르는 q:X→U(M)는 아직 준동형이 아니라 평범한 함수입니다.

Mon의 객체는 모노이드 전체입니다. 3장에서 모노이드 하나를 객체 하나의 범주로 표현한 것과 층위가 다릅니다. 그때 원소는 고리 사상이었고, 지금 Mon의 사상은 모노이드 사이 준동형입니다.

4. 보편적 성질: 생성자 지정의 유일한 확장

생성자 주입 η:X→U(X*)는 x를 한 원소 리스트 [x]로 보냅니다. 임의의 모노이드 M과 함수 q:X→U(M)에 대해 유일한 모노이드 준동형 h:X*→M이 있어 U(h)∘η=q를 만족합니다.

q : X → U(M)
유일한 h : X* → M
h([x])=q(x), h([])=e_M

존재는 각 생성자를 q로 바꾸어 모노이드 연산으로 접는 FoldMap입니다. 유일성은 모든 단어가 [x₁]++…++[xₙ]로 표현되고 준동형이 연결을 보존해야 하므로 h의 결과가 q(x₁)⋆…⋆q(xₙ)으로 강제된다는 사실로 얻습니다. 빈 단어의 결과도 항등원 보존이 강제합니다.

생성자 이미지를 고정한 뒤 연결의 두 해석 경로를 비교합니다.

5. 해석은 단어들을 합칠 수 있다

리스트를 정수 곱셈으로 해석하면 [2,3], [6], [1,6] 등은 모두 6으로 갈 수 있습니다. 자유 모노이드는 원래 단어들을 유지하고, 해석 준동형이 추가 식별을 도입합니다. 따라서 FoldMap이 항상 단사인 것은 아닙니다.

하나의 모노이드에 생성자 이미지를 지정하면 확장은 유일하지만, 생성자 함수를 바꾸면 다른 준동형이 됩니다. “모든 리스트에서 정수로 가는 준동형이 하나뿐”이라는 뜻은 아닙니다. 자유 구성의 보편성은 주어진 q를 고정한 뒤의 유일성입니다.

실험 3 · 단어와 해석 결과의 구별

리스트는 달라도 곱셈 해석은 같을 수 있습니다.

6. 한 생성자와 자연수

X가 한 원소 {a}면 각 단어는 길이로 완전히 정해집니다. 빈 단어는 0, a는 1, aa는 2입니다. 연결은 길이 덧셈으로 옮겨지므로 이 자유 모노이드는 (자연수,+,0)와 동형입니다. 곱셈의 자연수 모노이드와는 다른 이야기입니다.

임의의 모노이드 M에서는 모든 원소를 생성자로 삼아 평가하는 전사 준동형을 만들 수 있습니다. 같은 결과로 평가되는 단어들을 식별하면 M을 회복합니다. 원문은 이 관점으로 자유 구조가 더 많은 등식을 가진 구조의 출발점이 됨을 설명하고 뒤의 자유·망각 수반으로 연결합니다.

7. 항등원 보존을 빼면 생기는 문제

연산을 보존한다는 식만으로 항등원 보존을 항상 얻을 수는 없습니다. h의 상이 목표 모노이드 전체를 덮지 않으면 h(e)는 상 안에서만 항등원처럼 작동할 수 있습니다. 정수 곱셈에서 모든 값을 0으로 보내는 함수는 곱을 보존하지만 1을 1로 보내지 않습니다.

반면 연산 보존 함수가 동형처럼 전사이면 모든 목표 원소가 h(a)이므로 h(e)가 목표 전체의 양쪽 항등원으로 작동합니다. 항등원의 유일성 때문에 h(e)=e가 됩니다. 코드의 메서드 시그니처가 이 법칙을 자동으로 증명하는 것은 아니며, 부동소수점 연산 같은 후보에서는 결합법칙 자체도 따져야 합니다.

전체 C# 프로그램

C# 12 / .NET 8, 외부 패키지 없는 전체 Program.cs입니다. examples/Ch13에서 dotnet run으로 실행합니다. 이 예제는 명시한 순수 값 모델을 구현합니다. C# 전체의 종료·순수성을 타입이 증명한다는 뜻은 아닙니다.

using System.Numerics;

internal static class Program
{
    static BigInteger FoldMap<T>(IEnumerable<T> word, Func<T, BigInteger> q, Func<BigInteger, BigInteger, BigInteger> append, BigInteger unit)
    {
        var result = unit;
        foreach (var x in word)
            result = append(result, q(x));
        return result;
    }

    static void Main()
    {
        Func<char, BigInteger> q = c => c == 'a' ? 2 : 3;
        Func<BigInteger, BigInteger, BigInteger> multiply = (a, b) => a * b, add = (a, b) => a + b;
        Console.WriteLine($"product(aba) = {FoldMap("aba", q, multiply, 1)}");
        Console.WriteLine($"sum(aba) = {FoldMap("aba", q, add, 0)}");
        Console.WriteLine($"empty product = {FoldMap("", q, multiply, 1)}");
        string u = "ab", v = "ba";
        Console.WriteLine($"homomorphism = {FoldMap(u + v, q, multiply, 1) == FoldMap(u, q, multiply, 1) * FoldMap(v, q, multiply, 1)}");
    }
}

기대 출력:

product(aba) = 12
sum(aba) = 7
empty product = 1
homomorphism = True

해답 · 독립 실행 Program.cs
