1. 문제에서 출발하기

리스트 [2,4]를 보관한 뒤 int→string, int→bool 같은 관찰 함수를 받아 결과 리스트를 만드는 API를 생각해 봅시다. 관찰 함수를 받을 때마다 원소를 바꾸거나 새 원소를 추가할 수 있다면 원래 데이터와 대응하지 않습니다. 모든 관찰과 일관되게 작동한다는 조건이 필요합니다.

요네다 보조정리는 이 일관성을 자연성으로 표현합니다. 수많은 타입 X에 대한 함수족을 따로 저장할 필요 없이 F(A)의 값 하나로 정확히 복원할 수 있습니다. 모든 함자가 표현 가능하다는 정리는 아닙니다. Hom에서 F로 가는 자연변환을 분류하는 정리입니다.

2. 정의와 타입

C를 국소적으로 작은 범주, A를 C의 객체, F:C→Set을 공변 함자라 합시다. 필요한 자연변환들이 집합이 되는 크기 조건을 둡니다. H_A(X)=Hom_C(A,X), H_A(k)(h)=k∘h입니다. h:A→X, k:X→Y이므로 k∘h:A→Y입니다. 이 연산은 후합성입니다.

α:H_A⇒F의 성분은 α_X:Hom(A,X)→F(X)입니다. 자연성은 F(k)(α_X(h))=α_Y(k∘h)입니다. 이 조건을 만족하는 모든 α의 집합과 F(A) 사이에 전단사 대응이 있습니다.

Nat(Hom(A,−),F) ≅ F(A)
decode(α)=α_A(id_A)
encode(v)_X(h)=F(h)(v)

3. 계산에서 일반 논증으로

먼저 decode(encode(v))=F(id_A)(v)=v입니다. 함자의 항등 보존을 사용했습니다. 반대 방향은 자연성 식에서 X=A, h=id_A, k=q:A→Y를 대입하면 α_Y(q)=F(q)(α_A(id_A))이므로 encode(decode(α))=α입니다. 임의의 Y와 q에 대한 등식이므로 함수족 전체가 복원됩니다.

예를 들어 F=List, A=정수, v=[2,4], q(n)=n+1이면 α(q)=[3,5]입니다. q를 두 배로 바꾸면 [4,8]입니다. h:A→X가 없는 객체 X에서는 Hom(A,X)=∅이며 그 성분은 빈 집합에서 나가는 유일한 함수입니다. 연결되지 않은 객체에 임의의 선택이 더 생기지 않습니다.

4. 직접 조작하는 세 실험

1. 리스트 요네다 encode

v=[n,n+2]를 고정하고 q를 선택합니다. 원소별 선은 같은 슬롯이 q를 거쳐 어떤 값이 되는지 보여 줍니다. decode는 q 결과에서 역산하지 않습니다. 별도 id_A 관찰은 같은 함수족에서 원래 리스트를 복원합니다.

2. 자연성 사각형

h(x)=x+1 후 k를 합성하는 경로와 먼저 α(h)를 얻고 List(k)로 옮기는 경로를 비교합니다.

3. 자연성을 깨는 구현

α(h)=map(h,v) 뒤에 출력에 1을 더하는 정수 전용 편법과 lawful α를 비교합니다. k(x)=2x에서 경로 차이가 납니다. 오른쪽의 두 결과는 독립 경로의 비교 대상입니다. 위 결과를 아래 결과로 보내는 화살표는 없습니다.

5. 실행 가능한 C#

아래는 C# 12 / .NET 8 전체 프로그램입니다. BCL만 사용하며 examples/Ch15에서 실행할 수 있습니다. JavaScript 실험은 이 계산을 시각화한 별도 모형입니다.

int[] seed = [2, 4];
var encoded = new YonedaList<int>(seed);
Console.WriteLine(string.Join(",", encoded.Apply(x => x + 1)));
Console.WriteLine(string.Join(",", encoded.Apply(x => x)));
Console.WriteLine(string.Join(",", encoded.Apply(x => x.ToString())));
sealed class YonedaList<A>(IEnumerable<A> values)
{
    private readonly A[] data = values.ToArray();
    public B[] Apply<B>(Func<A, B> h) => data.Select(h).ToArray();
}

기대 표준 출력:

3,5
2,4
2,4

6. 모형의 경계

C#는 F<A>에서 F 자체를 타입 매개변수로 받는 고차 종류 타입을 직접 제공하지 않습니다. 위 코드는 List라는 구체 함자로 한정합니다. Apply<B>는 결과 타입을 바꿔 호출할 수 있지만 C#에서는 typeof(B), 전역 상태, 예외와 null을 사용할 수 있으므로 메서드 시그니처만으로 매개변수적 자연성을 증명하지 못합니다. 구현이 순수 map임을 별도로 확인합니다.

원문이 co-Yoneda라고 부르는 반변 버전은 F:Cᵒᵖ→Set에 대해 Nat(Hom(−,A),F)≅F(A)입니다. 여기의 F는 앞의 공변 F와 다릅니다. 이름은 문헌마다 달라질 수 있으므로 방향과 타입을 기준으로 읽습니다. CPS의 특수식 (∀X.(A→X)→X)≅A도 순수하고 전역적으로 매개변수적인 함수족에 대한 주장입니다.

8. 구현 실습

실습 A · 자연성 두 경로

v=[1,3], h(x)=x+2, k(x)=3x에서 두 경로를 구현하세요.

기대 출력:

9,15
True
힌트

Select를 두 번 하는 경로와 합성 함수로 한 번 하는 경로를 비교합니다.

해답 · 별도 Program.cs 전체
int[] v = [1, 3];
Func<int,int> h = x => x + 2, k = x => 3 * x;
var left = v.Select(x => k(h(x))).ToArray();
var right = v.Select(h).Select(k).ToArray();
Console.WriteLine(string.Join(",", left));
Console.WriteLine(left.SequenceEqual(right));

같은 입력의 결과를 비교합니다. 일반 증명은 함자의 합성 법칙입니다.

실습 B · Unit 리스트의 요네다 관찰

Unit 세 개로 길이 3을 표현합니다. α_X(h)=map(h,units)를 구현해 문자열 관찰 결과와 id_Unit에서 복원한 길이를 출력하세요.

기대 출력:

tick,tick,tick
3
힌트

Unit은 필드 없는 readonly record struct로 정의하고, 제네릭 지역 함수 Alpha에서 Select를 사용하세요.

해답 · 별도 Program.cs 전체
Unit[] units = [new(), new(), new()];
B[] Alpha<B>(Func<Unit,B> h) => units.Select(h).ToArray();
var observed = Alpha(_ => "tick");
var decoded = Alpha(x => x);
Console.WriteLine(string.Join(",", observed));
Console.WriteLine(decoded.Length);
readonly record struct Unit;

α는 모든 결과 타입 B에서 동일한 Unit 리스트를 관찰합니다. id_Unit에서의 평가로 원래 리스트를 복원하며 그 정보는 길이뿐입니다. C#의 null·타입 검사 일반 문제와 달리 이 구현은 순수 Select로 제한했습니다.

9. 핵심 정리

  • 요네다 대응의 입력은 자연변환 전체이며 출력은 F(A)의 원소 하나입니다.
  • decode는 항등에서 평가하고 encode는 F의 사상 작용으로 확장합니다.
  • 공변·반변 버전의 Hom 방향과 F의 분산을 함께 확인합니다.
  • C# 구현은 구체 함자의 순수 구현으로 정리를 모델링하며 타입 선언만으로 증명하지 않습니다.
