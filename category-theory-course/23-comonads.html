코모나드

모나드가 값에서 효과 있는 결과로 가는 계산을 연결한다면, 코모나드는 이미 주어진 문맥을 읽어 결과를 만드는 계산을 연결합니다. 초점이 있는 Store로 extract·duplicate·extend를 확인합니다.

1. 문제에서 출발하기

온도 배열의 각 위치에서 주변 세 칸 평균을 계산하려면 현재 값 하나만으로는 부족합니다. 주변 값 전체와 현재 위치라는 문맥이 필요합니다. 이런 문맥을 받는 함수 W(A)→B가 코클레이슬리 사상입니다.

각 위치로 초점을 옮긴 문맥을 만들고 같은 함수를 적용하면 전체 결과를 얻습니다. 코모나드는 이 이동과 관찰을 합성합니다. 모든 모나드에서 값을 꺼내는 공통 함수가 있는 것은 아니지만, 코모나드의 extract는 항상 현재 값을 얻도록 정의되어 있습니다.

2. 정의와 타입

코모나드는 자기함자 W:C→C와 자연변환 ε:W⇒Id, δ:W⇒W²로 이루어집니다. 성분은 extract_A:W(A)→A, duplicate_A:W(A)→W(W(A))입니다. 법칙은 extract_WA∘duplicate_A=id_WA, W(extract_A)∘duplicate_A=id_WA, duplicate_WA∘duplicate_A=W(duplicate_A)∘duplicate_A입니다.

extend(f)=map(f)∘duplicate:W(A)→W(B), f:W(A)→B입니다. f:W(A)→B, g:W(B)→C의 코클레이슬리 합성은 g∘extend(f):W(A)→C이며 항등은 extract입니다. duplicate=extend(id)이므로 중복 만들기와 확장 중 하나를 기본 연산으로 정할 수 있습니다.

Store(S,A) = (S→A) × S
extract(peek,s)=peek(s)
duplicate(peek,s)=(t↦(peek,t),s)
extend(f)(peek,s)=(t↦f(peek,t),s)

3. 계산에서 일반 논증으로

Store는 모든 위치의 값을 조회하는 순수 함수 peek:S→A와 현재 초점 s를 가집니다. duplicate는 데이터를 여러 번 변경하거나 복사하는 대신 각 t에서 초점 t를 갖는 Store를 볼 수 있게 만듭니다. 바깥 초점은 원래 s로 유지됩니다.

extract(duplicate(w))는 위치 s에 초점을 맞춘 원래 Store를 얻습니다. map(extract)(duplicate(w))의 조회 함수는 t↦extract(peek,t)=peek(t)이므로 원래 조회 함수와 입력별로 같습니다. 두 duplicate 경로는 각각 (peek,t)를 초점 u로 재관찰하는 동일한 문맥을 구성하므로 공동결합성을 만족합니다. 이 법칙들은 객체 참조의 같음이 아니라 조회 결과와 초점의 같음으로 이해합니다.

peek(i)=i²이고 초점이 2라면 extract=4입니다. 주변 세 값 합 함수 f(w)=peek(s−1)+peek(s)+peek(s+1)을 extend하면 새 조회 함수는 각 위치에서 그 합을 계산합니다. 초점 2의 합은 1+4+9=14입니다. 평균을 쓰면 분모 3을 나누되 경계 정책도 명시해야 합니다.

고정 환경 E와 값 A의 곱 (E,A)도 extract(e,a)=a, duplicate(e,a)=(e,(e,a))인 코모나드입니다. 무한 스트림은 첫 원소를 초점으로 하고 모든 꼬리 스트림을 duplicate합니다. 빈 리스트는 현재 값을 항상 꺼낼 수 없어 이 extract를 가진 코모나드가 되지 않습니다.

4. 직접 조작하는 세 실험

1. Store 초점과 주변 문맥

peek(i)=i²입니다. 초점 n에서 extract와 주변 세 칸 합을 계산하고 duplicate가 만든 초점별 문맥을 봅니다.

2. 두 쌍대단위 법칙

duplicate(w)에서 바깥 extract로 w를 얻는 경로와 각 안쪽 extract를 map하는 경로를 비교합니다.

3. 빈 리스트와 필수 초점

길이 n인 리스트에서 첫 값을 꺼내는 모델을 검사합니다. 빈 경우 임의 기본값으로 대체하면 원래 extract와 다른 함수입니다.

5. 실행 가능한 C#

아래는 C# 12 / .NET 8 전체 프로그램입니다. BCL만 사용하며 examples/Ch23에서 실행할 수 있습니다. JavaScript 실험은 이 계산을 시각화한 별도 모형입니다.

var store = new Store<int,int>(i => i*i, 2);
Console.WriteLine($"extract={store.Extract()}");
var sums = store.Extend(w => w.Peek(w.Position-1)
    + w.Extract() + w.Peek(w.Position+1));
Console.WriteLine($"localSum={sums.Extract()}");
var firstLaw = store.Duplicate().Extract();
var secondLaw = store.Duplicate().Map(w => w.Extract());
Console.WriteLine($"focus={firstLaw.Position},{secondLaw.Position}");
Console.WriteLine($"peek3={firstLaw.Peek(3)},{secondLaw.Peek(3)}");
sealed record Store<S,A>(Func<S,A> Peek, S Position)
{
    public A Extract() => Peek(Position);
    public Store<S,B> Map<B>(Func<A,B> f)
    {
        var peek = Peek;
        return new(s => f(peek(s)), Position);
    }
    public Store<S,Store<S,A>> Duplicate()
    {
        var peek = Peek;
        return new(s => new Store<S,A>(peek,s), Position);
    }
    public Store<S,B> Extend<B>(Func<Store<S,A>,B> f)
        => Duplicate().Map(f);
}

기대 표준 출력:

extract=4
localSum=14
focus=2,2
peek3=9,9

6. 모형의 경계

위 C# Store는 순수한 조회 함수와 값 초점을 전제로 합니다. record의 자동 동등성은 delegate 참조를 비교하므로 수학적 Store 동등성을 검사하지 않습니다. 유한 위치 표본에서 조회 결과를 비교할 수는 있지만 모든 입력의 함수 동등성을 결정하지는 못합니다.

원문의 무한 스트림을 C# 배열로 그대로 바꾸면 마지막 위치에서 다음 값이 없어지는 문제가 생깁니다. 이 장의 i² 조회 함수는 양 방향 위치를 계산해 경계 문제를 피하되 int 오버플로가 없는 작은 입력에서만 실행합니다. 실제 영상·격자 처리에서는 순환, 패딩, 고정 경계 등 정책을 명시해야 합니다.

모나드의 쌍대라는 말은 임의 모나드 값에서 extract를 만들어 낼 수 있다는 뜻이 아닙니다. 반대 범주에서 연산 방향을 뒤집은 구조입니다. 수반 L⊣R에서 RL은 모나드, LR은 코모나드이며 δ=LηR, ε는 수반의 쌍대단위입니다.

7. 확인 문제

코클레이슬리 사상의 타입은?
이미 주어진 문맥을 읽어 값을 계산합니다.
duplicate의 타입은?
join과 반대 방향으로 문맥의 문맥을 만듭니다.
Store duplicate가 바꾸는 것은?
바깥 초점은 유지하고 위치마다 다른 초점의 Store를 제공합니다.
List 전체에서 head를 extract로 쓸 수 없는 이유는?
코모나드 extract는 모든 유효한 W(A)에 정의되어야 합니다.

8. 구현 실습

실습 A · 곱 코모나드 extend

환경 e=3, 값 a=4인 쌍에서 f(e,a)=e+a로 extend한 결과와 extract를 계산하세요.

기대 출력:

3,7
7
힌트

환경은 보존하고 값 성분만 문맥 함수의 결과로 바꿉니다.

해답 · 별도 Program.cs 전체
var context = (Env: 3, Value: 4);
static (E Env, B Value) Extend<E,A,B>((E Env,A Value) w,
    Func<(E Env,A Value),B> f) => (w.Env, f(w));
var result = Extend(context, w => w.Env + w.Value);
Console.WriteLine($"{result.Env},{result.Value}");
Console.WriteLine(result.Value);

환경은 유지되며 f가 문맥 전체를 읽어 새로운 값을 만듭니다.

실습 B · 문맥 연산의 공동결합성

Store의 peek(i)=i², 원래 초점 2에서 duplicate 두 번과 duplicate를 map한 두 경로를 실제 구성해 비교하세요. 중간 초점 3, 안쪽 초점 4를 사용합니다.

기대 출력:

4,4
25,25
힌트

두 결과 타입은 Store>>입니다. 바깥 Peek(3) 후 안쪽 Peek(4)를 비교하세요.

해답 · 별도 Program.cs 전체
var w = new Store<int,int>(i => i*i, 2);
var left = w.Duplicate().Duplicate();
var right = w.Duplicate().Map(x => x.Duplicate());
var leftInner = left.Peek(3).Peek(4);
var rightInner = right.Peek(3).Peek(4);
Console.WriteLine($"{leftInner.Position},{rightInner.Position}");
Console.WriteLine($"{leftInner.Peek(5)},{rightInner.Peek(5)}");
sealed record Store<S,A>(Func<S,A> Peek, S Position)
{
    public Store<S,B> Map<B>(Func<A,B> f)
        => new(s => f(Peek(s)), Position);
    public Store<S,Store<S,A>> Duplicate()
        => new(s => new Store<S,A>(Peek,s), Position);
}

바깥 초점은 양쪽 모두 2이고, 중간 3 및 안쪽 4로 관찰해 같은 초점·조회값을 얻습니다. 일반 증명은 임의 초점에서 같은 조회 함수를 갖는다는 등식입니다.

9. 핵심 정리

  • 코모나드는 문맥을 소비하는 계산 W(A)→B를 합성합니다.
  • extract는 현재 값, duplicate는 초점별 문맥, extend는 문맥별 계산입니다.
  • 코모나드 법칙은 두 쌍대단위 법칙과 공동결합성입니다.
  • Store는 순수 조회 함수와 초점을 묶으며 수반의 LR에서 유도됩니다.
