자유·망각 수반

자유는 아무 법칙도 없다는 뜻이 아닙니다. 모노이드 법칙만 적용하고 추가 관계를 강제하지 않아, 생성자에 지정한 함수가 유일한 준동형으로 확장되는 구조입니다.

1. 문제에서 출발하기

토큰 a,b로 이루어진 입력을 여러 방식으로 해석하려 합니다. 한 해석은 토큰별 비용을 더하고, 다른 해석은 문자열을 이어 붙입니다. 매번 문법 트리를 새로 만들기보다 토큰의 리스트를 공통 중간 표현으로 쓰면 각 해석은 fold로 확장됩니다.

추가로 ab=ba를 강제하면 순서에 민감한 문자열 해석을 더 이상 만들 수 없습니다. 자유 모노이드는 모노이드의 결합·항등 법칙 이외의 관계를 넣지 않아서 가능한 모든 생성자 해석을 받아들입니다. 자유라는 말은 실행이 무료이거나 제약 없는 mutation이라는 뜻이 아닙니다.

2. 정의와 타입

Mon의 객체는 (M,⋅,e) 모노이드이고 사상은 h(e)=e′, h(x⋅y)=h(x)⋅′h(y)를 만족하는 준동형입니다. U는 연산과 항등을 잊고 기저 집합과 기저 함수를 남깁니다. F(X)=X의 유한 리스트 전체 X*이며 연산은 연결, 항등은 빈 리스트입니다. F(f)는 각 원소를 f로 바꿉니다.

F⊣U의 Hom 전단사는 Mon(FX,M)≅Set(X,UM)입니다. 오른쪽 함수 k는 임의의 전함수이며 단사일 필요가 없습니다. 확장은 k*([]) = e, k*([x₁,…,xₙ])=k(x₁)⋅…⋅k(xₙ)입니다. 역방향은 h를 길이 1 리스트에 제한한 k(x)=h([x])입니다.

η_X(x)=[x]
ε_M([m₁,…,mₙ])=m₁⋅…⋅mₙ
k* ∘ η_X=k

3. 계산에서 일반 논증으로

k*는 빈 리스트를 e로 보내고 연결을 곱으로 보내므로 준동형입니다. 다른 준동형 h가 h([x])=k(x)를 만족한다고 합시다. 모든 리스트는 [x₁]++…++[xₙ]으로 분해되므로 준동형 법칙을 반복 적용하면 h의 값이 k의 곱으로 강제됩니다. 빈 리스트도 항등 보존으로 고정됩니다. 이로써 존재와 유일성을 모두 얻습니다.

X={a,b}, k(a)=2,k(b)=3, M=(정수,+,0)이면 k*([a,b,a])=7입니다. 두 생성자가 같은 값으로 갈 수도 있습니다. 그래서 자유 모노이드가 모든 M의 부분모노이드로 단사 삽입된다는 해석은 틀립니다. 전단사는 “확장 방법” 사이의 대응이지 k 자체의 단사성 조건이 아닙니다.

자연성은 생성자를 먼저 바꾼 뒤 접는 것과 k를 먼저 합성해 접는 것이 같고, 해석 결과에 준동형을 나중에 적용하는 것과 생성자 해석에 먼저 적용하는 것이 같다는 뜻입니다. 임의의 출력 함수는 모노이드 연산을 보존하지 않을 수 있어 Mon 쪽 사상으로 사용할 수 없습니다.

4. 직접 조작하는 세 실험

1. 생성자 해석과 fold

리스트 [a,b,a]에서 k(a)=n, k(b)=3으로 정합니다. 덧셈 모노이드와 문자열 연결 모노이드의 해석을 비교합니다.

2. 준동형의 연결 보존

u=[a,b], v=[a]입니다. 연결 후 fold와 각각 fold한 뒤 목표 연산을 비교합니다.

3. 임의 함수와 준동형의 차이

정수 덧셈 모노이드의 후보 h(x)=cx 또는 h(x)=cx+1을 비교합니다. h(0)=0과 h(x+y)=h(x)+h(y)를 둘 다 확인합니다.

5. 실행 가능한 C#

아래는 C# 12 / .NET 8 전체 프로그램입니다. BCL만 사용하며 examples/Ch19에서 실행할 수 있습니다. JavaScript 실험은 이 계산을 시각화한 별도 모형입니다.

char[] word = ['a','b','a'];
static int K(char c) => c == 'a' ? 2 : 3;
static int Fold(IEnumerable<char> xs) => xs.Aggregate(0, (acc,c) => acc + K(c));
Console.WriteLine(Fold(word));
char[] u = ['a','b'], v = ['a'];
Console.WriteLine(Fold(u.Concat(v)) == Fold(u) + Fold(v));
Console.WriteLine(Fold(Array.Empty<char>()));
Console.WriteLine(Fold(new[]{'a'}) == K('a'));

기대 표준 출력:

7
True
0
True

6. 모형의 경계

C# 배열 한 개는 자유 모노이드 전체가 아니라 그 안의 원소 하나를 표현합니다. 리스트 연결이 새 값을 만드는 순수 연산이라는 관점으로 보고 원본 배열을 변경하지 않습니다. 유한 리스트의 크기·메모리 한계와 int 오버플로 때문에 프로그램 자체가 수학의 모든 리스트와 정수를 실행 가능한 객체로 포괄하지 않습니다.

망각 함자는 모든 정보를 지우지 않습니다. 어떤 구조를 잊는지는 출발·도착 범주가 결정합니다. Mon→Set에서는 모노이드 연산을 잊지만 객체의 원소와 사상의 기저 함수는 남깁니다. F는 U의 역함자가 아닙니다. UFM의 원소는 원소들로 만든 임의 길이 리스트이므로 원래 집합과 보통 같지 않습니다.

7. 확인 문제

Set(X,UM)의 k는 반드시 단사인가요?
생성자 해석은 원소를 합쳐도 됩니다.
자유 모노이드의 항등은?
연결에서 아무 변화도 만들지 않습니다.
확장이 유일한 이유는?
항등 보존이 빈 리스트의 값도 고정합니다.
F⊣U는 F와 U가 역함자라는 뜻인가요?
단위와 쌍대단위는 일반적으로 동형이 아닙니다.

8. 구현 실습

실습 A · 문자열 해석

k(a)="A", k(b)="BB"로 [a,b,a]를 해석하세요.

기대 출력:

ABBA
0
힌트

접기의 항등은 빈 문자열이고 연산은 문자열 연결입니다.

해답 · 별도 Program.cs 전체
char[] word = ['a','b','a'];
var result = word.Aggregate("", (acc,c) => acc + (c=='a' ? "A" : "BB"));
Console.WriteLine(result);
Console.WriteLine(Array.Empty<char>().Aggregate("", (acc,c) => acc+c).Length);

연결 순서를 바꾸지 않아 생성자 해석이 정확히 확장됩니다.

실습 B · 생성자 합치기

k(a)=k(b)=1로 두어 길이를 해석하고 k가 단사가 아니어도 확장이 존재함을 보이세요.

기대 출력:

True
3
힌트

모든 토큰을 1로 옮기고 덧셈으로 접습니다.

해답 · 별도 Program.cs 전체
char[] word = ['a','b','a'];
Func<char,int> k = _ => 1;
Console.WriteLine(k('a') == k('b'));
Console.WriteLine(word.Aggregate(0, (acc,c) => acc+k(c)));

같은 값으로 가는 생성자가 있어도 준동형 확장은 유일합니다.

9. 핵심 정리

  • 자유 모노이드 X*는 유한 리스트, 연결, 빈 리스트로 이루어집니다.
  • F⊣U의 전단사는 생성자 함수와 준동형 확장 사이에 있습니다.
  • 확장의 존재는 fold 구현, 유일성은 싱글턴 분해로 증명합니다.
  • 단위는 싱글턴, 쌍대단위는 모노이드 연산으로 fold입니다.
