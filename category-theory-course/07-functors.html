함자

Map은 반복문 이름이 아니라 타입과 함수의 연결을 함께 보존하는 연산입니다. Option·리스트·Reader에서 같은 두 법칙이 어떻게 구현되는지 확인합니다.

1. 함자는 객체와 화살표를 함께 옮긴다

범주 C의 각 객체 A에 D의 객체 F(A)를 정하는 것만으로 함자가 되지는 않습니다. f:A→B마다 F(f):F(A)→F(B)도 정해야 합니다. 출발·도착이 옮겨진 객체와 맞고, 아래의 두 법칙을 만족해야 합니다. 여러 객체나 사상을 같은 곳으로 보내는 것은 허용하므로 함자는 일반적으로 단사인 매장이 아닙니다.

F(id_A)=id_F(A)
F(g∘f)=F(g)∘F(f)

항등은 연결의 빈 단계를 보존하고, 합성 법칙은 한 번에 합성해 옮기든 각 화살표를 먼저 옮겨 연결하든 결과가 같다는 뜻입니다. 두 범주가 같으면 자기함자(endofunctor)입니다. 프로그래밍의 List·Option 같은 사례는 주로 이 경우입니다.

2. 타입 생성자와 Map

Option 자체는 아직 구체적인 값의 타입이 아니라 타입을 받는 생성자입니다. Option<int>를 주어야 구체적인 타입이 됩니다. 객체 작용은 A↦Option<A>이고, 사상 작용은 함수 f:A→B를 Option<A>→Option<B>로 올립니다. 이 올리는 연산이 Map 또는 원문의 fmap입니다.

Some(a)에는 f를 적용하고 None은 그대로 None입니다. None에서 B를 임의로 만들어 넣으면 원래 구조를 보존하지 못합니다. 순수 함수 모델에서 두 분기를 나누어 항등·합성 법칙을 식으로 전개할 수 있습니다. None에서는 양쪽 모두 None, Some에서는 일반 함수의 항등과 합성이 작동합니다.

3. 법칙은 타입 시그니처보다 강하다

Map이라는 이름과 (A→B)→F(A)→F(B) 모양만 맞춰도 잘못된 구현이 가능합니다. 리스트에서 첫 원소를 지우는 Map을 만들면 id를 넣었을 때 리스트가 바뀝니다. 두 번 Map하면 두 원소를 지우고 합성 함수를 한 번 Map하면 하나만 지우므로 합성도 어긋날 수 있습니다.

그 결과 함자 법칙을 사용한 리팩터링이 안전하지 않습니다. 이 법칙은 성능 수치를 보장하는 것이 아니라 값의 동등성을 보장합니다. C#의 지연 IEnumerable과 부작용 있는 선택 함수에서는 순회 시점·횟수를 추가로 관찰할 수 있으므로 순수하고 유한한 입력이라는 예제의 계약을 지킵니다.

4. 리스트와 Option의 구현

리스트 Map은 순서·길이·중복을 유지하고 각 원소를 f로 바꿉니다. 필터는 길이를 바꿀 수 있는 다른 연산이지 Map의 구현이 아닙니다. 리스트 법칙은 빈 리스트와 앞 원소·나머지 리스트라는 구조에 따라 귀납적으로 증명할 수 있습니다.

C#에서는 List에 대한 Map과 Option에 대한 Map을 각각 정의합니다. C#의 보통 제네릭 인수 F는 F<A>처럼 다시 적용할 수 있는 고차 타입 매개변수가 아닙니다. 한 인터페이스로 모든 함자를 자동 추상화하는 가상 문법을 쓰지 않고, 구체적 타입 생성자의 구현과 공통 법칙을 구별합니다.

5. Reader: 함자는 꼭 상자가 아니다

R을 고정하고 F(A)=R→A로 두면 Reader 자기함자가 됩니다. r:R→A와 f:A→B에 대해 Map(f,r)=f∘r입니다. 환경 R을 읽어 A를 만든 다음 f를 적용하는 함수가 새 Reader입니다.

Reader는 이미 저장된 A 값을 담은 상자가 아닙니다. 실제 환경을 받을 때 A 값을 계산합니다. 따라서 “함자는 컨테이너다”는 비유만 외우면 Reader에서 막힙니다. 일반 정의는 객체와 사상 및 법칙이며, 컨테이너는 일부 예의 직관입니다.

6. 함자의 합성

F와 G가 함자이면 F∘G도 함자입니다. 객체에는 F(G(A)), 사상에는 F(G(f))를 적용합니다. Option<List<A>>의 Map은 바깥 Option을 보존하면서 내부 리스트의 각 A를 바꿉니다. Option이 None이면 내부 리스트를 꺼내 처리할 값도 없습니다.

Map_(F∘G)(f)=Map_F(Map_G(f))

두 Map 각각이 항등과 합성을 보존하므로 중첩된 연산도 두 법칙을 보존합니다. 이는 중첩 자료구조를 평탄화하는 연산과 다릅니다. Map만으로 Option<Option<A>>를 Option<A>로 합치는 동작을 정의한 것은 아닙니다.

7. 등식 추론과 검사 범위

원문은 함수 정의를 대입하는 등식 추론으로 Maybe 법칙을 증명합니다. 일부 수의 실행 결과가 같은 것이 아니라, 두 생성 형태에서 임의의 값에 대해 같은 식이 된다는 논증입니다. 아래 프로그램은 별도로 구체적 실행 결과를 검사합니다.

함자 일반 정의는 임의 범주에 적용되지만, 코드의 null·예외·비종료·외부 상태를 자동으로 해결하지 않습니다. 여기의 Option 실패 상태에서는 Value를 읽지 않고, 리스트는 유한하며 Reader도 같은 환경에서 같은 결과를 내는 함수로 제한합니다.

전체 C# 프로그램

C# 12 / .NET 8, 외부 패키지 없는 전체 Program.cs입니다. examples/Ch07에서 dotnet run으로 실행합니다. 이 예제는 명시한 순수 값 모델을 구현합니다. C# 전체의 종료·순수성을 타입이 증명한다는 뜻은 아닙니다.

readonly record struct Option<T>(bool HasValue, T Value);
internal static class Program
{
    static Option<B> Map<A, B>(Option<A> x, Func<A, B> f) => x.HasValue ? new(true, f(x.Value)) : new(false, default !);
    static Func<R, B> MapReader<R, A, B>(Func<R, A> r, Func<A, B> f) => env => f(r(env));
    static void Main()
    {
        var x = new Option<int>(true, 2);
        Func<int, int> f = n => n + 1, g = n => n * 2;
        var a = Map(Map(x, f), g);
        var b = Map(x, n => g(f(n)));
        Console.WriteLine($"option composition = {a == b}");
        var none = new Option<int>(false, 0);
        Console.WriteLine($"none stays None = {!Map(none, f).HasValue}");
        Console.WriteLine($"list = {string.Join(",", new[] { 1, 2, 3 }.Select(g))}");
        Func<int, int> reader = env => env + 3;
        Console.WriteLine($"reader(4) = {MapReader(reader, g)(4)}");
    }
}

기대 출력:

option composition = True
none stays None = True
list = 2,4,6
reader(4) = 14

핵심 요약

  • 함자는 객체와 사상을 함께 옮기며 항등과 합성을 보존합니다.
  • Map의 타입 모양만으로 법칙이 보장되지는 않습니다.
  • Reader와 합성 함자는 컨테이너 비유를 넘는 예입니다.

확인 문제

함자의 두 법칙은?
함자는 단사일 필요가 없습니다.
None을 Map하면?
없는 값을 적용할 수 없고 구조를 유지합니다.
Reader의 Map은?
R→A 뒤에 A→B를 붙여 R→B를 만듭니다.

실습 2 · 중첩 리스트의 합성 함자

[[1,2],[3]]에서 안쪽 수에 1을 더하되 두 겹의 리스트 구조를 유지하세요.

기대 결과: 2,3;4

힌트

바깥 Select의 함수 안에 안쪽 Select를 둡니다.

해답 · 독립 실행 Program.cs
int[][] xs = [[1, 2], [3]];
var ys = xs.Select(row => row.Select(x => x + 1).ToArray()).ToArray();
Console.WriteLine(string.Join(";", ys.Select(row => string.Join(",", row))));
