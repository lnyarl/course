타입을 튜플이나 태그로 구현하기 전에, 어떤 화살표가 그 구조를 규정하는지 살펴봅니다. 핵심은 “만들 수 있다”를 넘어 “조건을 만족하는 방법이 정확히 하나다”입니다.

1. 관계로 구조를 정의하기

두 값을 묶으라는 요구를 받으면 C#의 튜플을 떠올릴 수 있습니다. 하지만 범주론에서는 객체의 내부에 필드가 있는지 먼저 들여다보지 않습니다. 그 객체와 다른 객체 사이에 어떤 사상이 있는지, 그 사상들이 어떤 식을 만족하는지로 구조를 지정합니다.

원문은 이를 보편적 구성(universal construction)으로 소개합니다. 먼저 원하는 화살표 모양을 정하고, 그 모양에 들어맞는 여러 후보를 찾습니다. 이어 모든 다른 후보가 지정한 방식으로 유일하게 연결되는 후보를 고릅니다. 여기서 “좋은 후보”는 속도가 빠르거나 메모리가 적게 든다는 뜻이 아닙니다. 정확한 사상 조건을 만족한다는 뜻입니다.

두 사영이 있다는 사실만으로 곱이라고 할 수 없고, 두 주입이 있다는 사실만으로 쌍대곱이라고 할 수 없습니다. 존재하지 않는 매개사상이 있거나 가능한 매개사상이 둘 이상이면 보편적 성질을 잃습니다. 이 장의 위젯은 그 두 실패를 서로 다른 색과 개수로 보여 줍니다.

2. 초기 객체와 말단 객체

초기 객체(initial object) I는 모든 객체 X에 대해 I → X 사상이 정확히 하나인 객체입니다. 말단 객체(terminal object) T는 모든 객체 X에 대해 X → T 사상이 정확히 하나인 객체입니다. “하나 이상”도, “최대 하나”도 아니라 정확히 하나입니다. X에는 I나 T 자신도 포함됩니다.

초기: 모든 X에 대해 |Hom(I,X)| = 1
말단: 모든 X에 대해 |Hom(X,T)| = 1

Set에서 빈 집합은 초기 객체입니다. 빈 정의역에는 결과를 지정해야 할 입력이 없으므로 빈 대응표 하나가 유일한 함수입니다. 원소 하나인 집합 Unit은 말단 객체입니다. 어떤 입력이든 그 유일한 원소로 보내는 함수밖에 없습니다. Unit → Bool에는 항상 false 함수와 항상 true 함수가 둘 있으므로 Bool은 말단 객체가 될 수 없습니다.

C#의 Unit은 필드 없는 readonly record struct로 값 동등성 관점의 모델을 만들 수 있습니다. C# void는 일급 Unit 타입이 아니며, 빈 enum을 만들어 수학적 Empty 타입을 구현했다고 주장할 수도 없습니다. 여기서 Empty는 수학적 모델로 사용합니다. 또한 Set 안의 객체 Empty와 3장의 “객체가 하나도 없는 빈 범주”는 서로 다른 층위입니다.

실험 1 · “정확히 하나”인 화살표 세기

후보 K와 크기 0·1·2·3의 검사 집합 X 사이의 모든 순수 전함수 개수를 계산합니다. K와 X는 크기만 정한 별개의 집합입니다. 화살표 방향을 바꾸어 초기·말단 조건을 비교하세요.

유한 집합에서 A → B 함수의 개수는 |B|의 |A|승입니다. Empty → Empty도 빈 대응표 하나이므로 이 문맥에서 0⁰=1입니다. 위젯은 네 검사 집합만 표시하지만, Set의 초기·말단 객체라는 일반 주장은 “모든 입력에 줄 값”을 어떻게 정하는지에 대한 위 설명으로 증명합니다.

모든 범주에 초기·말단 객체가 있는 것은 아닙니다. 정수 전체를 ≤로 보는 부분순서 범주에는 최소 정수도 최대 정수도 없으므로 둘 다 없습니다. 최소 원소가 있는 부분순서에서는 그것이 초기 객체이고, 최대 원소가 있으면 그것이 말단 객체입니다.

3. 쌍대성과 동형

범주 C의 모든 사상을 형식적으로 뒤집고 합성도 그에 맞게 뒤집으면 반대 범주 Cᵒᵖ(opposite category)를 얻습니다. f : A → B, g : B → C가 있다면 fᵒᵖ : B → A, gᵒᵖ : C → B가 되고 (g ∘ f)ᵒᵖ = fᵒᵖ ∘ gᵒᵖ입니다. 말단 객체는 반대 범주에서는 초기 객체가 됩니다.

반대 화살표는 역함수가 아닙니다함수 Length : String → Int를 뒤집어 모든 문자열을 복원하는 함수를 만들었다는 뜻이 아닙니다. Cᵒᵖ의 사상은 원래 사상을 다른 방향으로 해석하는 형식적 구성입니다. C 안에서 실제 역함수가 존재하려면 별도로 동형 조건을 만족해야 합니다.

f : A → B가 동형사상(isomorphism)이려면 g : B → A가 존재해 g ∘ f = id_A, f ∘ g = id_B를 모두 만족해야 합니다. Set에서는 이것이 전단사 함수와 같습니다. 튜플 (A,B)의 순서를 바꾸는 Swap은 (B,A)로 가는 동형이고, 다시 바꾸면 원래 값을 얻습니다. 메모리 주소나 C# 타입 이름이 같아야 한다는 뜻은 아닙니다.

초기 객체 I와 J가 두 개 있다고 합시다. 초기성 때문에 f : I → J와 g : J → I가 각각 유일합니다. g ∘ f와 id_I는 모두 I → I 사상인데 I의 초기성상 하나밖에 없으므로 같습니다. 다른 방향도 같습니다. 따라서 I와 J는 유일한 동형까지 같습니다. 말단 객체의 경우에는 모든 화살표를 뒤집어 같은 논증을 얻습니다.

곱·쌍대곱에서는 한 가지 조건을 더 기억해야 합니다. 고정한 사영·주입을 보존하는 동형이 유일합니다. 기저 집합 사이의 모든 전단사가 하나뿐이라는 뜻이 아닙니다. 예를 들어 원소 네 개인 집합에는 여러 전단사가 있지만, 지정한 두 사영을 동시에 보존해야 하면 가능한 동형이 제한됩니다.

4. 곱: 두 결과를 유일하게 묶기

A와 B의 곱은 객체 P와 두 사영 p : P → A, q : P → B로 정의합니다. 이 모양만 만족하는 후보는 많습니다. 필요한 추가 조건은 임의의 X와 f : X → A, g : X → B에 대해 두 사영을 재현하는 m : X → P가 유일하게 있어야 한다는 것입니다.

모든 X, f : X → A, g : X → B에 대해
유일한 m : X → P가 존재하며
p ∘ m = f, q ∘ m = g

Set에서는 P=A×B를 순서쌍들의 집합으로 두고 p(a,b)=a, q(a,b)=b로 둡니다. m(x)=(f(x),g(x))로 정의하면 두 식을 만족합니다. 다른 n도 두 식을 만족한다면 n(x)의 첫 성분은 f(x), 둘째 성분은 g(x)여야 하므로 n(x)=m(x)입니다. 모든 x에서 같아 m의 유일성이 증명됩니다.

실험 2 · 매개사상 0개·1개·여러 개 비교하기

A=B={0,1}입니다. X의 각 입력에 f(x),g(x)를 지정하고 후보 P에 보낼 값을 직접 고르세요. extraBit의 추가 비트는 두 사영에서 무시합니다.

순서쌍이 부족한 후보는 특정 목표 쌍을 만들 수 없어 매개사상 존재에 실패합니다. 반대로 (A×B)×Bool처럼 무시되는 비트를 덧붙이면 각 x마다 그 비트를 두 가지로 고를 수 있습니다. 고정한 f,g에 대해 가능한 전체 매개함수는 2의 |X|승 개입니다. |X|=1이면 2개, |X|=2이면 4개이므로 유일성에 실패합니다.

이것은 단순히 후보의 원소 수를 비교하는 문제가 아닙니다. 사영이 어떤 값을 잊는지가 핵심입니다. 다른 범주에서도 위 가환도와 존재·유일성으로 곱을 정의하며, 모든 범주에 모든 곱이 존재하는 것은 아닙니다. 또한 Set에서 한 성분이 비어 있으면 곱 자체가 비어 있을 수 있으므로 모든 사영이 무조건 전사라고 말할 수는 없습니다.

두 곱 (P,p,q), (Q,r,s)가 있다면 보편성으로 사영을 보존하는 u:P→Q, v:Q→P가 유일하게 생깁니다. v∘u와 id_P가 같은 사영을 주므로 유일성에 의해 같고, 다른 방향도 같습니다. 이것이 사영을 보존하는 유일한 동형이라는 말의 뜻입니다.

5. 쌍대곱: 출처를 보존하고 분기하기

곱의 모든 화살표를 뒤집으면 쌍대곱(coproduct)을 얻습니다. 객체 S와 i : A → S, j : B → S라는 두 주입을 두고, 어떤 f : A → X, g : B → X에 대해서도 m : S → X가 유일하게 존재해 m ∘ i=f, m ∘ j=g를 만족해야 합니다.

모든 X, f : A → X, g : B → X에 대해
유일한 m : S → X가 존재하며
m ∘ i = f, m ∘ j = g

Set에서는 출처 태그를 붙인 서로소 합집합(disjoint union)으로 구현합니다. i(a)=Left(a), j(b)=Right(b)입니다. A와 B에 같은 값 0이 있어도 Left(0)과 Right(0)은 다릅니다. 보통의 합집합으로 겹친 값을 합치면 f(0)과 g(0)가 다를 때 하나의 출력으로 둘을 재현할 수 없습니다.

유일한 m은 태그에 따라 분기하는 경우 분석 함수입니다. m(Left(a))=f(a), m(Right(b))=g(b)로 정의하면 두 식이 성립합니다. 쌍대곱의 모든 값이 이 두 형태 중 하나이므로 다른 결과를 자유롭게 정할 자리가 없고 m이 유일합니다. C#에서는 아래 Either의 Match가 이 제거 연산을 표현합니다.

실험 3 · 같은 값도 태그에 따라 다른 경로로

A=B={0,1}이고 f,g의 결과는 작은 정수입니다. 출처·값·각 처리 결과를 직접 바꾸고, 주입 → 태그 확인 → 처리 함수 호출을 재생하세요.

여기서 “주입”은 일반 범주의 보편적 구성에 붙이는 이름입니다. Set의 표준 태그 주입은 실제로 단사 함수이지만, 임의의 범주에서 쌍대곱 주입이 항상 모노사상이라고 추가로 가정하지는 않습니다. 정의에 필요한 것은 두 화살표와 유일한 매개사상의 조건입니다.

6. 곱과 쌍대곱이 다른 이유

정의는 화살표를 뒤집어 얻지만 Set 안의 구현은 다르게 생깁니다. 곱은 A의 값과 B의 값을 둘 다 담고, 쌍대곱은 A의 값 또는 B의 값 중 하나와 출처 태그를 담습니다. 유한 집합에서 |A×B|=|A|·|B|, |A+B|=|A|+|B|입니다. 크기가 2와 3이면 곱은 6개, 쌍대곱은 5개입니다.

함수는 모든 정의역 입력에 결과를 지정해야 하지만 공역을 모두 채울 의무는 없습니다. 또한 여러 입력을 하나의 결과로 합칠 수 있습니다. 예를 들어 A → Unit은 모든 정보를 버리는 반면 Unit → A는 A의 원소 하나를 고르는 함수입니다. 공역이 Empty이면 비어 있지 않은 정의역에서 오는 전함수가 없지만, Empty에서 나가는 함수는 언제나 하나입니다. 이러한 방향의 차이가 초기·말단, 곱·쌍대곱의 구현 차이로 드러납니다.

Unit → A×B는 순서쌍 하나를 고르는 일이라서 두 성분을 함께 선택합니다. 반대로 A+B → Unit은 어느 분기인지까지 버리는 유일한 함수입니다. 같은 “화살표 반전”이라는 형식적 원리를 사용해도 원래 범주의 각 구성이 서로 같은 객체가 되거나 모든 함수에 역함수가 생기지는 않습니다.

7. 전체 C# 구현

C# 12 / .NET 8 BCL만 사용하는 전체 Program.cs입니다. Fanout은 두 함수를 유일한 튜플 함수로 묶고, Cases는 두 처리 함수를 태그에 따라 하나의 함수로 묶습니다. Either는 private 기본 생성자의 abstract class와 중첩 sealed 파생 클래스로 구성해 외부에서 다른 분기 클래스를 임의로 추가하지 못하게 합니다.

using System;

readonly record struct Unit;

abstract class Either<A, B>
{
    private Either() { }
    public abstract R Match<R>(Func<A, R> left, Func<B, R> right);

    public sealed class Left : Either<A, B>
    {
        readonly A value;
        public Left(A value) { this.value = value; }
        public override R Match<R>(Func<A, R> left, Func<B, R> right)
            => left(value);
    }
    public sealed class Right : Either<A, B>
    {
        readonly B value;
        public Right(B value) { this.value = value; }
        public override R Match<R>(Func<A, R> left, Func<B, R> right)
            => right(value);
    }
}

internal static class Program
{
    static Func<X, (A, B)> Fanout<X, A, B>(Func<X, A> f, Func<X, B> g)
        => x => (f(x), g(x));
    static A First<A, B>((A, B) pair) => pair.Item1;
    static B Second<A, B>((A, B) pair) => pair.Item2;
    static (B, A) Swap<A, B>((A, B) pair) => (pair.Item2, pair.Item1);
    static Func<Either<A, B>, C> Cases<A, B, C>(Func<A, C> f, Func<B, C> g)
        => value => value.Match(f, g);

    static void Main()
    {
        Func<int, int> f = x => x + 1;
        Func<int, bool> g = x => x % 2 == 0;
        // 이 예제의 입력 범위에서 고정 폭 정수 오버플로는 없다.
        var pair = Fanout(f, g)(3);
        Console.WriteLine($"product(3) = ({pair.Item1},{pair.Item2})");
        Console.WriteLine($"projection A = {First(pair)}");
        Console.WriteLine($"projection B = {Second(pair)}");
        Console.WriteLine($"swap twice = {Swap(Swap(pair)) == pair}");

        var dispatch = Cases<int, int, string>(n => $"L:{n}", n => $"R:{n}");
        Either<int, int> left = new Either<int, int>.Left(0);
        Either<int, int> right = new Either<int, int>.Right(0);
        Console.WriteLine($"left(0) = {dispatch(left)}");
        Console.WriteLine($"right(0) = {dispatch(right)}");

        Func<int, Unit> discard = _ => new Unit();
        Console.WriteLine($"unit equal = {discard(3) == discard(99)}");
    }
}

product(3) = (4,False)
projection A = 4
projection B = False
swap twice = True
left(0) = L:0
right(0) = R:0
unit equal = True

이 예제에서는 null이 아닌 Either 객체와 정상 처리 함수를 입력으로 사용합니다. C# 참조에는 null이 들어갈 수 있으므로 타입 선언 자체가 모든 런타임 값에 대한 Set의 보편적 성질을 증명한 것은 아닙니다. Match는 유효한 Left/Right 값에서 해당 처리 함수 하나만 호출합니다. Swap의 동형도 값 대응에 관한 주장이지 실행 비용이나 객체 배치가 같다는 주장은 아닙니다.

8. 확인 문제

말단 객체 T의 정의로 맞는 것은?
방향과 유일성이 모두 필요합니다. Set에서는 원소 하나인 집합이 말단 객체입니다.
곱 후보 P=(A×B)×Bool의 사영이 마지막 Bool을 무시한다. 고정한 f,g와 |X|=2에서 가능한 매개함수 수는?
각 입력마다 두 선택이 있으므로 2²=4개입니다. 존재는 하지만 유일성이 실패합니다.
곱과 쌍대곱의 매개사상 방향은?
곱은 들어오는 두 결과를 묶고, 쌍대곱은 두 출처의 처리 함수를 하나의 경우 분석으로 묶습니다.
A=B={0,1}의 쌍대곱에서 Left(0)과 Right(0)은?
f(0)과 g(0)가 다를 수 있으므로 출처를 보존해야 합니다. 보통의 합집합은 이 차이를 잊습니다.
두 곱이 “유일한 동형까지 같다”는 뜻은?
보편적 구성의 구조를 함께 보존해야 합니다. 사영을 무시한 다른 전단사는 있을 수 있습니다.

9. 직접 구현하는 실습

실습 A · 사영이 잊은 비트와 유일성

A=B={0,1}, X={x₀,x₁}이고 f(x₀)=0, g(x₀)=1, f(x₁)=1, g(x₁)=0입니다. 후보 P=(A×B)×Bool에서 두 사영이 비트를 무시할 때, 두 식을 만족하는 매개함수의 전체 목록을 작성하세요.

기대 결과: m(x₀)=(0,1,u), m(x₁)=(1,0,v)이고 (u,v)는 (false,false), (false,true), (true,false), (true,true)의 네 경우입니다. 값이 충분하다는 사실과 유일성은 다른 조건임을 설명하세요.

힌트

함수 하나는 두 입력의 출력을 모두 지정한 대응표입니다. 따라서 각 입력의 비트를 하나씩 고르는 이중 반복문을 사용합니다.

해답 · Main에 추가할 C# 조각
bool[] bits = [false, true];
int mediators = 0;
foreach (bool u in bits)
foreach (bool v in bits)
{
    (int A, int B, bool Extra) first = (0, 1, u);
    (int A, int B, bool Extra) second = (1, 0, v);
    if (first.A != 0 || first.B != 1 || second.A != 1 || second.B != 0)
        throw new Exception("projection equation");
    mediators++;
}
Console.WriteLine($"mediators = {mediators}"); // 4

X가 하나의 원소만 가지면 2개, n개면 2ⁿ개의 매개함수가 생깁니다. n=0에서는 1개지만, 보편적 성질은 그 경우 하나만 요구하는 것이 아니라 모든 X와 모든 두 함수에 대해 유일성을 요구합니다.

실습 B · 부분순서에서 곱과 쌍대곱 찾기

집합 {1,2,3,6}에 나눗셈 관계 a≤b ⇔ a가 b를 나눔을 둡니다. 2와 3의 곱은 두 객체의 최대 하계(meet)이고 쌍대곱은 최소 상계(join)임을 보편적 성질로 설명한 뒤 계산하세요. 그다음 6을 집합에서 빼면 무엇이 달라지는지 확인하세요.

기대 결과: {1,2,3,6}에서는 meet(2,3)=1, join(2,3)=6. {1,2,3}에서는 meet=1이지만 join은 없습니다. 숫자의 min(2,3), max(2,3)를 그대로 답으로 쓰면 틀립니다. 비교 관계가 보통의 정수 ≤가 아니기 때문입니다.

힌트

곱의 사영 P→A, P→B는 P가 둘 다를 나눈다는 뜻입니다. 다른 하계 X에서 P로 사상이 있어야 하므로 모든 하계 X가 P를 나누어야 합니다. 쌍대곱은 이 방향을 뒤집습니다.

해답 · Main에 추가할 C# 조각
// 파일 맨 위에 using System.Linq; 추가
static bool Divides(int x, int y) => y % x == 0;
foreach (int[] elements in new[] { new[] { 1, 2, 3, 6 }, new[] { 1, 2, 3 } })
{
    var lower = elements.Where(d => Divides(d, 2) && Divides(d, 3)).ToArray();
    var upper = elements.Where(d => Divides(2, d) && Divides(3, d)).ToArray();
    var meets = lower.Where(d => lower.All(x => Divides(x, d))).ToArray();
    var joins = upper.Where(d => upper.All(x => Divides(d, x))).ToArray();
    Console.WriteLine($"meet = {(meets.Length == 1 ? meets[0].ToString() : "none")}");
    Console.WriteLine($"join = {(joins.Length == 1 ? joins[0].ToString() : "none")}");
}
// meet = 1, join = 6, meet = 1, join = none (각 줄)

부분순서에서는 각 객체 쌍의 사상이 최대 하나이므로 보편성의 유일성은 자동입니다. 남는 핵심은 해당 하계·상계와 모든 후보를 잇는 사상이 실제로 존재하는지입니다.

핵심 요약

  • 초기 I는 I→X, 말단 T는 X→T 사상이 모든 X에 대해 정확히 하나입니다.
  • 반대 범주는 화살표와 합성을 형식적으로 뒤집습니다. 원래 함수의 역함수를 만드는 일이 아닙니다.
  • 곱은 두 사영을 재현하는 X→P 매개사상이 유일한 구조입니다.
  • 쌍대곱은 두 주입의 처리를 재현하는 S→X 매개사상이 유일한 구조입니다.
  • Set의 곱은 순서쌍, 쌍대곱은 출처 태그를 가진 서로소 합집합입니다.
  • 곱·쌍대곱의 유일한 동형은 지정한 사영·주입을 보존해야 합니다.
  • 부분순서의 곱은 meet, 쌍대곱은 join이며 존재하지 않을 수도 있습니다.
