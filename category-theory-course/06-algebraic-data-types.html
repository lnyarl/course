1. 자료형을 조합하는 두 연산

좌표에는 x와 y가 모두 필요하고, 연락처에는 이메일 또는 전화번호 중 한 형태가 필요합니다. 앞은 곱 타입, 뒤는 합 타입입니다. 둘을 구분하면 데이터를 처리할 때 함께 읽어야 할 필드와 분기해야 할 경우가 명확해집니다. 원문은 일상적인 자료구조 상당수를 이 두 조합으로 만들 수 있다는 데서 출발합니다.

곱 A×B의 값은 (a,b)이며 각 성분을 독립적으로 고릅니다. 합 A+B의 값은 Left(a) 또는 Right(b)입니다. 두 집합에 같은 값이 있어도 출처 태그는 남습니다. 곱과 합을 혼동하면 “두 값이 동시에 필요하다”와 “둘 중 하나만 있다”라는 서로 다른 계약이 같은 구조로 섞입니다.

2. 튜플의 괄호와 레코드의 이름

((a,b),c)와 (a,(b,c))는 다른 메모리 표현이나 C# 타입일 수 있지만 괄호를 옮기는 서로 역인 변환이 있습니다. 이를 타입의 결합법칙이라고 부를 때의 등호는 동형을 뜻합니다. 값 자체를 빠뜨리거나 순서를 임의로 바꾸는 법칙이 아닙니다.

레코드는 곱의 각 좌표에 이름을 붙입니다. 이름은 코드의 의미와 읽기 쉬움을 바꾸지만 모든 필드의 값을 함께 갖는다는 구조는 같습니다. record라는 C# 키워드가 자동으로 순수성·깊은 불변성·보편적 성질을 증명하지는 않습니다. 필드가 가변 참조라면 공유 상태도 검토해야 합니다.

3. 0과 1에 해당하는 타입

Empty는 값이 0개, Unit은 값이 1개입니다. A×Unit≅A는 유일한 Unit 성분을 버리고 다시 붙이는 동형으로 설명합니다. A+Empty≅A에서는 Empty 분기의 실제 값이 없으므로 A 분기만 남습니다. A×Empty는 쌍의 두 번째 값을 만들 수 없어 비어 있습니다.

A×1 ≅ A, A+0 ≅ A, A×0 ≅ 0
|A×B|=|A|·|B|, |A+B|=|A|+|B|

여기서 Empty는 수학적 모델입니다. C#의 빈 enum은 캐스팅과 기본값이 있어 빈 타입이 아니며 void도 제네릭으로 사용하는 Unit과 다릅니다. 유한 개수 계산은 작은 모델을 이해하는 도구이지 무한 타입의 런타임 메모리 크기를 재는 계산이 아닙니다.

실험 1 · 유한 타입의 값 펼치기

곱은 두 축의 격자로, 합은 출처 태그가 다른 두 영역으로 값 공간을 비교합니다.

4. 분배법칙을 변환으로 증명하기

A×(B+C)의 값에는 공통 A와 B 또는 C 값이 있습니다. 태그가 Left면 (A,B)를 왼쪽 분기로, Right면 (A,C)를 오른쪽 분기로 보냅니다. 역변환은 각 분기의 A를 바깥으로 꺼냅니다. 양방향 변환을 합성하면 원래 값과 태그를 그대로 얻습니다.

A×(B+C) ≅ (A×B)+(A×C)

단순히 양쪽의 원소 수가 같은 것보다 실제 대응과 역변환을 제시하는 것이 더 강한 설명입니다. Bool×(Bool+Unit)은 2×(2+1)=6개입니다. 각 입력 형태를 나누어 왕복이 항등임을 보일 수 있고, 다음 프로그램은 이 유한 예를 모두 검사합니다.

실험 2 · 분배 변환 왕복

B는 Bool, C는 Unit입니다. C 분기에서는 payload를 사용하지 않습니다.

5. 합 타입으로 상태를 제한하기

열림·닫힘 상태를 두 bool로 저장하면 false,false와 true,true도 표현됩니다. 요구가 정확히 둘 중 하나라면 네 경우 중 둘은 불필요합니다. Open 또는 Closed라는 합을 사용하면 생성 규칙에서 그 차이를 드러낼 수 있습니다.

필드가 없는 분기는 Unit에 대응하고 Maybe(A)는 1+A입니다. Nothing은 “값이 아직 생성되지 않은 실패한 객체”가 아니라 하나의 유효한 분기 값입니다. nullable 참조와 수학의 합은 구분해야 합니다. C#에서 null이 스며들 수 있는 경계는 생성자·주석·검증의 실제 계약으로 다룹니다.

실험 3 · 상태 모델 검사

두 플래그 중 정확히 하나만 true라는 계약을 검사합니다.

6. 대수적 법칙과 실제 설계의 경계

곱과 합은 각각 Unit과 Empty를 단위원으로 가지며, 교환·결합은 명시적인 동형으로 표현됩니다. 전체 모양은 반환형을 설계하거나 가능한 상태 수를 세는 데 유용합니다. 하지만 타입이 동형이어도 직렬화 포맷, 호환성, 성능, 필드 이름의 업무 의미는 같지 않을 수 있습니다.

원문의 도형 예처럼 공통 인터페이스 아래 원·사각형을 두는 방식도 태그에 따른 분기를 구현할 수 있습니다. 단, 확장 가능한 상속 계층을 닫힌 합이라고 부르려면 실제 생성 가능한 파생형을 제한해야 합니다. 아래 Either는 외부 파생형을 제한하는 작은 구현을 사용합니다.

7. 검사에서 일반 논증으로

유한 Bool 예제는 가능한 입력을 모두 나열할 수 있습니다. 일반 A,B,C에 대한 분배 동형은 각 Left·Right 형태에서 두 변환을 실제로 전개해 증명합니다. 임의의 함수 샘플 몇 개가 맞았다고 모든 타입에 대한 법칙을 증명했다고 말하지 않습니다.

이 장의 동형들은 이후 함자 구현의 재료입니다. 자료형이 곱과 합으로 만들어졌다는 구조를 알면 안의 함수를 어느 분기에, 어느 좌표에 적용해야 하는지도 재귀적으로 정할 수 있습니다.

전체 C# 프로그램

C# 12 / .NET 8, 외부 패키지 없는 전체 Program.cs입니다. examples/Ch06에서 dotnet run으로 실행합니다. 이 예제는 명시한 순수 값 모델을 구현합니다. C# 전체의 종료·순수성을 타입이 증명한다는 뜻은 아닙니다.

abstract class Either<A, B>
{
    private Either()
    {
    }

    public abstract R Match<R>(Func<A, R> l, Func<B, R> r);
    public sealed class Left(A value) : Either<A, B>
    {
        public override R Match<R>(Func<A, R> l, Func<B, R> r) => l(value);
    }

    public sealed class Right(B value) : Either<A, B>
    {
        public override R Match<R>(Func<A, R> l, Func<B, R> r) => r(value);
    }
}

readonly record struct Unit;
internal static class Program
{
    static Either<(A, B), (A, C)> Spread<A, B, C>((A, Either<B, C>) x) => x.Item2.Match<Either<(A, B), (A, C)>>(b => new Either<(A, B), (A, C)>.Left((x.Item1, b)), c => new Either<(A, B), (A, C)>.Right((x.Item1, c)));
    static (A, Either<B, C>) Collect<A, B, C>(Either<(A, B), (A, C)> x) => x.Match<(A, Either<B, C>)>(p => (p.Item1, new Either<B, C>.Left(p.Item2)), p => (p.Item1, new Either<B, C>.Right(p.Item2)));
    static string Signature((bool, Either<bool, Unit>) p) => p.Item1 + ":" + p.Item2.Match(b => "L" + b, _ => "R");
    static void Main()
    {
        var values = new List<(bool, Either<bool, Unit>)>();
        foreach (bool a in new[]
        {
            false,
            true
        }

        )
        {
            foreach (bool b in new[]
            {
                false,
                true
            }

            )
                values.Add((a, new Either<bool, Unit>.Left(b)));
            values.Add((a, new Either<bool, Unit>.Right(new Unit())));
        }

        Console.WriteLine($"states = {values.Count}");
        Console.WriteLine($"roundtrip = {values.All(x => Signature(Collect(Spread(x))) == Signature(x))}");
    }
}

기대 출력:

states = 6
roundtrip = True

핵심 요약

  • 곱은 두 성분 모두, 합은 태그가 있는 한 분기를 담습니다.
  • 타입 대수의 등호는 실제 왕복 변환으로 보이는 동형입니다.
  • 분배법칙과 0·1 법칙은 가능한 상태를 설계하는 도구입니다.

확인 문제

A×Empty의 값은 몇 개인가?
Empty 성분을 만들 수 없어 쌍도 만들 수 없습니다.
Maybe(A)의 대수적 구조는?
Nothing 하나와 A 값을 담은 분기입니다.
분배법칙의 근거는?
태그와 A 값을 보존하는 두 변환을 구성합니다.
record 키워드만으로 보장되지 않는 것은?
가변 참조 필드와 부작용은 별도 문제입니다.

직접 구현하는 실습

실습 1 · Unit 곱의 왕복

Bool×Unit에서 Unit을 버리고 다시 붙이는 동형을 전수 검사하세요.

기대 결과: bool roundtrip = True / pair roundtrip = True

힌트

Unit에는 고를 다른 값이 없습니다.

해답 · 독립 실행 Program.cs
readonly record struct Unit;
internal static class Program
{
    static bool ToBool((bool, Unit) pair) => pair.Item1;
    static (bool, Unit) FromBool(bool value) => (value, new Unit());
    static void Main()
    {
        bool[] bits = [false, true ];
        var pairs = bits.Select(FromBool).ToArray();
        Console.WriteLine($"bool roundtrip = {bits.All(x => ToBool(FromBool(x)) == x)}");
        Console.WriteLine($"pair roundtrip = {pairs.All(x => FromBool(ToBool(x)) == x)}");
    }
}

메모리 동일성이 아니라 값 대응을 검사합니다.

실습 2 · 두 플래그의 불필요한 상태

두 bool의 네 조합 중 정확히 하나만 true인 경우를 세세요.

기대 결과: all = 4, valid = 2

힌트

두 플래그가 다를 때만 유효합니다.

해답 · 독립 실행 Program.cs
int all = 0, valid = 0;
foreach (bool a in new[]
{
    false,
    true
}

)
    foreach (bool b in new[]
    {
        false,
        true
    }

    )
    {
        all++;
