1. 무엇을 만족할지와 어떻게 계산할지

h=g∘f는 결과 관계를 선언합니다. 임시 변수 y에 f(x)를 저장하고 g(y)를 호출하는 코드는 실행 절차를 드러냅니다. 둘이 같은 순수 함수를 나타낼 수 있지만, 문제를 분해하고 변경하는 사고 방식은 다릅니다. 선언적 표현이라고 실행 단계가 없어지는 것은 아닙니다.

원문은 범주론이 전역적인 관계와 보편적 명세로 사고하도록 돕는다고 설명합니다. 이는 모든 선언적 문장을 자동으로 효율적인 프로그램으로 바꿀 수 있다는 정리는 아닙니다. 실제 알고리즘·자료구조·비용 모델을 고르는 일은 여전히 남습니다.

2. 합성 법칙으로 구현을 바꾸기

순수한 리스트 Map에서 Map(g)∘Map(f)=Map(g∘f)입니다. 중간 리스트를 만드는 두 단계와 원소별로 두 함수를 연결하는 한 단계를 바꿀 수 있습니다. 이 실험은 앞 장의 법칙을 선언적 프로그램 구성에 적용하는 추가 사례입니다.

결과값이 같아도 실행 횟수·할당·예외 시점까지 같다는 뜻은 아닙니다. 특히 C# LINQ는 지연 순회이고 ToArray는 실행을 강제합니다. 원래 함수에 로그 같은 관찰 가능한 효과가 있으면 순회 묶음의 변화가 로그 순서를 바꿀 수 있어 순수 함수 법칙만으로 변환을 정당화하지 못합니다.

3. 지역적 갱신과 전역적 조건

원문은 물리학의 비유를 사용합니다. 위치와 속도를 작은 시간 간격마다 갱신하는 관점은 지역적인 계산입니다. 반대로 시작·끝 조건과 경로 전체의 성질로 경로를 선택하는 관점은 전역적입니다. 이는 범주의 공리를 물리 법칙으로 바꾸는 설명이 아니라 명세 방식의 비유입니다.

두 매질을 지나는 빛의 단순 모형에서는 경계 통과점에 따라 전체 이동 시간이 달라집니다. 페르마 원리의 해당 최소시간 사례를 유한 격자로 근사하면 전역 목적을 만족하는 후보를 비교할 수 있습니다. 일반적인 작용 원리는 항상 최솟값이라는 뜻이 아니라 정지 조건이라는 점도 구분해야 합니다.

4. 실행 비용은 모델을 정해야 말할 수 있다

범주론의 사상에는 기본적으로 거리나 물리 시간이 들어 있지 않습니다. 여러 단계의 합성을 한 사상으로 볼 수 있지만, 그것이 CPU 명령 하나나 일정한 응답 시간을 뜻하지는 않습니다. 동일한 표시적 의미를 가진 구현들이 서로 다른 실행 비용을 가질 수 있습니다.

아래 경로 실험도 21개 통과점 중 최적 후보를 고릅니다. 연속 공간의 정확한 해를 모두 탐색했다거나 실제 렌더링·광학 시스템을 검증했다는 뜻은 아닙니다. 전역 목표와 구체적인 수치 근사 알고리즘을 분리하는 연습입니다.

5. 이벤트를 데이터 흐름으로 읽기

여러 이벤트 핸들러가 공유 상태를 직접 고치는 대신, 이벤트 열을 변환하는 관점으로 사용자 상호작용을 모델링할 수 있습니다. 원문은 FRP의 이러한 전역적 시각을 소개합니다. 미래 이벤트를 실제로 예측하거나 미리 저장한다는 뜻이 아니라, 전체 입력 스트림에 대한 변환을 개념적으로 지정한다는 뜻입니다.

인과적인 변환은 현재까지의 출력에 미래 입력을 요구하지 않습니다. 예를 들어 관찰한 이벤트의 양수 부분을 두 배 해서 누적하는 변환은 접두부만으로 계산할 수 있습니다. 무한 스트림 전체를 정렬한 뒤 첫 값을 내는 연산은 같은 방식의 실시간 인과적 변환이 아닙니다.

6. 보편적 구성은 선언적 명세다

곱은 튜플을 메모리에 배치하는 조리법 대신 사영과 유일한 인수 분해로 정의했습니다. 이 조건을 만족하면 어떤 내부 표현을 쓰든 같은 구조 보존 동형으로 연결됩니다. 이는 “어떤 관계가 성립해야 하는가”를 먼저 적는 선언적 접근입니다.

실제 언어는 튜플·합·함수를 원시 구성으로 제공할 수 있습니다. 보편적 성질은 그 구성을 구현체와 독립적으로 설명하고, 새 구현의 올바름을 논의하는 언어를 줍니다. 모든 명세가 계산 가능한 해나 자동 합성 프로그램을 갖는다고 약속하지는 않습니다.

7. 실무에서 관찰 범위를 고정하기

두 구현의 같은 점을 주장할 때 반환값, 오류, 상태 변경, 시간·메모리 가운데 무엇을 비교하는지 먼저 정합니다. 순수 변환은 작은 단위로 검사하고, I/O 경계의 순서와 정책은 별도로 검증하면 등식 추론을 적용할 범위가 선명해집니다.

아래 C# 프로그램은 작은 유한 이벤트 배열의 값 의미를 비교합니다. 실제 FRP 런타임, 스케줄러, backpressure나 무한 스트림 메모리 관리를 구현한 코드는 아닙니다. 개념 모형과 생산 시스템의 운영 특성을 혼동하지 않는 것이 이 장의 목표입니다.

전체 C# 프로그램

C# 12 / .NET 8, 외부 패키지 없는 전체 Program.cs입니다. examples/Ch11에서 dotnet run으로 실행합니다. 이 예제는 명시한 순수 값 모델을 구현합니다. C# 전체의 종료·순수성을 타입이 증명한다는 뜻은 아닙니다.

internal static class Program
{
    static void Main()
    {
        int[] events = [1, -2, 3];
        int imperative = 0;
        foreach (int x in events)
            if (x > 0)
                imperative += x * 2;
        int declarative = events.Where(x => x > 0).Select(x => x * 2).Sum();
        Console.WriteLine($"query = {declarative}");
        Console.WriteLine($"loop = {imperative}");
        int state = 0;
        var prefix = new List<int>();
        foreach (int x in events)
        {
            if (x > 0)
                state += x * 2;
            prefix.Add(state);
        }

        Console.WriteLine($"prefix states = {string.Join(",", prefix)}");
    }
}

기대 출력:

query = 8
loop = 8
prefix states = 2,2,8

핵심 요약

  • 선언적 관계와 실행 절차는 구별하되 어느 한쪽이 자동으로 빠르다고 결론 내리지 않습니다.
  • 순수 등식 재작성은 부작용의 순서까지 보존하지 않을 수 있습니다.
  • 스트림의 전역 모델과 접두부에 의존하는 인과적 실행은 함께 생각할 수 있습니다.

직접 구현하는 실습

실습 1 · 같은 값·다른 효과 순서

단계별 ToArray와 융합된 Select에서 호출 로그를 비교하세요.

기대 결과: f1,f2,g2,g3 / f1,g2,f2,g3 / values = True

힌트

로그를 남기는 함수는 의도적으로 순수하지 않습니다.

해답 · 독립 실행 Program.cs
int[] xs = [1, 2];
var log = new List<string>();
Func<int, int> f = x =>
{
    log.Add($"f{x}");
    return x + 1;
};
Func<int, int> g = x =>
{
    log.Add($"g{x}");
    return x * 2;
};
var staged = xs.Select(f).ToArray().Select(g).ToArray();
Console.WriteLine(string.Join(",", log));
log.Clear();
var fused = xs.Select(x => g(f(x))).ToArray();
Console.WriteLine(string.Join(",", log));
Console.WriteLine($"values = {staged.SequenceEqual(fused)}");

실습 2 · 접두부 인과성

미래 이벤트를 덧붙여도 이미 계산한 접두부 상태가 같은지 검사하세요.

기대 결과: prefix = 2,2 / causal sample = True

힌트

각 관측 시점의 상태를 저장합니다.

해답 · 독립 실행 Program.cs
static int[] Scan(int[] xs)
{
    int state = 0;
    return xs.Select(x =>
    {
        if (x > 0)
            state += 2 * x;
        return state;
    }).ToArray();
}

var past = Scan([1, -2]);
var future = Scan([1, -2, 3]);
Console.WriteLine($"prefix = {string.Join(",", past)}");
Console.WriteLine($"causal sample = {past.SequenceEqual(future.Take(2))}");
