1. 작은 함수에서 큰 동작으로

문자열의 길이가 짝수인지 알려 주는 기능을 생각해 봅시다. 한 함수에서 문자열을 읽고 길이를 계산하고 짝수를 판정해도 됩니다. 하지만 길이를 구하는 일과 짝수를 판정하는 일은 각각 따로 이해할 수 있습니다. 이미 두 함수가 있다면 새로 필요한 일은 앞 함수의 반환값을 뒷 함수의 인수로 전달하는 것입니다.

// 설명용 조각. 전체 실행 프로그램은 5절에 있습니다.
Func<string, int> length = text => text.Length;
Func<int, bool> isEven = n => n % 2 == 0;
Func<string, bool> evenLength = text => isEven(length(text));

Console.WriteLine(evenLength("code")); // True

evenLength를 호출하는 쪽은 두 함수의 구현을 몰라도 됩니다. string을 받아 bool을 돌려준다는 약속으로 사용할 수 있습니다. 원문의 출발점도 이 합성입니다. 큰 기능을 나누는 이유는 나중에 조각을 연결해 원하는 동작을 다시 만들 수 있기 때문입니다.

이번 장에서 말하는 객체범주론의 객체(object)는 여기서는 string, int, bool 같은 타입으로 읽습니다. new Customer()로 만든 개별 인스턴스를 뜻하지 않습니다. 이것은 범주의 한 가지 모델이며, 모든 범주의 객체가 타입인 것은 아닙니다.

먼저 익숙한 함수로 법칙을 익힌 뒤, 6절에서 함수가 아닌 화살표로도 범주를 만들 수 있는지 살펴봅니다. 낯선 용어를 외우기보다 각 화살표의 출발점과 도착점을 적는 습관부터 들이세요.

2. 객체·사상·합성의 방향

사상(morphism)은 출발 객체와 도착 객체가 정해진 화살표입니다. f : A → B라고 쓰면 A가 정의역(domain), B가 공역(codomain)입니다. 이 장의 함수 모델에서는 A의 값을 받아 B의 값을 만드는 함수로 읽습니다. 공역은 실제로 나온 결과들의 집합인 치역과 다릅니다.

f : A → B, g : B → C
g ∘ f : A → C
(g ∘ f)(x) = g(f(x))

g ∘ f는 f를 먼저, g를 나중에 실행합니다. 기호를 오른쪽에서 왼쪽으로 읽는 이유는 g(f(x))의 괄호 안부터 계산하기 때문입니다. 화살표를 따라갈 때는 A → B → C입니다. 두 표기는 같은 과정을 다른 방향으로 적습니다.

위 그림의 노드는 값이 아니라 타입입니다. 아래 줄의 "code", 4, True는 그 타입을 따라 이동하는 한 입력의 예입니다. 그림에는 합성에 필요한 화살표만 그렸으며, 완전한 범주에 필요한 항등사상 등은 생략했습니다.

합성하려면 접점이 맞아야 합니다. isEven(length(text))는 가능하지만 length(isEven(n))은 bool을 string으로 받으려 하므로 이 두 화살표로는 만들 수 없습니다. 이론의 객체는 정확하게 일치한다고 가정합니다. C#이 제공하는 상속·분산·암시적 변환까지 포함하려면 변환을 어떤 화살표로 모델링할지 추가로 정해야 합니다.

실험 1 · 합성 계산기

같은 정수 타입 안의 함수들을 고르세요. 먼저 예상한 뒤 g ∘ f와 f ∘ g를 비교합니다. 위젯은 표시된 작은 정수 범위에서 계산합니다.


    

    
기호와 API의 인수 순서는 별개의 선택입니다아래에서 구현할 Compose(g, f)는 수학 표기 g ∘ f에 맞춥니다. 반대로 Then(f, g)처럼 실행 순서를 먼저 적는 API도 만들 수 있습니다. 이름과 인수 순서를 정한 뒤 일관되게 사용해야 합니다.

  


  

    
3. 결합법칙: 순서를 유지하며 묶기

    
이제 함수가 세 개 있다고 합시다. f : A → B, g : B → C, h : C → D입니다. 먼저 f와 g를 하나의 함수로 만들고 h를 붙여도 되고, g와 h를 먼저 묶은 뒤 f를 붙여도 됩니다. 두 방법은 같은 입력에 같은 결과를 줘야 합니다.

    
h ∘ (g ∘ f) = (h ∘ g) ∘ f
두 쪽 모두 x ↦ h(g(f(x)))

    
이것이 결합법칙(associativity)입니다. 함수 호출을 생략한 약속이 아니라, 합성한 함수를 어떤 단위로 묶어 재사용해도 전체 의미가 유지된다는 법칙입니다. 예를 들어 “정규화 → 길이 계산”을 먼저 추출하든 “길이 계산 → 짝수 판정”을 먼저 추출하든 함수의 연결 순서가 같으면 결과도 같습니다.

    
결합법칙
h ∘ (g ∘ f)와 (h ∘ g) ∘ f의 비교입니다. f → g → h 순서는 그대로이고 괄호만 옮깁니다.
교환법칙
g ∘ f와 f ∘ g의 비교입니다. 실행 순서를 바꿉니다. 범주의 합성에는 요구하지 않으며 역순이 타입상 불가능할 수도 있습니다.

    
실험 1의 기본 함수 f(x) = x + 3, g(x) = 2x에 x = 2를 넣으면 g(f(2)) = 10, f(g(2)) = 7입니다. 결합법칙은 이 차이를 없애 주지 않습니다. “순서를 자유롭게 바꿔도 된다”로 기억하면 잘못된 리팩터링을 하게 됩니다.

    

      
실험 2 · 함수의 묶음과 호출 순서 구분하기

      
f(x) = x + 1, g(x) = 2x, h(x) = x²입니다. 묶음을 바꾸면 점선 경계가 옮겨 갑니다. f → g → h의 호출 순서와 각 중간값은 그대로인지 확인하세요.

      

        
        
      

      

    

    
왜 같은가: 입력 하나를 따라가며 증명하기

      
합성의 정의를 적용하면 [h ∘ (g ∘ f)](x) = h((g ∘ f)(x)) = h(g(f(x)))입니다. 다른 쪽은 [(h ∘ g) ∘ f](x) = (h ∘ g)(f(x)) = h(g(f(x)))입니다. 정의역 A의 모든 x에서 같으므로 두 함수는 외연적으로 같습니다.

      
위젯은 이 식을 특정 수에 적용해 보여 줍니다. 몇 개의 입력을 실행한 결과가 이 일반적인 증명을 대신하지는 않습니다.

    

  


  

    
4. 항등함수와 타입의 경계

    
각 객체 A에는 그 객체에서 출발해 같은 객체로 돌아오는 항등사상(identity morphism) id_A : A → A가 있습니다. 함수 모델에서는 입력을 그대로 돌려주는 x => x입니다. 아무 함수나 자기 자신으로 가기만 하면 항등사상인 것은 아닙니다. 예를 들어 정수에 1을 더하는 함수도 정수에서 정수로 가지만 다른 함수와 합성할 때 결과를 바꿉니다.

    
f : A → B일 때
f ∘ id_A = f
id_B ∘ f = f

    
id_A는 f 앞에서 A를 보존하고, id_B는 f 뒤에서 B를 보존합니다. length가 string → int라면 앞에는 문자열 항등함수, 뒤에는 정수 항등함수를 붙여야 합니다. 동작이 비슷하다는 이유로 타입을 바꿔 붙일 수는 없습니다.

    
    
항등함수는 비어 있는 처리 단계를 표현하는 데 쓸 수 있습니다. 선택적 정규화 기능이 꺼졌다면 normalize = Identity<string>을 선택합니다. 호출하는 쪽은 분기 없이 같은 합성 구조를 유지할 수 있습니다. 0이 덧셈의 빈 시작값인 것처럼 항등함수는 합성의 빈 시작값입니다.

    

      
실험 3 · 타입을 확인하고 항등함수 붙이기

      
위젯은 표시된 타입이 정확히 일치할 때만 합성합니다. 문자열 입력은 그대로 사용하고, Int는 −1000~1000의 정수, Bool은 true 또는 false를 입력합니다. 이는 C# 컴파일러 전체를 흉내 내는 도구가 아닙니다.

      

        
        
        
      

      

    

    
항등함수는 복사 함수가 아닙니다C#에서 참조형 값을 그대로 돌려주면 같은 참조가 돌아옵니다. 깊은 복사나 불변성 보장을 새로 만들지 않습니다. 항등함수를 통과한 뒤 원본 객체를 수정하면 그 참조를 공유하는 코드에도 영향이 있습니다.

  


  

    
5. C#으로 구현하고 결과 비교하기

    
C#의 Func<A, B>는 A를 받아 B를 반환하는 델리게이트 타입입니다. 합성은 두 함수를 받아 새 함수를 만드는 고차 함수입니다. 아래의 제네릭 인수 A, B, C는 각각 출발·중간·도착 타입이며, 중간 타입 B가 양쪽에서 공유되어 접점을 맞춥니다.

    
다음은 C# 12 / .NET 8, 외부 패키지 없는 전체 Program.cs입니다. 정수 연산은 BigInteger로 표현해 예제의 덧셈·곱셈에서 고정 폭 정수 오버플로를 피합니다. 실제 실행의 메모리 한계까지 수학적 정수로 없애는 것은 아닙니다.

    
using System;
using System.Linq;
using System.Numerics;

internal static class Program
{
    static T Identity<T>(T value) => value;

    // Compose(g, f)는 f를 먼저 실행하고 g를 실행한다.
    static Func<A, C> Compose<A, B, C>(
        Func<B, C> g, Func<A, B> f)
        => x => g(f(x));

    static bool SameOn<A, B>(
        Func<A, B> left, Func<A, B> right, A[] samples)
        => samples.All(x =>
            System.Collections.Generic.EqualityComparer<B>
                .Default.Equals(left(x), right(x)));

    static void Main()
    {
        Func<string, int> length = text => text.Length;
        Func<int, bool> isEven = n => n % 2 == 0;
        var evenLength = Compose<string, int, bool>(isEven, length);
        Console.WriteLine($"evenLength(code) = {evenLength("code")}");

        Func<BigInteger, BigInteger> f = x => x + 1;
        Func<BigInteger, BigInteger> g = x => x * 2;
        Func<BigInteger, BigInteger> h = x => x * x;
        var left = Compose(h, Compose(g, f));
        var right = Compose(Compose(h, g), f);
        BigInteger[] samples = [-2, -1, 0, 1, 2];
        Console.WriteLine($"left(2) = {left(2)}");
        Console.WriteLine($"right(2) = {right(2)}");
        Console.WriteLine($"associative on samples = {SameOn(left, right, samples)}");

        Func<string, string> idString = Identity<string>;
        Func<int, int> idInt = Identity<int>;
        string[] words = ["", "a", "code"];
        var before = Compose<string, string, int>(length, idString);
        var after = Compose<string, int, int>(idInt, length);
        Console.WriteLine($"identity before = {SameOn(before, length, words)}");
        Console.WriteLine($"identity after = {SameOn(after, length, words)}");

        Func<bool, bool> not = value => !value;
        Func<bool, bool> idBool = Identity<bool>;
        var twice = Compose<bool, bool, bool>(not, not);
        Console.WriteLine($"not twice = {SameOn(twice, idBool, [false, true])}");
    }
}

    
코스의 examples/Ch01/Program.cs에서 같은 프로그램을 확인할 수 있습니다. 해당 폴더에서 dotnet run으로 실행합니다. 출력은 다음과 같습니다.

    
evenLength(code) = True
left(2) = 36
right(2) = 36
associative on samples = True
identity before = True
identity after = True
not twice = True

    
같다는 것은 어떤 뜻인가

    
위 법칙의 등호는 외연적 동등성(extensional equality)입니다. 정의역의 모든 입력에 대해 결과가 같다는 뜻입니다. C# 델리게이트의 ==는 메서드와 대상 객체로 이루어진 호출 목록을 비교합니다. 모든 인수를 넣어 함수를 비교하는 연산이 아닙니다. 따라서 Compose(id, f) == f를 검사하는 코드는 항등법칙을 올바르게 검사하지 못합니다.

    
SameOn은 주어진 입력들의 반환값을 비교할 뿐입니다. 일반적인 문자열·정수 함수에서 샘플 5개가 같다고 모든 입력에서 같다고 결론 내릴 수는 없습니다. 반면 순수 전함수 bool → bool의 정의역은 false, true뿐이므로 두 값을 빠짐없이 확인하면 그 모델에서는 전수 검사입니다. 결과 타입 B의 비교 방법도 중요합니다. 위 프로그램의 int, bool, BigInteger는 값 비교가 적합하지만, 임의의 참조형까지 원하는 의미로 비교해 주는 보편적인 함수는 아닙니다.

    
모든 C# 함수가 이 모델에 들어가지는 않습니다이 장에서는 명시한 정의역의 모든 입력에서 끝나고 결과를 내는 순수 전함수를 사용합니다. length의 정의역은 null을 제외한 문자열입니다. Func<string, int>만으로 null 불가·종료·순수성을 컴파일러가 증명하지는 않습니다. 예외, 무한 반복, 시간 읽기, 외부 상태 변경은 추가 모델링이 필요합니다. 리소스 고갈과 실행 비용도 여기서 비교하는 값의 의미에는 포함하지 않습니다.

    
부작용이 있다고 함수 합성의 괄호를 바꾸는 것만으로 반드시 호출 순서가 바뀌는 것은 아닙니다. 이 장에서 순수성을 요구하는 이유는 “함수는 입력과 출력으로 설명된다”는 모델과 등호를 명확히 쓰기 위해서입니다. 부작용을 다루는 구조는 원문 4장과 뒤의 모나드 장에서 이어집니다.

  


  

    
6. 그래프는 언제 범주가 되는가

    
지금까지 배운 내용을 함수 예제에서 떼어 내면 범주의 정의가 됩니다. 범주에는 객체와 사상이 있고, 각 사상의 출발·도착 객체가 정해집니다. 도착과 출발이 맞는 두 사상에는 합성이 정의되며, 각 객체에는 항등사상이 있습니다. 합성은 결합법칙과 양쪽 항등법칙을 만족해야 합니다.

    
따라서 A → B, B → C를 그렸다는 사실만으로 범주가 되지는 않습니다. 합성 A → C가 필요하고, A·B·C 각각의 항등사상도 필요합니다. 한 쌍의 객체 사이에 여러 화살표가 있다면 어느 것이 어떤 합성의 결과인지도 정해야 합니다. 필요한 화살표가 있다는 사실만으로 결합법칙이 자동으로 정해지지는 않습니다.

    
구조있는 것추가로 확인할 것

      
유향 그래프노드와 화살표합성과 항등사상을 갖추었는지 보장하지 않음

      
범주객체, 사상, 합성, 항등사상합성의 결합법칙과 양쪽 항등법칙

      
자유 범주의 구성 예고그래프의 노드는 객체, 유한 경로는 사상합성은 경로 연결, 항등은 길이 0 경로. 3장에서 자세히 다룸

    

    
웹 페이지를 객체, 직접 걸린 하이퍼링크를 사상이라고 해도 바로 범주는 아닙니다. A에서 B로 링크가 있고 B에서 C로 링크가 있다고 A에서 C로 직접 가는 링크가 반드시 있지는 않기 때문입니다. 대신 “유한한 링크 경로”를 사상으로 삼으면 경로를 이어 붙이는 합성을 생각할 수 있습니다. 무엇을 사상으로 정하느냐가 결론을 바꿉니다.

    

      
실험 4 · 제한된 관계 모델에서 범주 조건 확인하기

      
A, B, C 사이에 화살표가 최대 하나인 경우만 다룹니다. 행은 출발, 열은 도착입니다. 이 모델은 반사성과 추이성을 만족하면 얇은 범주가 됩니다. 일반적인 다중 화살표 범주 검사기는 아닙니다.

      
출발 ↓ / 도착 →ABC

        
A

        
B

        
C

      

      

      

    

    
이 제한된 모델에서는 왜 법칙이 자동으로 성립할까

      
각 객체 쌍의 사상이 최대 하나라면, A → B와 B → C가 있을 때 A → C의 유일한 사상을 합성 결과로 정할 수 있습니다. 존재는 추이성으로 보장합니다. 세 화살표를 어떻게 묶어도 같은 시작과 끝을 가지며, 그 사이의 사상은 최대 하나이므로 결합법칙이 성립합니다. 자기 자신으로 가는 사상을 반사성으로 마련하면 같은 유일성 때문에 항등법칙도 성립합니다.

      
그래프의 서로 다른 경로들을 별개 사상으로 보존하는 자유 범주와는 다릅니다. 이 위젯의 “폐포”는 도달 가능 여부만 남기므로 여러 경로를 하나의 관계로 합칩니다.

    

  


  

    
7. 확인 문제

    
f : A → B, g : B → C일 때 g ∘ f의 뜻은?
(g ∘ f)(x) = g(f(x))입니다. 중간 타입 B가 접점이 됩니다.

    
결합법칙이 허용하는 변경은?
결합법칙은 괄호의 위치에 관한 법칙입니다. 교환법칙을 요구하지 않습니다.

    
length : String → Int에 맞는 항등법칙은?
입력 쪽에는 String → String, 출력 쪽에는 Int → Int가 필요합니다.

    
정수 함수 두 개가 샘플 5개에서 같은 값을 반환했다. 확실히 말할 수 있는 것은?
외연적 동등성은 전체 정의역에 대한 주장입니다. 델리게이트의 호출 목록 비교와도 다릅니다.

    
A → B, B → C라는 직접 링크만 있는 그래프가 바로 범주가 아닌 이유는?
A → C 합성과 각 객체의 항등사상이 필요합니다. 일반적인 경우에는 합성 연산과 법칙까지 정해야 합니다.

  


  

    
8. 직접 구현하는 실습

    
실습 A · 합성 순서를 드러내는 API 만들기

      
5절의 Compose를 참고해 Then<A,B,C>(Func<A,B> f, Func<B,C> g)를 구현하세요. 입력 순서는 실행 순서입니다. f(x) = x + 3, g(x) = 2x를 BigInteger로 정의하고 Then(f,g)(2)와 Then(g,f)(2)를 출력하세요.

      
기대 결과: 첫째 줄 10, 둘째 줄 7. 두 출력이 다르면서도 Then(Then(f,g),h)와 Then(f,Then(g,h))는 같은 호출 순서가 되는 이유를 설명하세요.

      
힌트
반환할 함수는 x 하나를 받습니다. f의 반환값을 g에 넣으세요. 함수 자체를 만들 때 f나 g를 미리 호출할 필요는 없습니다.

      
해답 · Program 클래스에 추가할 조각
static Func<A, C> Then<A, B, C>(
    Func<A, B> f, Func<B, C> g)
    => x => g(f(x));

// Main 안에서 실행
Func<BigInteger, BigInteger> add3 = x => x + 3;
Func<BigInteger, BigInteger> doubleIt = x => x * 2;
Console.WriteLine(Then(add3, doubleIt)(2)); // 10
Console.WriteLine(Then(doubleIt, add3)(2)); // 7
f·g·h를 세 번 실행하는 순서는 양쪽 모두 f → g → h입니다. 두 함수를 먼저 묶어 만든다는 것과 입력값을 먼저 계산한다는 것은 구분해야 합니다.

    

    
실습 B · Bool → Bool 함수를 전수 검사하기

      
순수 전함수 Bool → Bool은 네 가지입니다. 항상 false, 항상 true, 입력 그대로, 부정입니다. 각 함수에 대해 앞·뒤에 항등함수를 붙인 결과가 원래 함수와 같은지 false와 true 모두에서 확인하세요. 네 함수에서 세 함수를 고르는 모든 경우에 결합법칙도 검사하세요.

      
기대 결과: 항등법칙 검사 16개, 결합법칙 검사 128개가 모두 통과합니다. 16은 함수 4개 × 입력 2개 × 항등함수 위치 2곳, 128은 함수 선택 4³가지 × 입력 2개입니다.

      
힌트
함수는 배열에 담고 입력은 new[] { false, true }로 순회하세요. 결합법칙에서는 g와 f를 바꾸지 말고 Compose의 중첩만 바꾸세요. 기존 Main의 끝에 아래 조각을 넣을 수 있습니다.

      
해답 · Main에 추가할 조각
Func<bool, bool>[] functions =
[
    _ => false, _ => true, Identity<bool>, x => !x
];
Func<bool, bool> identity = Identity<bool>;
int identityChecks = 0, associationChecks = 0;
foreach (var fn in functions)
foreach (var value in new[] { false, true })
{
    if (Compose<bool, bool, bool>(fn, identity)(value) != fn(value))
        throw new Exception("identity before");
    if (Compose<bool, bool, bool>(identity, fn)(value) != fn(value))
        throw new Exception("identity after");
    identityChecks += 2;
}
foreach (var first in functions)
foreach (var second in functions)
foreach (var third in functions)
foreach (var value in new[] { false, true })
{
    var lhs = Compose(third, Compose(second, first));
    var rhs = Compose(Compose(third, second), first);
    if (lhs(value) != rhs(value)) throw new Exception("associativity");
    associationChecks++;
}
Console.WriteLine($"identity checks = {identityChecks}"); // 16
Console.WriteLine($"associativity checks = {associationChecks}"); // 128
이 경우는 Bool → Bool의 가능한 모든 순수 전함수와 입력을 열거했으므로 이 유한 모델에 대한 전수 검사입니다. 모든 C# 타입에 대한 결합법칙의 증명은 3절의 식 전개가 담당합니다.
