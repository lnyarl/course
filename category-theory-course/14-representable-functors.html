1. Hom은 집합값 함자다

국소적으로 작은 범주 C에서 Hom(R,A)는 R에서 A로 가는 사상들의 집합입니다. R을 고정하고 A를 바꾸면 Set으로 가는 함자를 얻습니다. f:A→B는 h:R→A를 f∘h:R→B로 보내므로 이 작용은 후합성입니다.

목표를 고정한 Hom(−,R)는 반대로 입력 사상을 앞에 붙이는 반변 함자입니다. 두 자리를 함께 바꾸면 Hom:Cᵒᵖ×C→Set 프로함자입니다. 원소가 함수인 집합과 함수들을 담은 내부 지수 객체는 앞 장의 조건 아래 연결되지만 일반 범주에서 무조건 같은 객체라고 놓지는 않습니다.

2. 표현 가능 함자의 정의

F:C→Set가 어떤 객체 R에 대해 Hom(R,−)와 자연동형이면 표현 가능(representable)하다고 합니다. 모든 A에 α_A:Hom(R,A)→F(A)와 β_A:F(A)→Hom(R,A)가 있고 두 합성이 항등이며, 이 대응은 A의 사상 작용과 자연적으로 호환되어야 합니다.

F(A) ≅ Hom(R,A)
α_A∘β_A=id_F(A), β_A∘α_A=id_Hom(R,A)
F(f)∘α_A=α_B∘Hom(R,f)

객체마다 원소 수가 우연히 같은 것만으로 충분하지 않습니다. 같은 R이 모든 A에 작동하고, 왕복과 자연성을 함께 만족해야 합니다. 임의의 자연변환 Hom(R,−)⇒F가 있다는 것과 그 변환이 가역이라는 것도 다른 조건입니다. 이 차이는 요네다 보조정리에서 중요해집니다.

3. Pair의 표현 객체는 Bool

Pair<A>=(A,A)는 Bool→A 함수와 같은 정보입니다. false에 대응하는 첫 값, true에 대응하는 둘째 값을 저장하면 됩니다. Tabulate(f)=(f(false),f(true)), Index(pair)(key)는 key에 맞는 좌표를 선택합니다.

Index(Tabulate(f))(key)=f(key)는 두 Bool 경우에서 바로 성립합니다. Tabulate(Index(pair))도 원래 두 좌표를 복원합니다. 이 사례는 단순한 한쪽 역변환이 아니라 두 방향이 모두 항등인 자연동형입니다.

4. 사상 작용과 왕복의 호환

Pair의 각 좌표에 g:A→B를 적용한 결과는 키 함수 f 뒤에 g를 합성한 뒤 Tabulate한 결과와 같습니다. 따라서 두 값의 테이블이라는 표현과 함수라는 표현 사이에서 Map을 옮겨도 결과가 유지됩니다.

Reader<R,A>=R→A는 Hom(R,−) 그 자체이므로 표현 가능합니다. 표현 객체는 R입니다. C#에서 Pair나 Reader의 구체 구현은 가능하지만 임의의 고차 타입 F 전체를 보통 제네릭 인수 하나로 표현하는 문법은 제공하지 않습니다. 아래 코드는 Pair에 대해 실제 실행 가능한 구현을 제시합니다.

5. Maybe와 List가 표현 가능하지 않은 이유

Set에서 임의의 R에 대해 Hom(R,Unit)는 하나입니다. 모든 R 값을 유일한 Unit 값으로 보내야 하기 때문이며 R이 비어 있어도 빈 함수 하나입니다. 하지만 Maybe(Unit)는 None과 Some(Unit)의 두 값이 있습니다. 따라서 어떤 R도 모든 A에 대한 자연동형을 만들 수 없습니다.

유한 리스트 List(Unit)는 길이마다 다른 리스트가 있어 무한히 많습니다. Hom(R,Unit)는 여전히 하나이므로 List도 표현 가능하지 않습니다. 빈 리스트에서 A값을 꺼낼 수 없다는 직관과 연결되지만, Unit에서의 개수 반례는 임의의 표현 객체 R을 한 번에 배제합니다.

실험 3 · 개수로 표현 후보 반박

Unit을 검사하면 Maybe·List의 어떤 표현 객체도 배제됩니다. 다른 검사 집합에서 우연히 맞는 것과 구별하세요.

6. Stream과 자연수 키

빈 경우가 없는 무한 스트림 A는 자연수 인덱스 n↦a_n와 대응합니다. 표현 객체는 음이 아닌 자연수입니다. Haskell의 지연 평가에서는 Tabulate가 무한 스트림을 개념적으로 만들고 필요한 접두부만 평가할 수 있습니다.

C#에서는 비음수 인덱스 함수나 지연 노드·메모이제이션을 사용해 필요한 값만 계산하는 구체 표현을 만들 수 있습니다. 유한 배열 접두부만 저장했다고 완전한 무한 스트림을 모두 구축한 것은 아닙니다. 음수 키·예외·리소스 고갈은 구현의 실제 경계로 검증해야 합니다.

7. 표현과 성능은 다른 축

같은 값을 같은 키로 찾는 함수 표현과 데이터 표현이 자연동형이어도 평가 시점·할당·캐시·메모리 비용은 다를 수 있습니다. 표현 가능성은 실제 벤치마크 속도를 약속하지 않지만 구현을 바꿔 볼 구조적인 근거를 줍니다.

곱으로 만든 고정 좌표 구조는 키의 합으로 표현할 수 있습니다. 예를 들어 A×A는 Bool 키이며 고정 길이 n의 벡터는 유한 인덱스 n개입니다. 반변 표현 가능성은 Hom(−,R)를 사용해 쌍대적으로 정의합니다. 임의 길이 합 구조인 Maybe·List의 위 반례와 구분하세요.

전체 C# 프로그램

C# 12 / .NET 8, 외부 패키지 없는 전체 Program.cs입니다. examples/Ch14에서 dotnet run으로 실행합니다. 이 예제는 명시한 순수 값 모델을 구현합니다. C# 전체의 종료·순수성을 타입이 증명한다는 뜻은 아닙니다.

readonly record struct Pair<T>(T First, T Second);
internal static class Program
{
    static Pair<A> Tabulate<A>(Func<bool, A> f) => new(f(false), f(true));
    static A Index<A>(Pair<A> p, bool key) => key ? p.Second : p.First;
    static Pair<B> Map<A, B>(Pair<A> p, Func<A, B> f) => new(f(p.First), f(p.Second));
    static void Main()
    {
        Func<bool, int> f = b => b ? 7 : 3;
        var table = Tabulate(f);
        Console.WriteLine($"pair = ({table.First},{table.Second})");
        Console.WriteLine($"index/tabulate = {new[] { false, true }.All(k => Index(Tabulate(f), k) == f(k))}");
        Func<bool, int> indexed = k => Index(table, k);
        Console.WriteLine($"tabulate/index = {Tabulate(indexed) == table}");
        Func<int, int> g = x => x * 2;
        Console.WriteLine($"natural = {Map(table, g) == Tabulate<int>(k => g(f(k)))}");
    }
}

기대 출력:

pair = (3,7)
index/tabulate = True
tabulate/index = True
natural = True

핵심 요약

  • 표현 가능성은 F와 고정 R의 Hom(R,−) 사이 자연동형입니다.
  • Tabulate와 Index는 두 방향의 항등과 자연성을 만족해야 합니다.
  • Pair·Reader·Stream은 키 함수로 표현되지만 Maybe·List는 Unit 반례로 배제됩니다.

직접 구현하는 실습

실습 1 · Unit에서의 반례

R의 크기를 바꾸며 Hom(R,Unit)와 Maybe(Unit)의 개수를 비교하고 일반 이유를 설명하세요.

기대 결과: Hom counts = 1,1,1,1 / Maybe(Unit) = 2

힌트

1의 어떤 비음수 거듭제곱도 1입니다. 일반 논증은 유일한 Unit 값으로 보냅니다.

해답 · 독립 실행 Program.cs
using System.Numerics;

Console.WriteLine($"Hom counts = {string.Join(",", Enumerable.Range(0, 4).Select(n => BigInteger.Pow(1, n)))}");
Console.WriteLine("Maybe(Unit) = 2");

계산은 유한한 예이고 임의 R에 대한 이유는 유일한 Unit 반환값입니다.

실습 2 · 자연수 키의 지연 메모이제이션

비음수 인덱스 제곱값을 요청 순서 2,3,2로 캐시하세요. 계산 횟수는 진단용 계측임을 밝히세요.

기대 결과: values = 4,9,4 / computations = 2

힌트

존재하는 키는 재사용하고 없는 키만 계산합니다.

해답 · 독립 실행 Program.cs
using System.Numerics;

var cache = new Dictionary<int, BigInteger>();
int computations = 0;
BigInteger At(int n)
{
    if (n < 0)
        throw new ArgumentOutOfRangeException(nameof(n));
    if (cache.TryGetValue(n, out var value))
        return value;
    computations++;
    value = new BigInteger(n) * n;
    cache.Add(n, value);
    return value;
}

int[] requests = [2, 3, 2];
var values = requests.Select(At).ToArray();
Console.WriteLine($"values = {string.Join(",", values)}");
Console.WriteLine($"computations = {computations}");

필요한 키만 평가하며 전체 무한 스트림을 메모리에 구축하지 않습니다. 캐시는 요청에 따라 성장합니다.
