모나드와 효과

읽기 전용 설정, 누적 로그, 변경되는 상태는 서로 다른 데이터 흐름입니다. 효과를 함수의 인자와 반환값에 드러내면 전역 상태 없이 합성 규칙을 정할 수 있습니다.

1. 문제에서 출발하기

요청을 처리하면서 설정을 읽고, 로그를 남기고, 사용한 번호를 증가시키려 합니다. 전역 변수에 모두 넣으면 재현 가능한 테스트가 어려워집니다. 세 종류의 정보를 명시적인 함수 인자와 결과로 바꾸면 같은 초기 조건에서 같은 결과를 계산할 수 있습니다.

읽기만 하는 환경은 Reader, 쓰기만 누적하는 로그는 Writer, 읽고 갱신하는 상태는 State로 표현합니다. 모두 모나드라고 해서 계산 흐름이 같은 것은 아닙니다. 무엇을 공유하고 무엇을 이어 붙이며 무엇을 교체하는지 구체적으로 정해야 합니다.

2. 정의와 타입

고정한 환경 E에 대해 Reader<E,A>=E→A입니다. pure(a)(e)=a이고 bind(r,f)(e)=f(r(e))(e)입니다. 두 계산이 같은 e를 읽습니다. 고정한 모노이드 (W,⋅,ε)에 대해 Writer<W,A>=(A,W), pure(a)=(a,ε), bind((a,w),f)에서 f(a)=(b,w′)이면 결과는 (b,w⋅w′)입니다.

State<S,A>=S→(A,S)입니다. pure(a)(s)=(a,s). bind(m,f)(s)는 (a,s′)=m(s)를 먼저 구한 뒤 f(a)(s′)를 반환합니다. 두 번째 계산이 원래 s를 쓰면 상태 연결이 끊어집니다. 값 A와 상태 S는 타입 역할이 다릅니다.

Reader: e → a → b (같은 환경 공유)
Writer: (a,w) → (b,w⋅w′) (로그 누적)
State: s → (a,s′) → (b,s″) (새 상태 전달)

3. 계산에서 일반 논증으로

Reader 결합 법칙은 같은 e에서 두 경로 모두 g(f(r(e))(e))(e)가 되는 것으로 확인합니다. Writer 결합성은 로그 모노이드의 (w₁⋅w₂)⋅w₃=w₁⋅(w₂⋅w₃)에서 옵니다. 로그가 문자열이면 순서를 바꿔도 된다는 뜻이 아닙니다.

State에서 fresh(s)=(s,s+1)이라 합시다. fresh를 두 번 연결하고 두 번호의 합을 값으로 반환하면 초기 s=10에서 첫 값 10, 다음 상태 11, 둘째 값 11, 최종 상태 12이므로 (21,12)가 됩니다. 항상 전역 counter를 실제 변경하는 것이 아니라 상태를 인자에서 반환값으로 전달하는 순수 계산입니다.

원문은 Option의 실패, List의 비결정성, Either의 오류, continuation과 I/O도 함께 논의합니다. List 비결정성은 난수 선택이 아니라 가능한 결과들을 열거하는 모델입니다. continuation (A→R)→R은 이후 계산을 명시하지만 그 자체가 실제 비동기 실행의 시간·취소 정책을 정하지는 않습니다.

4. 직접 조작하는 세 실험

1. 번호 발급 State 추적

fresh(s)=(s,s+1)을 두 번 실행합니다. 올바른 상태 전달과 원래 상태를 재사용하는 오류를 비교합니다.

2. Writer 로그의 순서

첫 계산은 +n, 둘째는 두 배를 합니다. 로그 문자열을 정순 또는 역순으로 연결합니다. 값은 같아도 로그 의미는 다릅니다.

3. Reader 환경 공유

read(e)=e+n, next(a)(e)=a×e입니다. 환경 e를 양쪽 계산이 공유합니다.

5. 실행 가능한 C#

아래는 C# 12 / .NET 8 전체 프로그램입니다. BCL만 사용하며 examples/Ch21에서 실행할 수 있습니다. JavaScript 실험은 이 계산을 시각화한 별도 모형입니다.

Func<int, int> reader = env => (env + 3) * env;
Console.WriteLine($"reader={reader(2)}");
var writer = (Value: (2 + 3) * 2, Log: "add;" + "double;");
Console.WriteLine($"writer={writer.Value}:{writer.Log}");
Func<int, (int Value, int State)> fresh = s => (s, s + 1);
var program = Bind(fresh, a => Bind(fresh, b => Pure(a + b)));
var result = program(10);
Console.WriteLine($"state={result.Value},{result.State}");
static Func<int, (A Value, int State)> Pure<A>(A a) => s => (a, s);
static Func<int, (B Value, int State)> Bind<A,B>(
    Func<int, (A Value, int State)> m,
    Func<A, Func<int, (B Value, int State)>> f)
    => s =>
    {
        var (a, next) = m(s);
        return f(a)(next);
    };

기대 표준 출력:

reader=10
writer=10:add;double;
state=21,12

6. 모형의 경계

State 모형은 공유 메모리 동시 접근이나 트랜잭션을 자동으로 해결하지 않습니다. 여러 스레드가 같은 상태를 실제 변경하는 문제는 이 순수 함수 모형 밖입니다. Reader도 가변 객체 E를 읽으면 참조가 같아도 내용이 바뀔 수 있으므로 불변 환경과 순수 함수를 전제합니다.

Writer의 W는 모노이드여야 합니다. float 덧셈처럼 반올림 때문에 결합법칙이 깨지는 연산을 로그 결합으로 고르면 수학적 법칙을 그대로 주장할 수 없습니다. 예제는 작은 정수와 문자열 연결을 사용합니다. 세 효과를 섞는 순서와 오류 발생 때 로그를 남기는 정책도 추가 설계가 필요합니다.

실제 파일·콘솔·네트워크 I/O는 외부 세계와 상호작용합니다. 효과를 데이터나 함수로 표현하는 것과 실행하는 것을 구분하세요. 순수한 기술만으로 실제 동작의 타이밍, 실패, 재시도 정책이 사라지지 않습니다.

아래 도식은 Writer 로그의 결합성만 확대합니다. W는 로그 모노이드이고 μ:W×W→W는 로그 연결입니다. Reader의 환경 공유와는 별개 법칙입니다.

7. 확인 문제

Reader bind의 두 계산이 사용하는 환경은?
환경을 읽기 전용으로 공유합니다.
Writer가 필요로 하는 로그 구조는?
항등과 결합적 로그 연산이 법칙을 지탱합니다.
State의 두 번째 계산에 넘길 상태는?
이 상태 연결이 State의 핵심입니다.
State 모나드가 자동으로 제공하는 것은?
공유 메모리나 외부 시스템의 동시성 보장은 별도로 필요합니다.

8. 구현 실습

실습 A · get과 put

초기 상태 5를 읽어 +4로 갱신하고 이전 값과 현재 상태를 출력하세요.

기대 출력:

old=5, state=9
힌트

get(s)=(s,s), put(v)(s)=(Unit,v)로 생각합니다.

해답 · 별도 Program.cs 전체
static (int Value, int State) Get(int s) => (s, s);
static (bool Unit, int State) Put(int value, int _) => (false, value);
var (old, state) = Get(5);
var (_, updated) = Put(old + 4, state);
Console.WriteLine($"old={old}, state={updated}");

bool false 하나만 사용하는 Unit 모형입니다. 입력 상태를 제자리 변경하지 않고 새 상태를 반환했습니다.

실습 B · Writer 괄호 바꾸기

세 로그 a;,b;,c;를 두 괄호 순서로 합치고 값 일치를 확인하세요. 이어 순서 교환의 반례도 확인하세요.

기대 출력:

a;b;c;
a;b;c;
False
힌트

문자열 +는 결합적이지만 일반적으로 교환적이지 않습니다.

해답 · 별도 Program.cs 전체
string a = "a;", b = "b;", c = "c;";
Console.WriteLine((a + b) + c);
Console.WriteLine(a + (b + c));
Console.WriteLine(a + b == b + a);

모나드 결합성은 괄호 이동을 허용하고 효과의 순서를 바꾸지는 않습니다.

9. 핵심 정리

  • Reader는 환경 공유, Writer는 모노이드 로그 누적, State는 최신 상태 전달입니다.
  • 효과를 인자·반환값으로 표현하면 순수 함수로 합성할 수 있습니다.
  • 각 효과의 법칙은 구체적인 데이터 흐름에서 확인해야 합니다.
  • 순수 효과 모형과 외부 세계에서의 실행·동시성 보장은 별개입니다.
