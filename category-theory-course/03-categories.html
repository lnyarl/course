크고 작은 범주

타입과 함수만이 범주의 재료는 아닙니다. 그래프의 경로, “이하” 관계, 문자열 연결을 서로 다른 범주로 만들며 객체와 사상을 무엇으로 정하는지 연습합니다.

1. 객체가 없거나 항등사상만 있다면

범주에는 객체와 사상이 필요하다고 배웠습니다. 그렇다면 객체가 하나도 없으면 어떨까요? 빈 범주(empty category)는 객체도 사상도 0개입니다. “각 객체에 항등사상이 있다”는 조건은 반례가 되는 객체가 없으므로 성립합니다. 합성할 사상도 없어서 합성법칙을 어기는 경우가 없습니다.

2장에서 본 빈 타입과는 다른 층위입니다. 빈 타입을 하나의 객체로 둔 범주라면 객체는 이미 하나 있습니다. 그 객체에는 적어도 항등사상이 있어야 하므로 빈 범주가 아닙니다. “객체 안에 값이 없다”와 “범주 안에 객체가 없다”를 구분해야 합니다.

객체 A, B, C는 있지만 각각의 항등사상만 두는 구성도 가능합니다. 이를 이산 범주(discrete category)라고 합니다. 서로 다른 객체 사이의 사상이 없으므로 그 객체들을 연결할 수 없습니다. 이산 범주의 객체가 n개라면 사상도 n개이며, n=0이면 빈 범주가 됩니다.

2. 그래프의 모든 경로: 자유 범주

이제 A → B 화살표 a와 B → C 화살표 b가 있는 그래프를 생각합니다. 범주를 만들려면 합성 b ∘ a가 필요합니다. 그래프의 변을 출발 재료로 삼고 유한한 경로 하나하나를 사상으로 정하면 이 문제를 해결할 수 있습니다. 객체는 그래프의 노드이고, 합성은 경로를 이어 붙이는 것이며, 각 노드의 길이 0 경로가 항등사상입니다.

a : A → B, b : B → C
b ∘ a = 경로 [a, b] : A → C
id_A = A에서 시작해 아무 변도 지나지 않는 길이 0 경로

이렇게 만든 범주를 주어진 그래프가 생성하는 자유 범주(free category)라고 합니다. “자유”는 필요한 법칙 외에 경로들을 추가로 같다고 만들지 않는다는 뜻입니다. A → C 직접 변 c가 이미 있어도 [c]와 [a,b]는 서로 다른 사상입니다. 시작과 끝이 같다는 이유로 둘을 합치면 자유 범주가 아니라 다른 구조를 만들게 됩니다.

경로 연결은 순서대로 변을 나열하는 연산입니다. 세 경로를 어떻게 묶어 연결해도 전체 변의 시퀀스는 같습니다. 빈 경로를 앞이나 뒤에 연결해도 변의 시퀀스는 바뀌지 않습니다. 따라서 결합법칙과 항등법칙이 성립합니다. C#에서 경로를 List로 표현할 때도 빈 경로의 출발 노드는 저장해야 합니다. id_A와 id_B는 변 목록이 둘 다 비어 있지만 다른 사상입니다.

실험 1 · 경로를 보존하며 범주 만들기

변을 켜거나 끄고, 표시할 최대 길이를 정하세요. c와 a·b는 끝점이 같아도 다른 경로입니다. 재생기는 선택한 경로를 한 변씩 따라갑니다.

최대 길이는 표시 한도입니다위젯과 C# 예제는 길이 한도 안의 경로만 열거합니다. 전체 자유 범주에서 더 긴 경로를 금지한 것이 아닙니다. B의 고리 l을 켜면 id_B, l, ll, lll, …이 모두 다른 사상이므로 사상이 무한히 많습니다. 길이를 4에서 잘라 놓은 목록은 일반적으로 합성에 닫혀 있지 않아 그 자체를 완전한 범주라고 부르면 안 됩니다.

3. 관계로 만드는 얇은 범주

이번에는 경로를 기억하지 않고 “A ≤ B가 성립하는가”만 기억해 봅시다. 객체를 관계의 원소로 두고 A ≤ B일 때만 A → B 사상 하나를 둡니다. 반사성 A ≤ A는 항등사상을 제공하고, 추이성 A ≤ B, B ≤ C ⇒ A ≤ C는 합성 결과의 존재를 보장합니다. 같은 출발·도착 사이의 사상이 최대 하나이므로 합성의 결합법칙과 항등법칙도 자동으로 정해집니다.

반사성과 추이성을 만족하는 관계가 준순서(preorder)입니다. 이 용어는 비교 가능성을 모두 요구하는 선형순서(total order)와 다릅니다. 준순서의 범주에서는 Hom(A,B)가 빈 집합이거나 한 원소 집합입니다. 얇은 범주(thin category)라는 이름은 이 “객체 쌍마다 사상이 최대 하나”라는 성질을 가리킵니다.

관계요구 조건범주에서 읽기
준순서 preorder반사성 + 추이성얇은 범주. 다른 객체끼리 양방향 사상이 있어도 된다.
부분순서 poset위 조건 + 반대칭성A ≤ B와 B ≤ A이면 A = B. 다른 객체의 양방향 연결은 없다.
선형순서 total order부분순서 + 모든 쌍 비교 가능A ≤ B 또는 B ≤ A가 모든 쌍에서 성립한다.

부분순서에서는 모든 원소 쌍이 비교 가능할 필요가 없습니다. 예를 들어 집합 포함 관계에서 {1}과 {2}는 어느 쪽도 다른 쪽의 부분집합이 아닙니다. 작업의 선행 의존성도 부분순서로 볼 수 있습니다. 선형순서는 이런 비교 불가능한 쌍이 없는 더 강한 조건입니다.

실험 2 · 준순서와 부분순서의 차이 찾기

행이 출발, 열이 도착입니다. 체크 하나가 해당 Hom 집합에 사상이 하나 있음을 뜻합니다. 서로 다른 경로를 따로 저장하는 실험 1과 구별하세요.

출발 ↓ / 도착 →ABC
A
B
C

A와 B가 서로 다른 객체인데 A → B와 B → A가 모두 있어도 준순서가 될 수 있습니다. 이때 얇은 범주에서는 두 합성이 각각의 항등사상이므로 A와 B는 동형입니다. 동형이라고 같은 객체로 합쳐야 하는 것은 아닙니다. 부분순서 조건은 이러한 서로 다른 객체의 양방향 관계를 배제합니다.

경로 열거와 폐포의 차이실험 1에서 A → C의 사상 [c]와 [a,b]는 둘입니다. 이 관계 모델에서는 A에서 C로 도달 가능한지 하나만 남겨 사상을 하나로 봅니다. 반사·추이 폐포는 빠진 관계를 채우지만 어떤 경로로 도달했는지는 보존하지 않습니다. 따라서 자유 범주를 계산하는 연산과 같지 않습니다.

4. 모노이드: 연산과 항등원

모노이드(monoid)는 집합 M, 닫힌 이항 연산 ⋆ : M × M → M, 항등원 e ∈ M으로 이루어집니다. 어떤 두 원소를 연산해도 다시 M의 원소여야 하며, 다음 법칙을 만족해야 합니다.

모든 a,b,c ∈ M에서 (a ⋆ b) ⋆ c = a ⋆ (b ⋆ c)
모든 a ∈ M에서 e ⋆ a = a = a ⋆ e

수학적 자연수와 덧셈은 항등원 0을 가진 모노이드입니다. 문자열 연결은 항등원 빈 문자열을 가진 모노이드입니다. bool의 AND는 true가 항등원이고 OR는 false가 항등원입니다. 같은 집합에도 연산을 달리 고르면 서로 다른 모노이드가 생깁니다.

교환법칙 a ⋆ b = b ⋆ a는 요구하지 않습니다. 문자열에서 “ab”와 “ba”는 다르지만, (“a”+“b”)+“c”와 “a”+(“b”+“c”)는 같은 “abc”입니다. 뺄셈은 일반적으로 결합적이지 않습니다. 후보 항등원 0도 오른쪽에서는 a−0=a지만 왼쪽에서는 0−a=a가 아니므로 양쪽 항등원이 아닙니다.

실험 3 · 법칙을 계산하고 한 객체 범주로 읽기

연산·원소·항등원 후보를 바꾸세요. 도식은 객체 ⋆ 하나인 범주 후보이며 a,b,c는 고리 사상 후보입니다. 법칙을 만족할 때만 실제 범주가 됩니다. 양쪽 괄호의 계산 결과와 항등법칙을 비교합니다.

위젯에서 몇 개의 값을 확인하는 것은 법칙의 일반 증명이 아닙니다. 반례 하나는 법칙을 부정할 수 있지만, 표본에서 같다고 모든 원소에 대해 같다는 결론을 내릴 수는 없습니다. 문자열 연결의 결합법칙은 양쪽이 동일한 문자 시퀀스를 만든다는 사실로, 덧셈은 수학적 덧셈의 결합법칙으로 설명합니다. Bool AND처럼 집합이 유한하고 작은 경우에는 모든 조합을 빠짐없이 검사할 수 있습니다.

C#의 인터페이스나 연산자 시그니처는 연산과 항등원을 제공하도록 요구할 수 있지만 법칙을 자동으로 증명하지는 않습니다. 고정 폭 정수나 부동소수점의 연산을 수학적 정수 덧셈과 그대로 동일시해서도 안 됩니다. 위젯의 정수 값은 검증된 작은 범위에서 계산하며, C# 프로그램은 큰 정수 예시에 BigInteger를 사용합니다.

5. 모노이드: 객체 하나와 많은 사상

모노이드의 원소를 각각 사상으로 바꾸고, 모든 사상의 출발과 도착을 같은 객체 ⋆로 정해 봅시다. 그러면 객체는 하나이고 사상은 M의 원소만큼 있습니다. 합성을 모노이드 연산으로 정의하고 항등사상을 e로 두면 모노이드 법칙이 그대로 범주 법칙이 됩니다.

객체: ⋆ 하나
Hom(⋆,⋆) = M
사상 f,g의 합성 규약: g ∘ f := g ⋆ f
id_⋆ = e

순서가 혼동되기 쉬우므로 이 장은 위 규약으로 고정합니다. 문자열 사상 s를 함수 P_s(x) = s + x, 즉 앞에 붙이는 함수로 나타내면 P_g(P_f(x)) = g + f + x입니다. 따라서 P_g ∘ P_f = P_(g+f)입니다. f=“foo”, g=“bar”라면 f 다음 g의 결과 접두사는 “barfoo”입니다.

뒤에 붙이는 함수 R_s(x)=x+s를 고르면 R_g ∘ R_f=R_(f+g)가 되어 대응 순서가 뒤집힙니다. 원문이 왼쪽 붙이기와 오른쪽 붙이기의 합성표를 거울상이라고 하는 이유입니다. 어느 구현을 선택하든 연산과 합성의 순서 규약을 함께 적어야 합니다.

반대로 한 객체 범주에서 그 객체의 자기 사상들을 모으면 모노이드가 됩니다. 그 집합이 Hom(⋆,⋆)이며 합성은 항상 가능하고 항등사상이 항등원입니다. 일반 범주에서는 사상 전체가 하나의 집합이 아닐 수도 있습니다. 각 객체 쌍 사이의 Hom이 집합인 범주를 국소적으로 작은 범주(locally small category)라고 합니다. 여기의 유한 그래프 경로·관계·문자열 예제는 이 조건 안에서 다룹니다.

6. C#으로 구성과 판정 구현하기

아래는 C# 12 / .NET 8 BCL만 사용하는 전체 Program.cs입니다. 경로마다 출발·도착·변 시퀀스를 저장하고 같은 끝점의 다른 경로를 합치지 않습니다. 예제의 변 이름은 한 글자이므로 문자열 시퀀스로 저장합니다. 임의의 다중 문자 이름이라면 구분자나 변 배열을 사용해야 합니다.

using System;
using System.Collections.Generic;
using System.Linq;
using System.Numerics;

internal static class Program
{
    readonly record struct Edge(string Name, int From, int To);
    readonly record struct Path(int From, int To, string Word, int Length);

    // 표시·검사용 유한 열거. 전체 자유 범주를 유한하다고 가정하지 않는다.
    static List<Path> PathsUpTo(int objects, Edge[] edges, int bound)
    {
        var frontier = Enumerable.Range(0, objects)
            .Select(i => new Path(i, i, "", 0)).ToList();
        var all = new List<Path>(frontier);
        for (int length = 0; length < bound; length++)
        {
            var next = new List<Path>();
            foreach (var path in frontier)
            foreach (var edge in edges)
                if (path.To == edge.From)
                    next.Add(new Path(path.From, edge.To,
                        path.Word + edge.Name, path.Length + 1));
            all.AddRange(next);
            frontier = next;
        }
        return all;
    }

    static bool Preorder(bool[,] relation)
    {
        int n = relation.GetLength(0);
        for (int a = 0; a < n; a++)
        {
            if (!relation[a, a]) return false;
            for (int b = 0; b < n; b++)
            for (int c = 0; c < n; c++)
                if (relation[a, b] && relation[b, c] && !relation[a, c])
                    return false;
        }
        return true;
    }

    static bool Poset(bool[,] relation)
    {
        if (!Preorder(relation)) return false;
        int n = relation.GetLength(0);
        for (int a = 0; a < n; a++)
        for (int b = a + 1; b < n; b++)
            if (relation[a, b] && relation[b, a]) return false;
        return true;
    }

    static void Main()
    {
        Edge[] triangle = [new("a", 0, 1), new("b", 1, 2), new("c", 0, 2)];
        var paths = PathsUpTo(3, triangle, 2);
        Console.WriteLine($"triangle paths <= 2 = {paths.Count}");
        Console.WriteLine($"A -> C = {string.Join(",", paths
            .Where(p => p.From == 0 && p.To == 2).Select(p => p.Word))}");
        var loop = PathsUpTo(1, [new Edge("l", 0, 0)], 3);
        Console.WriteLine($"loop paths <= 3 = {string.Join(",", loop
            .Select(p => p.Length == 0 ? "id_A" : p.Word))}");
        Console.WriteLine($"empty category paths = {PathsUpTo(0, [], 3).Count}");

        bool[,] cycle = { { true, true }, { true, true } };
        bool[,] chain = { { true, true }, { false, true } };
        Console.WriteLine($"cycle preorder = {Preorder(cycle)}");
        Console.WriteLine($"cycle poset = {Poset(cycle)}");
        Console.WriteLine($"chain poset = {Poset(chain)}");

        string a = "a", b = "b", c = "c", unit = "";
        Console.WriteLine($"concat associativity = {((a + b) + c == a + (b + c))}");
        Console.WriteLine($"concat identity = {(unit + a == a && a + unit == a)}");
        BigInteger large = BigInteger.Pow(2, 100);
        Console.WriteLine($"addition sample = {((large + 7) + 9 == large + (7 + 9))}");

        Func<string, string> f = x => "foo" + x;
        Func<string, string> g = x => "bar" + x;
        Console.WriteLine($"g after f (prepend) = {g(f("x"))}");
        Console.WriteLine($"g * f = {"bar" + "foo"}");
    }
}

g after f (prepend) = barfoox
g * f = barfoo

관계 판정 함수는 정사각형 행렬을 입력으로 받는다는 계약입니다. 경로 열거 함수는 유효한 객체 번호를 가진 변과 작은 음이 아닌 한도를 사용합니다. 이는 교재의 유한 열거 도구이며 그래프가 만드는 무한 범주 전체를 메모리에 구축하는 API가 아닙니다. addition sample = True 역시 선택한 큰 수의 계산 결과이지 일반적인 법칙의 증명이라고 출력하지 않습니다.

7. 확인 문제

객체가 0개인 빈 범주의 항등사상 수는?
빈 타입을 하나의 객체로 둔 범주와 빈 범주는 다릅니다. 빈 범주에는 객체도 사상도 없습니다.
A → C 직접 변 c와 A → B → C 경로 [a,b]는 자유 범주에서?
자유 범주는 경로를 보존합니다. 도달 가능 여부 하나로 합치는 것은 얇은 관계 범주를 만드는 다른 구성입니다.
반사적·추이적인 관계에서 서로 다른 A와 B가 A ≤ B, B ≤ A를 만족한다. 맞는 설명은?
부분순서에는 반대칭성이 추가로 필요합니다. 다른 객체 사이의 양방향 관계는 준순서에서 허용됩니다.
문자열 모노이드에 대응하는 한 객체 범주에서 “foo”는?
원소는 사상에 대응합니다. 객체는 하나이며, 항등사상은 빈 문자열입니다.
모노이드가 반드시 만족해야 하는 법칙의 조합은?
문자열 연결처럼 비가환인 모노이드가 있습니다. 역원도 일반 모노이드에는 요구하지 않습니다.

8. 직접 구현하는 실습

실습 A · 한 노드·한 고리의 경로를 세기

전체 프로그램의 PathsUpTo로 객체 1개, 변 l : A → A 하나인 그래프를 길이 0·1·2·3·4 한도에서 각각 열거하세요. 각 목록에 길이 0 경로를 포함하고, 결과를 노드 쌍으로 중복 제거하지 마세요.

기대 결과: 경로 개수는 1,2,3,4,5. 길이 4 목록은 id_A,l,ll,lll,llll입니다. 전체 자유 범주의 사상이 무한하다는 이유도 적으세요.

힌트

길이가 k인 경로가 l을 k번 지난 시퀀스 하나입니다. 길이 한도를 올릴 때마다 이전에 없던 사상 하나가 생깁니다.

해답 · Main에 추가할 조각
Edge[] oneLoop = [new("l", 0, 0)];
for (int bound = 0; bound <= 4; bound++)
    Console.WriteLine(PathsUpTo(1, oneLoop, bound).Count);
// 1, 2, 3, 4, 5가 한 줄씩 출력된다.

임의의 자연수 k에 대해 길이 k의 경로가 있고 서로 길이가 다르면 다른 사상입니다. 따라서 표시 한도를 늘리는 유한 실험과 별개로 전체 경로 집합은 무한합니다.

실습 B · Bool AND와 3을 법으로 하는 덧셈

Bool AND의 항등원 true와 결합법칙을 모든 입력에서 검사하세요. 이어 {0,1,2}에서 연산 a ⋆ b = (a+b) mod 3, 항등원 0을 검사하세요. 각 집합의 원소를 객체로 세지 말고, 대응하는 한 객체 범주에서 사상을 세세요.

기대 결과: AND에서 항등법칙 4회·결합법칙 8회, mod 3에서 항등법칙 6회·결합법칙 27회가 모두 통과합니다. 두 범주의 객체 수는 각각 1개, 사상 수는 각각 2개와 3개입니다.

힌트

항등법칙은 원소마다 왼쪽·오른쪽을 별도로 셉니다. 결합법칙은 가능한 삼중쌍을 모두 검사합니다. finite 집합이라서 이번에는 전수 검사입니다.

해답 · Main에 추가할 조각
bool[] booleans = [false, true];
int boolUnits = 0, boolAssociations = 0;
foreach (bool x in booleans)
{
    if ((true && x) != x || (x && true) != x)
        throw new Exception("AND identity");
    boolUnits += 2;
}
foreach (bool x in booleans)
foreach (bool y in booleans)
foreach (bool z in booleans)
{
    if (((x && y) && z) != (x && (y && z)))
        throw new Exception("AND associativity");
    boolAssociations++;
}
static int Add3(int x, int y) => (x + y) % 3;
int modUnits = 0, modAssociations = 0;
for (int x = 0; x < 3; x++)
{
    if (Add3(0, x) != x || Add3(x, 0) != x)
        throw new Exception("mod identity");
    modUnits += 2;
    for (int y = 0; y < 3; y++)
    for (int z = 0; z < 3; z++)
    {
        if (Add3(Add3(x, y), z) != Add3(x, Add3(y, z)))
            throw new Exception("mod associativity");
        modAssociations++;
    }
}
Console.WriteLine($"AND: {boolUnits}, {boolAssociations}");
Console.WriteLine($"mod3: {modUnits}, {modAssociations}");

원소는 사상에 대응하고, 사상의 합성표는 선택한 이항 연산의 표와 같습니다. 예를 들어 mod 3에서 2 ∘ 2에 대응하는 사상은 1입니다.

핵심 요약

  • 빈 범주는 객체·사상이 모두 0개이고, n개 객체의 이산 범주에는 항등사상 n개만 있습니다.
  • 자유 범주의 사상은 유한 경로입니다. 같은 끝점이라도 경로가 다르면 다른 사상입니다.
  • 고리가 있으면 경로가 무한해질 수 있습니다. 유한 표시 한도는 전체 범주가 아닙니다.
  • 준순서는 얇은 범주가 됩니다. 부분순서는 반대칭성을, 선형순서는 모든 쌍의 비교 가능성을 더 요구합니다.
  • 모노이드는 닫힌 결합 연산과 양쪽 항등원을 갖습니다. 교환법칙이나 역원은 필요하지 않습니다.
  • 모노이드의 원소는 한 객체 범주의 사상에 대응하며 객체 자체가 아닙니다.
