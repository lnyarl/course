코스 목록

C# 범주론 심화

기존 31장의 순서와 원전 대응을 유지하고, Applicative·순회·효과 조합·명령 해석·표현식 언어를 별도 응용 단원으로 연결합니다. C# 구체 타입의 계산과 일반 수학적 법칙, 브라우저 예상 결과와 실제 .NET 실행 증거를 구분합니다.

기존 코스 목차

  1. Applicative와 독립적인 효과 결합

    회원 폼의 이름과 나이를 각각 검사하려고 합니다. Map은 한 효과 안의 값 하나를 바꾸고, Bind는 앞 결과를 읽어 다음 계산을 만듭니다. 두 검사 결과를 모두 얻어 User를 만드는 중간 구조를 정의하면, 독립된 입력의 오류를 한 번에 모으는 정책을 분명하게 설명할 수 있습니다.

  2. Traversable·sequence와 구조를 보존하는 순회

    문자열 배열을 정수로 파싱하면 배열 안에 성공과 실패가 섞입니다. List<Option<int>>와 Option<List<int>>는 다른 타입입니다. 모든 항목을 성공했을 때만 완성 배열을 받거나, 모든 실패 위치를 모으는 순회를 통해 구조와 효과를 바꾸는 조건을 살펴봅니다.

  3. 오류·상태·로그 효과의 조합 순서

    카운터를 5에서 6으로 바꾼 뒤 오류가 났습니다. 호출자는 새 상태 6을 볼 수 있을까요? 두 효과를 모두 사용했다는 설명만으로는 답이 정해지지 않습니다. 오류가 상태 결과를 감싸는지, 상태가 오류 결과를 감싸는지 타입을 펼쳐 보면 정책 차이를 직접 읽을 수 있습니다.

  4. Free 구조·명령 DSL과 테스트 해석기

    카운터를 읽고 1을 더해 저장하는 기능을 테스트하려고 합니다. 기능을 만들 때 실제 파일을 읽는다면 테스트마다 파일 환경이 필요합니다. 무엇을 할지 표현한 명령 트리와 그것을 실제로 수행하는 해석기를 분리해, 같은 프로그램을 메모리·추적·실제 저장의 세 경계에서 살펴봅니다.

  5. 표현식 언어 캡스톤과 법칙 기반 최적화

    덧셈·곱셈 표현식을 계산하고 출력하는 작은 언어를 만듭니다. 같은 트리를 다른 대수로 해석하면 계산기와 pretty printer를 분리할 수 있습니다. 이어 0 곱셈 최적화를 넣어, 수학적 값이 같다는 법칙이 오류나 로그가 있는 실행에서도 그대로 성립하는지 시험합니다.
