Traversable·sequence와 구조를 보존하는 순회

선수 장 · 기존 8장 · 자료형에서 얻는 Map

문자열 배열을 정수로 파싱하면 배열 안에 성공과 실패가 섞입니다. List<Option<int>>와 Option<List<int>>는 다른 타입입니다. 모든 항목을 성공했을 때만 완성 배열을 받거나, 모든 실패 위치를 모으는 순회를 통해 구조와 효과를 바꾸는 조건을 살펴봅니다.

Map 다음에 남는 중첩의 방향

각 문자열을 ParseOption으로 바꾸면 [Some(1),None,Some(3)] 같은 배열을 얻습니다. Sequence는 List<F<A>>→F<List<A>> 방향으로 문맥을 옮기고, Traverse는 Map으로 효과를 만든 뒤 Sequence한 것입니다. Option 정책에서는 하나라도 None이면 전체가 None이고, 모두 Some이면 입력 순서대로 값을 모읍니다. 실패 원인을 전달해야 한다면 Option 대신 오류 정보를 가진 문맥을 골라야 합니다.

빈 배열의 Sequence는 None이 아니라 Pure([])입니다. 처리할 효과가 없어도 빈 구조 자체는 성공적으로 만들 수 있기 때문입니다. [Some(1),Some(2),Some(3)]을 [3,2,1]로 뒤집는 구현은 단순히 모두 성공했다는 조건을 넘어서 원래 순서 의미를 바꿉니다. 어떤 자료구조의 어떤 순회를 정의하는지부터 고정해야 합니다.

효과 정책과 순회 법칙을 함께 검사하기

같은 입력 ["1","x","y"]에 fail-fast Result를 쓰면 첫 실패만 보일 수 있고, 오류 누적 Validation을 쓰면 index 1·2의 두 오류를 얻습니다. 자료형을 방문하는 규칙과 효과를 결합하는 규칙을 분리하면 파서와 오류 정책을 재사용할 수 있습니다. 오류 메시지에 위치를 붙여 중복 문자열의 실패도 구분하세요.

Identity 효과로 Traverse하면 일반 Map과 같은 구조가 나와야 하고, 효과를 두 겹 결합한 순회와 단계적으로 순회한 결과의 호환도 확인해야 합니다. 유한 배열에서는 빈 배열·한 원소·중복·실패 위치를 전수 검사할 수 있습니다. 무한 스트림의 종료·엄격한 C# 평가·I/O 자원 정리는 이 유한 구조의 법칙만으로 해결되지 않습니다.

실습과 예상 관찰

[Some(1),None,Some(3)]과 빈 배열의 결과를 먼저 예측하세요. 아래 조건을 선택한 다음 입력 순서와 출력 타입을 적습니다. C# 연습에서는 배열 전용 SequenceOption을 만들고 빈 배열·모두 성공·가운데 실패·끝 실패의 네 경우를 검사한 뒤, Validation으로 바꿔 오류 위치가 보존되는지 비교하세요.

모두 Some인 배열

결과는 Some([1,2,3])입니다. 배열 순서·원소 수·중복을 보존합니다.

가운데 항목이 None

결과는 None입니다. [1,3]만 반환하는 것은 실패 항목을 필터링한 다른 계약입니다.

빈 배열

결과는 Some([])입니다. 빈 입력은 성공한 빈 구조이며 실패 상태와 구별해야 합니다.

Validation으로 x·y 두 실패 누적

Invalid([index1,index2])를 얻습니다. 순회가 방문 위치를 보존하고 효과 정책이 두 오류를 결합합니다.
