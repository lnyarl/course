1. 문제에서 출발하기

리팩터링 전후 API가 같은지 확인할 때 데이터 타입 이름만 같아서는 부족합니다. 입력을 먼저 바꾸고 변환하는 경로와 변환한 뒤 출력을 바꾸는 경로가 같은지를 확인해야 합니다. 범주론의 가환도는 이런 요구를 정확한 등식으로 기록합니다.

원문 17장은 새 구조를 대량으로 도입하기보다 앞의 언어를 사상 중심으로 다시 연결합니다. 객체를 지우자는 뜻이 아닙니다. 객체는 어떤 합성이 정의되는지 알려 주는 경계로 계속 필요합니다.

2. 정의와 타입

f:A→B, g:B→C가 있을 때 g∘f:A→C가 정의됩니다. 함자 F:C→D는 F(g∘f)=F(g)∘F(f), F(id_A)=id_F(A)를 만족합니다. 사상을 어디로 보내는지 정해도 출발·도착 객체가 일관되어야 합니다.

α:F⇒G는 각 A에 대해 α_A:F(A)→G(A)를 주며 G(f)∘α_A=α_B∘F(f)입니다. 모든 성분 α_A가 동형이면 α는 자연동형입니다. 역 성분 α_A⁻¹을 모은 가족도 자연성 식 양쪽을 역 성분으로 합성해 자연변환이 됨을 보일 수 있습니다.

G(f) ∘ α_A = α_B ∘ F(f)
α_B⁻¹ ∘ G(f) = F(f) ∘ α_A⁻¹

3. 계산에서 일반 논증으로

자연성 등식에서 왼쪽에 α_B⁻¹, 오른쪽에 α_A⁻¹을 합성합니다. α_B⁻¹∘G(f)∘α_A∘α_A⁻¹=α_B⁻¹∘α_B∘F(f)∘α_A⁻¹가 되어 역 성분의 자연성 식을 얻습니다. 임의의 성분이 전단사라는 사실과 자연성 원래 조건을 모두 사용했습니다.

Hom 집합 자체의 동형은 Set에서 전단사 함수입니다. A≅B라는 객체 동형과 Hom(A,B)≅Hom(B,A)라는 집합 동형은 같은 주장이 아닙니다. Set에서 |A|=2, |B|=3이면 |Hom(A,B)|=3²=9이지만 반대 방향은 2³=8입니다. 원소별로 다르게 결과를 고를 수 있기 때문에 방향이 비대칭입니다.

함자 List에서 리스트 원소마다 f 후 g를 적용하면 합성 함수를 한 번 적용한 결과와 같습니다. 리스트 길이를 얻는 자연변환 List⇒Const(N)은 map으로 원소를 바꿔도 길이가 유지되어 자연성을 만족합니다. 반면 첫 원소만 보는 함수는 빈 리스트에서 값을 만들 수 없어 List⇒Identity의 전함수 자연변환이 되지 못합니다.

4. 직접 조작하는 세 실험

1. 함자 합성 경로

리스트 [n,n+1]에 f(x)=x+1, g를 적용합니다. map 두 번과 합성 한 번을 비교합니다.

2. 길이 자연변환

길이 n인 리스트의 원소를 바꾸어도 length가 유지됩니다. Const(N)의 사상 작용은 항등입니다.

3. Hom의 비대칭

A와 B의 유한 집합 크기를 바꾸며 양 방향 전함수 수를 비교합니다.

5. 실행 가능한 C#

아래는 C# 12 / .NET 8 전체 프로그램입니다. BCL만 사용하며 examples/Ch17에서 실행할 수 있습니다. JavaScript 실험은 이 계산을 시각화한 별도 모형입니다.

int[] xs = [2, 3];
Func<int,int> f = x => x + 1, g = x => 2 * x;
var path1 = xs.Select(f).Select(g).ToArray();
var path2 = xs.Select(x => g(f(x))).ToArray();
Console.WriteLine(string.Join(",", path1));
Console.WriteLine(path1.SequenceEqual(path2));
Console.WriteLine(xs.Length == xs.Select(_ => "changed").Count());
Console.WriteLine($"Hom(2,3)={Pow(3,2)}, Hom(3,2)={Pow(2,3)}");
static int Pow(int b, int e) => Enumerable.Repeat(b, e).Aggregate(1, (x,y) => x*y);

기대 표준 출력:

6,8
True
True
Hom(2,3)=9, Hom(3,2)=8

6. 모형의 경계

그림의 화살표가 실제로 타입이 맞는 합성을 나타내는지 먼저 검토해야 합니다. 사각형을 그렸다는 이유만으로 가환하는 것은 아닙니다. 함수의 같은 출력, 구조를 보존하는 사상, 함자 간 자연성은 각각 다른 수준의 주장입니다.

C# IEnumerable의 지연 평가에서 원본을 변경하거나 변환 함수가 상태를 읽으면 반복 열거 결과가 달라질 수 있습니다. 이 장은 고정 배열과 순수 람다를 사용하고 계산 후 배열로 구체화합니다. int 오버플로가 없는 작은 입력 범위로 수학적 정수 연산을 모델링합니다.

8. 구현 실습

실습 A · 가환 실패

f(x)=x+1, g(x)=2x에 대해 g∘f와 f∘g를 x=3에서 비교하세요.

기대 출력:

8
7
힌트

결합법칙과 교환법칙은 다릅니다.

해답 · 별도 Program.cs 전체
Func<int,int> f = x => x+1, g = x => 2*x;
Console.WriteLine(g(f(3)));
Console.WriteLine(f(g(3)));

합성은 결합적이지만 일반적으로 교환적이지 않습니다.

실습 B · 자연동형 역

튜플 swap을 두 번 적용해 복원하고, 두 성분에 함수를 적용하는 연산과 swap의 자연성을 확인하세요.

기대 출력:

True
True
힌트

swap 전후에 f,g의 위치도 바뀌어야 합니다.

해답 · 별도 Program.cs 전체
var p = (2, 5);
static (B,A) Swap<A,B>((A,B) x) => (x.Item2,x.Item1);
Func<int,int> f=x=>x+1, g=x=>2*x;
var left = Swap((f(p.Item1), g(p.Item2)));
var s = Swap(p);
var right = (g(s.Item1), f(s.Item2));
Console.WriteLine(Swap(Swap(p)) == p);
Console.WriteLine(left == right);

단순 swap의 자기역성과 map과의 자연성을 구분해 검사했습니다.

9. 핵심 정리

  • 객체는 합성의 경계이며 사상은 구조의 동작을 보여 줍니다.
  • 함자의 합성·항등 보존과 자연변환의 자연성은 별도 법칙입니다.
  • 자연동형의 역 성분도 자연변환을 이룹니다.
  • 수반은 방향이 다른 Hom 집합 사이의 자연 전단사로 이어집니다.
