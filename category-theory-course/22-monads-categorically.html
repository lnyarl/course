범주론으로 정의하는 모나드

“모나드는 자기함자 범주에서의 모노이드다”를 타입으로 풀어봅니다. 곱 대신 함자 합성을 쓰고, 원소의 곱 대신 자연변환 join을 쓰면 프로그래머의 bind 정의와 만납니다.

1. 문제에서 출발하기

리스트 안에 리스트가 있고 그 안에 또 리스트가 있다면 어느 층을 먼저 펼쳐야 할까요? 두 방법이 같은 순서의 결과를 내야 중첩 자료를 안정적으로 합성할 수 있습니다. 이 구조는 숫자의 곱이 결합적이라는 모노이드와 닮았지만 원소 대신 타입 변환 자체를 결합합니다.

원문은 식의 변수 자리에 새로운 식을 대입하는 연산을 동기로 제시합니다. A를 담은 식 M(A)에 A→M(B)를 대입해 M(B)를 얻는 연산은 바로 bind입니다. 같은 모양이 리스트의 중첩 제거와 범주론의 모노이드 객체에 나타납니다.

2. 정의와 타입

모노이달 범주는 텐서 ⊗:C×C→C, 단위 객체 I, 결합자·좌우 단위자 자연동형을 갖고 오각형·삼각형 일관성 조건을 만족합니다. 일반적으로 텐서는 카르테시안 곱일 필요가 없습니다. 모노이드 객체는 M과 μ:M⊗M→M, η:I→M이며 결합성과 양쪽 단위 법칙을 만족합니다.

End(C)=[C,C]의 객체는 자기함자, 사상은 자연변환입니다. 텐서는 함자 합성, 단위는 항등함자 Id_C로 잡습니다. 함자 합성은 엄밀히 결합적이므로 여기서는 결합자를 생략할 수 있습니다. 모나드는 이 모노이달 범주의 모노이드 객체입니다. 즉 M:C→C, η:Id⇒M, μ:M∘M⇒M가 자연변환이고 아래 법칙을 만족합니다.

μ_A ∘ M(μ_A)=μ_A ∘ μ_MA : M³(A)→M(A)
μ_A ∘ M(η_A)=id_MA
μ_A ∘ η_MA=id_MA

3. 계산에서 일반 논증으로

리스트에서 η_A(a)=[a], μ_A는 리스트들의 리스트를 순서대로 연결합니다. M³(A)에서 먼저 바깥 중첩을 없애거나 각 안쪽 중첩을 없애면 원소 순서가 같습니다. 연결의 결합성과 빈 리스트의 항등성으로 모든 유한 중첩 리스트에 대한 법칙을 얻습니다. μ의 자연성은 map(h)∘join=join∘map(map(h))입니다.

bind(m,f)=μ_B(M(f)(m)), map(h,m)=bind(m,η∘h)로 20장의 정의를 복원합니다. 단순히 자기함자 M이 있다는 사실만으로 모나드는 아닙니다. 자연변환 η,μ와 세 법칙을 함께 지정해야 합니다. 하나의 함자에 서로 다른 lawful 구조가 가능할 수도 있으므로 타입 생성자 이름만으로 구조를 결정했다고 하면 안 됩니다.

수반 L:D→C, R:C→D에서 M=RL은 D의 모나드가 됩니다. η는 수반의 단위이고 μ_d=R(ε_Ld):RLRLd→RLd입니다. 가운데 LR을 ε로 축약합니다. 곱–지수 수반의 RL(A)=S→(A×S)는 State이며 μ는 바깥 계산이 반환한 새 상태로 안쪽 계산을 실행합니다. LR은 다음 장의 코모나드가 됩니다.

4. 직접 조작하는 세 실험

1. 세 겹 리스트 join

M³(int)=[[[n],[n+1]],[[n+2]]]입니다. 바깥 먼저와 안쪽 먼저 펼치는 두 경로를 비교합니다.

2. 두 단위 법칙

리스트 [n,n+1]에 싱글턴을 바깥에 넣거나 각 원소에 넣은 뒤 join합니다.

3. μ의 자연성

중첩 [[n],[n+1,n+2]]에 h를 적용하고 join하는 순서를 비교합니다.

6. 모형의 경계

“모나드는 모노이드”라는 문장에서 모노이드의 원소는 평범한 값 a가 아니라 End(C)의 객체인 함자 M입니다. μ는 숫자 두 개를 곱하는 이항 함수가 아니라 모든 A에 대해 M(M(A))→M(A)를 주는 자연변환입니다. 서로 다른 수준을 혼합하지 마세요.

일반 모노이달 범주에서는 괄호와 단위가 등호가 아니라 지정한 자연동형으로 연결되어 결합자·단위자가 법칙 도식에 들어갑니다. End(C)의 함자 합성 사례에서는 엄밀한 결합성을 이용해 표기를 단순화했습니다. C# 배열 예제는 리스트 함자의 구체 모형이며 일반 자기함자 범주 전체를 런타임 타입으로 구현하지 않습니다.

8. 구현 실습

실습 A · join 자연성

[[1,2],[],[3]]에서 h(x)=x+5를 join 전후로 적용하고 비교하세요.

기대 출력:

6,7,8
True
힌트

안쪽 map 두 번과 바깥 map 한 번의 타입을 확인하세요.

해답 · 별도 Program.cs 전체
int[][] nested = [ [1,2], [], [3] ];
Func<int,int> h = x => x + 5;
var a = nested.SelectMany(xs => xs).Select(h).ToArray();
var b = nested.Select(xs => xs.Select(h)).SelectMany(xs => xs).ToArray();
Console.WriteLine(string.Join(",", a));
Console.WriteLine(a.SequenceEqual(b));

빈 내부 리스트도 결과 원소를 추가하지 않아 자연성이 유지됩니다.

실습 B · State의 join

바깥 계산 outer(s)가 안쪽 계산 inner(t)=(2t,t+1)와 새 상태 s+3을 반환할 때 join(outer)(5)를 계산하세요.

기대 출력:

16,9
힌트

안쪽 계산에 원래 5가 아니라 바깥의 새 상태 8을 줍니다.

해답 · 별도 Program.cs 전체
Func<int, (int Value, int State)> inner = t => (2*t, t+1);
Func<int, (Func<int, (int Value, int State)> Value, int State)> outer
    = s => (inner, s+3);
Func<int, (int Value, int State)> joined = s =>
{
    var (nextComputation, nextState) = outer(s);
    return nextComputation(nextState);
};
var result = joined(5);
Console.WriteLine($"{result.Value},{result.State}");

이것이 곱–지수 수반에서 유도된 μ=RεL의 State 계산입니다.

9. 핵심 정리

  • 모나드는 (End(C),합성,Id)의 모노이드 객체입니다.
  • η와 μ는 자연변환이며 결합성·양쪽 단위 법칙을 만족합니다.
  • join의 세 법칙은 bind의 모나드 법칙과 같은 구조를 표현합니다.
  • 수반 L⊣R은 RL 모나드와 μ=RεL을 만듭니다.
