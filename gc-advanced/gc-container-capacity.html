Server GC·DATAS·컨테이너 용량 실험

선수 장 · GC 모드와 DATAS

코어가 많은 호스트에서 작은 컨테이너를 실행하면 같은 앱도 GC와 메모리 사용이 달라질 수 있습니다. 모드 선택을 실제 제한과 할당 패턴의 조합으로 검사합니다.

설정값과 실제 사용량 구분하기

Server GC와 Workstation GC는 처리량·스레드·힙 구성이 다릅니다. DATAS는 Server GC의 힙과 예산을 애플리케이션 크기에 맞게 조정하는 정책입니다. 사용 런타임의 활성 설정을 확인하고 고정된 코어당 힙 그림을 모든 버전의 실제 상태로 해석하지 않습니다.

GCSettings.IsServerGC와 GC.GetConfigurationVariables()로 적용 구성을 기록합니다. 설정한 HeapCount와 동적으로 사용 중인 힙 수는 같은 관측이 아닐 수 있으므로 실제 힙 수가 필요하면 지원되는 trace 분석 자료로 확인합니다. GC.GetGCMemoryInfo의 committed/heap/fragmentation과 프로세스 RSS도 구분합니다.

예산을 넘는 위치를 찾기

GC HeapHardLimit은 전체 프로세스 RSS 한도가 아닙니다. native 라이브러리, 스레드 스택, 코드와 각종 버퍼에 예산이 더 필요합니다. 같은 입력에서 관리 힙이 작아도 컨테이너 한도를 넘을 수 있으므로 총 사용량과 제한 초과 종료를 함께 관측합니다.

코드 변경 없이 runtimeconfig.json의 Server GC·DATAS·하드 리밋 조건을 한 가지씩 바꾸어 비교합니다. HeapHardLimit 같은 설정의 JSON 숫자와 환경 변수의 진수 규칙을 공식 문서에서 확인합니다. 원하는 설정을 썼다는 사실과 런타임에 실제 적용됐다는 확인을 분리합니다.

실습과 예상 관찰

자신의 작은 할당 실습 앱을 같은 이미지에서 실행하고 메모리/CPU 제한 두 수준을 정하세요. 입력·생존율을 고정해 Workstation, Server의 관측을 비교하고 지원되는 런타임에서 DATAS 활성 조건을 바꿉니다. 모드·설정·RSS·committed bytes·GC pause·완료 작업 수를 함께 저장하세요.

GC 힙만 한도 아래로 제한

프로세스의 다른 메모리는 별도로 늘 수 있습니다. HeapHardLimit 준수만으로 컨테이너 생존을 보장하지 못합니다.

동일 입력에 모드·제한 변경

처리량·pause·보유 메모리의 절충이 달라질 수 있습니다. 특정 모드가 항상 빠르거나 작다는 결론 대신 관측한 조건을 제시합니다.

실습의 경계와 다음 장

기존 컨테이너를 재설정하지 말고 실습용 환경에서만 비교합니다. 다음 설정 절에서는 실제 적용값과 버전·CPU·메모리 경계를 함께 적습니다.
