Rust 데이터베이스 구현

데이터베이스는 마법이 아니라 파일에 바이트를 놓는 규칙과, 그 규칙이 깨지지 않게 지키는 장치들입니다. 이 코스는 파일 끝에 레코드를 덧붙이는 키-값 저장소에서 출발해 페이지, B+트리, SQL, 쿼리 실행기, WAL과 크래시 복구, 트랜잭션과 psql 접속 서버까지 직접 구현합니다. INSERT 한 줄이 디스크의 어느 바이트가 되는지, 프로세스 중단 뒤 커밋을 복구하는 순서를 손으로 확인합니다. 각 장에서 완성 코드를 읽고 실행한 뒤, 시뮬레이터로 중간 상태를 확인하고 입력을 바꿔 실험합니다. 개념 · 도식 · 조작 안내 · 실행 가능한 구현 · 완료 기준을 함께 제공합니다.

저장 엔진이 두 번 바뀝니다1장의 저장소는 파일 끝에 덧붙이기만 하는 로그 구조입니다. 2장부터는 같은 자리를 고쳐 쓰는 페이지 구조로 옮겨 가고, 3장의 B+트리가 그 위에 올라갑니다. 1장의 로그는 버리는 것이 아니라 7장에서 WAL로 돌아옵니다. 실제 데이터베이스도 이 두 방식을 함께 씁니다.

9장 전체가 준비됐습니다. 참조 구현 실행 안내 · 1~9장 소스 ZIP · 전체 검사 스크립트

처음 시작한다면

  1. 전체 소스 ZIP을 풀고 터미널에서 그 폴더로 이동합니다. Rust/Cargo, Bash, Python 3가 필요합니다.
  2. bash ch01/check.sh로 로그 KV의 저장·재시작·손상 복구를 확인합니다. 성공하면 17개 완료 검사가 통과합니다.
  3. 1장에서 바이트 배치와 완성 코드를 읽고, 위젯에 같은 키를 두 번 넣어 최신 값이 선택되는 과정을 확인합니다.
  4. 다음 장도 해당 chXX/check.sh로 검증합니다. 전체 연결은 bash check-all.sh로 확인합니다.

이 코스를 보는 법

  • 완성 코드부터 실행하세요. 각 장의 구현 가이드에서 핵심 함수를 읽고, 전체 소스를 내려받아 해당 장의 check.sh를 실행하세요. 파일 간 의존성이 있으므로 ZIP의 폴더 구조를 유지하세요.
  • 완료 기준을 통과하면 다음 장으로. 장마다 셸 스크립트로 확인할 수 있는 기준을 둡니다. 통과하면 git tag ch01처럼 태그를 남겨 성장 과정을 기록하세요.
  • 위젯의 실습 안내를 따라가세요. 입력 → 조작 → 관찰 → 해석 순서로 실험합니다. 브라우저 모델은 파일 I/O나 내구성을 증명하지 않습니다. 실제 저장·복구는 Rust 검사로 따로 확인하세요.
