저장 엔진 · Chapter 03

B+트리

페이지마다 키의 범위를 맡깁니다. 키 하나를 찾을 때는 루트에서 리프로 내려가고, 범위를 읽을 때는 리프의 옆 페이지로 이동합니다. 키가 늘어나면 페이지를 나눠 균형을 유지합니다.

학습 목표

  • 구분 키와 같을 때 어느 자식으로 내려가는지 결정합니다.
  • 리프 분할의 복사와 내부 노드 분할의 이동을 구분합니다.
  • 분할을 부모로 전파하고 새 루트의 페이지 번호를 저장합니다.
  • 리프 연결로 범위를 조회하고 flush 후 다시 열어 결과를 확인합니다.
목차
  1. 읽을 페이지를 고르는 규칙
  2. 4KB 페이지 위에 노드 올리기
  3. 리프를 나눌 때는 구분 키를 복사한다
  4. 내부 노드 분할은 부모까지 이어진다
  5. 범위를 읽을 때는 리프를 연결해서 간다
  6. 삭제 후 빌리기와 병합
  7. 구현 가이드
  8. 이 저장 구조가 못 하는 것

1. 읽을 페이지를 고르는 규칙

2장은 페이지 번호를 알아야 레코드를 읽을 수 있었습니다. 이제 키를 보고 다음 페이지를 선택하는 색인을 만듭니다. 이 장의 B+트리는 내부 노드에 구분 키와 자식 페이지 번호를 저장하고, 실제 키·값은 리프에만 저장합니다. 모든 리프의 깊이는 같습니다.

이 코스에서는 구분 키를 오른쪽 하위 트리의 최소 키로 정합니다. 내부 노드에 [20, 40]이 있으면 자식은 세 개입니다. 왼쪽부터 key < 20, 20 ≤ key < 40, 40 ≤ key를 맡습니다. 이 경계 규칙을 검색과 삽입에 똑같이 사용해야 합니다.

경계와 같은 키는 어디로 갈까?
구분 키는 20, 40입니다. 19 → 20 → 39 → 40을 입력해 비교하세요.
child[0]
[5, 10]
child[1]
[20, 30]
child[2]
[40, 50]

Rust에서는 keys.partition_point(|&s| s <= key)가 자식 인덱스입니다. 이 결과는 key 이하인 구분 키의 개수입니다. <만 사용하면 경계와 같은 키가 왼쪽으로 내려가므로 실제 리프에 있어도 찾지 못합니다. 이 장에서는 중복 키를 추가하지 않고 기존 값을 갱신합니다.

왜 이진 트리 대신 한 페이지에 여러 키를 넣나요?

자식이 두 개뿐인 트리는 키가 늘수록 깊어집니다. 페이지 하나에 구분 키와 자식 번호를 여러 개 넣으면 한 번 내려갈 때 검색 범위를 더 크게 줄입니다. 다만 높이가 곧 물리 디스크 읽기 횟수는 아닙니다. 상위 노드는 버퍼 풀에 남을 수 있고 파일 읽기는 OS 캐시가 처리할 수 있습니다.

2. 4KB 페이지 위에 노드 올리기

2장의 PG02 페이지 형식을 그대로 사용합니다. 페이지의 슬롯 0에 노드 전체를 하나의 레코드로 저장합니다. 삽입으로 정렬 순서가 바뀌면 슬롯 0을 새 노드 바이트로 다시 만듭니다. 키마다 슬롯을 따로 두는 방식보다 낭비가 있지만, 이번 장에서는 트리 규칙을 먼저 확인할 수 있습니다.

페이지 0의 슬롯 0은 메타데이터입니다. 루트 번호를 여기에 저장하므로 다시 열어도 새 루트를 찾습니다. 노드 페이지는 1번부터 할당합니다. 리프의 next=0은 다음 리프가 없다는 뜻입니다.

레코드상대 오프셋내용
메타데이터 16바이트0..4magic BT03
4..6max_keys: u16 LE
6..8예약 2바이트, 0
8..16root_page_id: u64 LE
리프: 11 + 16n바이트0kind=1
1..3키 수 n: u16 LE
3..11next_leaf: u64 LE
11..(key: i64 LE, value: i64 LE) × n
내부 노드: 11 + 16n바이트0kind=2
1..3구분 키 수 n: u16 LE
3..11첫 자식: u64 LE
11..(구분 키: i64 LE, 오른쪽 자식: u64 LE) × n

위 오프셋은 페이지 시작이 아니라 슬롯 0 레코드의 시작을 기준으로 합니다. 2장의 페이지 헤더와 슬롯은 그대로 남습니다. 체크섬은 없습니다. 디코더는 노드 종류, 길이, 키의 정렬, 페이지 번호 범위를 검사합니다. 전체 트리의 균형과 구분 키는 별도의 테스트로 확인합니다.

화면에서는 최대 3키로 분할을 관찰합니다참조 구현은 max_keys를 3~200으로 받습니다. 최댓값 200일 때 노드 크기는 3211바이트로 슬롯 0의 최대 크기 4084바이트 안에 들어갑니다. 기본값 3은 학습용입니다. 실제 페이지 용량을 모두 쓰는 설정이나 성능 측정 결과가 아닙니다.

키는 부호 있는 64비트 정수입니다. 바이트 배열을 사전순으로 비교하지 않고 i64::from_le_bytes로 읽은 숫자를 비교합니다. 웹 시뮬레이터는 정수 −999~999로 제한하지만 Rust 예제는 i64 전체 범위를 받습니다.

3. 리프를 나눌 때는 구분 키를 복사한다

최대 3개 키를 담는 리프 [10, 20, 30]에 40을 넣으면 네 개가 됩니다. 정렬한 뒤 가운데에서 나눠 왼쪽은 [10, 20], 오른쪽은 [30, 40]으로 만듭니다. 부모에는 오른쪽의 첫 키 30과 새 페이지 번호를 넣습니다. 30의 실제 값은 오른쪽 리프에 그대로 남습니다.

리프 연결은 right.next = old.next를 먼저 정하고 left.next = right_id로 바꿉니다. 오른쪽 끝이 아닌 리프를 나눌 때도 기존의 다음 리프를 잃으면 안 됩니다. 코드에서는 새 오른쪽 노드를 저장한 뒤 왼쪽 노드를 갱신합니다. 이 순서는 정상 실행의 연결을 지키지만 크래시 원자성을 보장하지는 않습니다.

분할을 멈춰 보며 비교하기
넘친 노드의 키 4개를 입력하세요. 값은 리프에만 있으며, 내부 노드 그림은 구분 키와 자식 개수만 보여 줍니다. 모드를 바꾸면 같은 키가 어디에 남는지 비교할 수 있습니다.

4. 내부 노드 분할은 부모까지 이어진다

자식의 분할로 부모에도 키가 하나 늘어납니다. 부모가 넘치면 내부 노드도 나눕니다. [10, 20, 30, 40]을 나눌 때 가운데 인덱스를 2로 잡으면 30을 부모로 올리고 왼쪽에는 [10, 20], 오른쪽에는 [40]을 남깁니다. 자식 다섯 개는 왼쪽 세 개, 오른쪽 두 개로 나눕니다.

내부 노드의 30은 부모로 이동하므로 분할 후 내부 노드 양쪽에 남기지 않습니다. 리프에 저장된 실제 키 30과 값은 그대로입니다. 루트까지 분할되면 기존 루트와 새 오른쪽 노드를 자식으로 갖는 새 루트를 만들고, 페이지 0의 루트 번호를 바꿉니다. 높이는 이때만 1 증가합니다.

직접 키를 넣고 트리를 나누기
최대 3키, 값은 key × 10입니다. 각 버튼은 삽입 하나를 끝까지 실행합니다. 로그에서 분할 순서를 확인하세요. 화면은 24개 키까지 표시합니다. 트리가 넓어지면 도식을 좌우로 스크롤하세요.

10 → 20 → 30 → 40을 순서대로 넣으세요네 번째 삽입 후 루트는 p3의 [30], 리프는 p1의 [10, 20]과 p2의 [30, 40]입니다. 30을 검색하면 오른쪽으로 갑니다. ‘예제 10~120’을 누르면 내부 노드 분할까지 이어져 높이가 3이 됩니다.

참조 구현은 내려갈 때 (부모 페이지 번호, 선택한 자식 인덱스)를 경로에 저장합니다. 리프를 수정한 뒤 이 경로를 거꾸로 올라가며 분할 결과를 반영합니다. 노드를 메모리의 값으로 읽은 직후 pin을 반납하므로 부모에서 자식으로 내려가는 동안 여러 프레임을 계속 pin하지 않습니다. 프레임 하나로도 동작하는지 검사합니다.

5. 범위를 읽을 때는 리프를 연결해서 간다

range(25, 65)는 먼저 25가 들어갈 리프를 찾습니다. 그 리프에서 25 이상인 키를 모으고, next를 따라 오른쪽 리프를 읽습니다. 65보다 큰 키를 만나거나 next가 0이면 끝냅니다. 이 장의 범위는 양 끝을 포함합니다. 하한이 상한보다 크면 빈 결과입니다.

리프를 하나씩 읽는 범위 스캔
위 트리를 그대로 사용합니다. ‘예제 10~120’을 만든 뒤 25~65를 조회해 보세요. 키를 삽입하거나 트리를 초기화하면 진행 중인 스캔을 취소합니다.

키마다 루트에서 다시 내려갈 필요가 없습니다. 초기 경로 검색 이후에는 리프 연결을 따라 읽습니다. 예제는 결과를 Vec에 모읍니다. 큰 결과를 다루는 서버에서는 한 행씩 반환하는 iterator나 배치 API로 바꾸는 편이 적합합니다.

6. 삭제 후 빌리기와 병합

분할만 있으면 삭제 후 비어 가는 페이지를 정리하지 못합니다. 이 장에서는 병합 원리를 설명하고, delete 구현은 실습 확장으로 둡니다. 기본 참조 구현과 위 시뮬레이터는 검색·삽입·갱신·범위 조회까지만 제공합니다.

최대 3키인 리프의 최소 키 수를 2로 정해 보겠습니다. 같은 부모 아래 [10, 20]과 [30, 40, 50]이 있을 때 10을 삭제하면 왼쪽에 20만 남습니다. 오른쪽에서 30을 빌리면 [20, 30], [40, 50]이 됩니다. 부모의 경계도 30에서 40으로 바꿉니다.

오른쪽도 최소 개수뿐이라 빌릴 수 없으면 합칩니다. [20]과 [30, 40]은 [20, 30, 40]이 되고, 왼쪽의 next를 오른쪽의 next로 바꿉니다. 부모에서는 오른쪽 자식 번호와 그 앞의 구분 키를 제거합니다. 부모까지 부족해지면 같은 과정을 반복합니다. 루트에 자식이 하나만 남으면 그 자식을 새 루트로 정합니다.

내부 노드 병합에서 빠뜨리기 쉬운 것

내부 노드를 합칠 때는 부모에서 제거한 구분 키를 두 내부 노드의 키 사이에 내려 넣어야 합니다. 리프 병합은 실제 키·값을 합치는 작업이므로 부모의 구분 키를 별도 레코드로 넣지 않습니다. 또한 이 장의 ‘오른쪽 최소 키’ 규칙을 유지하려면 최소 키 삭제가 상위 경계에 미치는 영향도 확인해야 합니다.

삭제 구현에는 분리된 페이지의 재사용 목록도 필요합니다. 페이지 연결에서만 제거하고 파일 공간을 반환하지 않으면 파일 크기는 줄지 않습니다. 이 예제에는 재사용 목록이 없으므로 삽입 때 새 페이지를 파일 끝에 할당합니다.

삭제 뒤에는 빌릴까, 합칠까?
최대 3키·최소 2키인 리프를 가정합니다. 루트의 두 자식 중 왼쪽 [10,20]에서 10을 삭제합니다. 오른쪽의 여유에 따라 부모 경계와 next 연결이 어떻게 바뀌는지 예측하세요. 이 위젯은 병합 원리 실습이며 Rust 참조 코드에 delete를 추가하지 않습니다.

도식이 넓으면 좌우로 스크롤해 연결을 확인하세요.

#[allow(dead_code)]
mod storage {
    include!("../ch02/pages.rs");
    pub struct Pager(Pool);
    impl Pager {
        pub fn open(path: &Path, capacity: usize) -> io::Result<Self> {
            Ok(Self(Pool::new(Disk::open(path)?, capacity)?))
        }
        pub fn len(&self) -> u64 {
            self.0.disk.pages
        }
        pub fn allocate(&mut self) -> io::Result<u64> {
            self.0.disk.allocate()
        }
        pub fn read(&mut self, id: u64) -> io::Result<Vec<u8>> {
            let f = self.0.fetch(id)?;
            let result = self.0.get(f, 0).and_then(|record| {
                record
                    .map(<[u8]>::to_vec)
                    .ok_or_else(|| invalid("missing slot zero"))
            });
            self.0.unpin(f)?;
            result
        }
        pub fn write(&mut self, id: u64, bytes: &[u8]) -> io::Result<()> {
            let mut page = Page::new();
            page.insert(bytes)?;
            let f = self.0.fetch(id)?;
            let frame = self.0.frames[f].as_mut().unwrap();
            frame.page = page;
            frame.dirty = true;
            self.0.unpin(f)
        }
        pub fn flush(&mut self) -> io::Result<()> {
            self.0.flush()
        }
    }
}
fn bad(message: &str) -> io::Error {
    io::Error::new(io::ErrorKind::InvalidData, message)

#[derive(Debug, Clone, PartialEq)]
enum Node {
    Leaf { rows: Vec<(i64, i64)>, next: u64 },
    Branch { keys: Vec<i64>, children: Vec<u64> },
}
impl Node {
    fn encode(&self) -> Vec<u8> {
        let mut b = Vec::new();
        match self {
            Self::Leaf { rows, next } => {
                b.push(1);
                b.extend_from_slice(&(rows.len() as u16).to_le_bytes());
                b.extend_from_slice(&next.to_le_bytes());
                for (key, value) in rows {
                    b.extend_from_slice(&key.to_le_bytes());
                    b.extend_from_slice(&value.to_le_bytes());
                }
            }
            Self::Branch { keys, children } => {
                b.push(2);
                b.extend_from_slice(&(keys.len() as u16).to_le_bytes());
                b.extend_from_slice(&children[0].to_le_bytes());
                for (key, child) in keys.iter().zip(&children[1..]) {
                    b.extend_from_slice(&key.to_le_bytes());
                    b.extend_from_slice(&child.to_le_bytes());
                }
            }
        }
        b
    }
    fn decode(b: &[u8], max: usize, pages: u64) -> io::Result<Self> {
        if b.len() < 11 {
            return Err(bad("short node"));
        }
        let n = u16::from_le_bytes([b[1], b[2]]) as usize;
        if n > max || b.len() != 11 + 16 * n {
            return Err(bad("bad node size"));
        }
        let u64_at = |at| u64::from_le_bytes(b[at..at + 8].try_into().unwrap());
        let i64_at = |at| i64::from_le_bytes(b[at..at + 8].try_into().unwrap());
        let valid_id = |id| id > 0 && id < pages;
        let keys: Vec<_> = (0..n).map(|i| i64_at(11 + i * 16)).collect();
        if keys.windows(2).any(|w| w[0] >= w[1]) {
            return Err(bad("unsorted node"));
        }
        match b[0] {
            1 => {
                let next = u64_at(3);
                if next != 0 && !valid_id(next) {
                    return Err(bad("bad next leaf"));
                }
                let rows = keys
                    .into_iter()
                    .enumerate()
                    .map(|(i, k)| (k, i64_at(19 + i * 16)))
                    .collect();
                Ok(Self::Leaf { rows, next })
            }
            2 => {
                let mut children = vec![u64_at(3)];
                children.extend((0..n).map(|i| u64_at(19 + i * 16)));
                if n == 0 || children.iter().any(|&id| !valid_id(id)) {
                    return Err(bad("bad branch"));
                }
                Ok(Self::Branch { keys, children })
            }
            _ => Err(bad("unknown node kind")),
        }
    }
}
struct Tree {
    pager: storage::Pager,
    root: u64,
    max: usize,
}
impl Tree {
    fn open(path: &Path, max: usize, capacity: usize) -> io::Result<Self> {
        if !(3..=200).contains(&max) {
            return Err(bad("max_keys must be 3..200"));
        }
        let mut pager = storage::Pager::open(path, capacity)?;
        if pager.len() == 0 {
            pager.allocate()?; // page 0: metadata
            let root = pager.allocate()?;
            let mut t = Self { pager, root, max };
            t.save(
                root,
                &Node::Leaf {
                    rows: vec![],
                    next: 0,
                },
            )?;
            t.save_meta()?;
            t.flush()?;
            Ok(t)
        } else {
            let b = pager.read(0)?;
            if b.len() != 16 || &b[..4] != b"BT03" || b[6..8] != [0, 0] {
                return Err(bad("bad metadata"));
            }
            if u16::from_le_bytes([b[4], b[5]]) as usize != max {
                return Err(bad("max_keys mismatch"));
            }
            let root = u64::from_le_bytes(b[8..16].try_into().unwrap());
            if root == 0 || root >= pager.len() {
                return Err(bad("bad root"));
            }
            let mut t = Self { pager, root, max };
            t.load(root)?;
            Ok(t)
        }
    }
    fn save_meta(&mut self) -> io::Result<()> {
        let mut b = b"BT03".to_vec();
        b.extend_from_slice(&(self.max as u16).to_le_bytes());
        b.extend_from_slice(&[0, 0]);
        b.extend_from_slice(&self.root.to_le_bytes());
        self.pager.write(0, &b)
    }
    fn load(&mut self, id: u64) -> io::Result<Node> {
        if id == 0 {
            return Err(bad("metadata is not a node"));
        }
        Node::decode(&self.pager.read(id)?, self.max, self.pager.len())
    }
    fn save(&mut self, id: u64, node: &Node) -> io::Result<()> {
        self.pager.write(id, &node.encode())
    }
    fn new_node(&mut self, node: &Node) -> io::Result<u64> {
        let id = self.pager.allocate()?;
        self.save(id, node)?;
        Ok(id)
    }
    // Equality goes right: separators are lower bounds of right subtrees.
    fn leaf(&mut self, key: i64) -> io::Result<(u64, Vec<(u64, usize)>)> {
        let mut path = Vec::new();
        let mut id = self.root;
        for _ in 0..self.pager.len() {
            match self.load(id)? {
                Node::Leaf { .. } => return Ok((id, path)),
                Node::Branch { keys, children } => {
                    let i = keys.partition_point(|&separator| separator <= key);
                    path.push((id, i));
                    id = children[i];
                }
            }
        }
        Err(bad("cycle in tree"))
    }
    fn get(&mut self, key: i64) -> io::Result<Option<i64>> {
        let (id, _) = self.leaf(key)?;
        let Node::Leaf { rows, .. } = self.load(id)? else {
            unreachable!()
        };
        Ok(rows
            .binary_search_by_key(&key, |r| r.0)
            .ok()
            .map(|i| rows[i].1))
    }
    fn set(&mut self, key: i64, value: i64) -> io::Result<()> {
        let (id, mut path) = self.leaf(key)?;
        let Node::Leaf { mut rows, next } = self.load(id)? else {
            unreachable!()
        };
        match rows.binary_search_by_key(&key, |r| r.0) {
            Ok(i) => rows[i].1 = value,
            Err(i) => rows.insert(i, (key, value)),
        }
        if rows.len() <= self.max {
            return self.save(id, &Node::Leaf { rows, next });
        }
        let right_rows = rows.split_off(rows.len() / 2);
        let mut separator = right_rows[0].0;
        let mut right = self.new_node(&Node::Leaf {
            rows: right_rows,
            next,
        })?;
        self.save(id, &Node::Leaf { rows, next: right })?;
        while let Some((parent, i)) = path.pop() {
            let Node::Branch {
                mut keys,
                mut children,
            } = self.load(parent)?
            else {
                return Err(bad("bad insertion path"));
            };
            keys.insert(i, separator);
            children.insert(i + 1, right);
            if keys.len() <= self.max {
                return self.save(parent, &Node::Branch { keys, children });
            }
            let mid = keys.len() / 2;
            let right_keys = keys.split_off(mid + 1);
            separator = keys.pop().unwrap();
            let right_children = children.split_off(mid + 1);
            right = self.new_node(&Node::Branch {
                keys: right_keys,
                children: right_children,
            })?;
            self.save(parent, &Node::Branch { keys, children })?;
        }
        self.root = self.new_node(&Node::Branch {
            keys: vec![separator],
            children: vec![self.root, right],
        })?;
        self.save_meta()
    }
    fn range(&mut self, lo: i64, hi: i64) -> io::Result<Vec<(i64, i64)>> {
        if lo > hi {
            return Ok(vec![]);
        }
        let (mut id, _) = self.leaf(lo)?;
        let mut result = Vec::new();
        let mut seen = std::collections::HashSet::new();
        loop {
            if !seen.insert(id) {
                return Err(bad("cycle in leaf chain"));
            }
            let Node::Leaf { rows, next } = self.load(id)? else {
                return Err(bad("next points to branch"));
            };
            for (k, v) in rows {
                if k > hi {
                    return Ok(result);
                }
                if k >= lo {
                    result.push((k, v));
                }
            }
            if next == 0 {
                return Ok(result);
            }
            id = next;
        }
    }
    fn flush(&mut self) -> io::Result<()> {
        self.pager.flush()
    }
}
fn main() -> io::Result<()> {
    let args: Vec<_> = std::env::args().collect();
    let path = args
        .get(1)
        .ok_or_else(|| bad("usage: btree FILE [MAX_KEYS]"))?;
    let max = args
        .get(2)
        .map(|s| s.parse::<usize>())
        .transpose()
        .map_err(|_| bad("bad max_keys"))?
        .unwrap_or(3);
    let mut t = Tree::open(Path::new(path), max, 3)?;
    for line in io::stdin().lock().lines() {
        let line = line?;
        let words: Vec<_> = line.split_whitespace().collect();
        let integer = |s: &str| s.parse::<i64>().map_err(|_| bad("expected i64"));
        match words.as_slice() {
            ["set", k, v] => {
                t.set(integer(k)?, integer(v)?)?;
                println!("OK");
            }
            ["get", k] => match t.get(integer(k)?)? {
                Some(v) => println!("{v}"),
                None => println!("(nil)"),
            },
            ["range", lo, hi] => {
                let rows = t.range(integer(lo)?, integer(hi)?)?;
                println!(
                    "{}",
                    rows.iter()
                        .map(|(k, v)| format!("{k}:{v}"))
                        .collect::<Vec<_>>()
                        .join(" ")
                );
            }
            [".flush"] => {
                t.flush()?;
                println!("FLUSHED");
            }
            [".exit"] => break,
            [] => {}
            _ => {
                return Err(bad(
                    "commands: set K V | get K | range LO HI | .flush | .exit",
                ));
            }
        }
    }
    t.flush()
}

    // Verify balance, separator meaning, occupancy and the complete leaf chain.
    fn verify(t: &mut Tree) {
        fn walk(
            t: &mut Tree,
            id: u64,
            root: bool,
            level: usize,
            depths: &mut Vec<usize>,
            leaves: &mut Vec<u64>,
        ) -> Option<(i64, i64)> {
            match t.load(id).unwrap() {
                Node::Leaf { rows, .. } => {
                    assert!(rows.len() <= t.max);
                    if !root {
                        assert!(rows.len() >= t.max.div_ceil(2));
                    }
                    depths.push(level);
                    leaves.push(id);
                    rows.first().zip(rows.last()).map(|(a, b)| (a.0, b.0))
                }
                Node::Branch { keys, children } => {
                    assert_eq!(children.len(), keys.len() + 1);
                    assert!(!keys.is_empty() && keys.len() <= t.max);
                    if !root {
                        assert!(keys.len() >= t.max / 2);
                    }
                    let ranges: Vec<_> = children
                        .into_iter()
                        .map(|c| walk(t, c, false, level + 1, depths, leaves).unwrap())
                        .collect();
                    for i in 0..keys.len() {
                        assert!(ranges[i].1 < keys[i]);
                        assert_eq!(keys[i], ranges[i + 1].0);
                    }
                    Some((ranges[0].0, ranges.last().unwrap().1))
                }
            }
        }
        let mut depths = vec![];
        let mut leaves = vec![];
        walk(t, t.root, true, 0, &mut depths, &mut leaves);
        assert!(depths.iter().all(|d| *d == depths[0]));
        for (i, &id) in leaves.iter().enumerate() {

                unreachable!()

            assert_eq!(next, leaves.get(i + 1).copied().unwrap_or(0));

  • 오름차순·내림차순·섞인 삽입 후 모든 리프의 깊이가 같습니다.
  • 각 구분 키는 오른쪽 하위 트리의 최소 키이고 왼쪽 범위와 겹치지 않습니다.
  • 모든 리프가 next로 한 번씩 연결되고 마지막 next는 0입니다.
  • 프레임 하나로도 분할·조회·flush가 성공합니다.

핵심 요약

  • 경계와 같은 키는 오른쪽 자식으로 내려갑니다.
  • 리프 분할은 오른쪽 첫 키를 복사하고, 내부 분할은 가운데 키를 부모로 이동합니다.
  • 범위 조회는 하한을 찾은 뒤 리프의 next를 따라갑니다.
  • 새 루트의 번호도 파일에 기록해야 합니다.

확인 문제

구분 키가 [20,40]일 때 키 40이 내려갈 자식은?
자식 인덱스는 40 이하인 구분 키의 개수인 2입니다.
리프 [10,20,30,40]을 분할하고 30을 부모에 넣었습니다. 실제 키 30은?
값은 리프에만 저장합니다. 구분 키는 오른쪽 첫 키의 복사입니다.
내부 노드의 가운데 키를 부모로 올릴 때는?
내부 노드에서는 가운데 구분 키를 이동합니다. 리프의 실제 값은 지우지 않습니다.
새 루트를 만든 뒤 재시작을 위해 함께 저장할 정보는?
트리를 다시 열 때 페이지 0에서 루트 번호를 읽습니다.
range(25,65)가 반환하는 키는? 저장된 키는 10,20,…,120입니다.
하한 이상, 상한 이하를 반환합니다. 양 끝을 포함합니다.

실습 과제

  1. 분할 순서를 기록하세요. 10~120을 10씩 올려 넣고 각 단계의 루트·리프 연결을 적으세요. 최종 높이는 3이고 range(25,65)는 30,40,50,60의 값만 반환해야 합니다. 30의 값을 다시 바꿔도 노드 수는 늘지 않아야 합니다.
  2. 삭제·빌리기·병합을 추가하세요. 같은 부모 아래 리프 [10,20], [30,40,50]에서 10을 지우고 오른쪽에서 빌리세요. 결과는 [20,30], [40,50]이고 부모 경계는 40이어야 합니다. 다시 삭제해 병합하는 경우에도 next 연결, 검색 결과, 새 루트 번호를 검사하세요.
  3. 분할된 파일을 다시 여세요. 오름차순과 내림차순으로 각각 180개를 넣고 flush한 뒤 프로세스를 종료하세요. 두 파일의 페이지 배치는 달라도 get과 전체 range 결과는 같아야 합니다. BTreeMap과 비교하는 검사에 키 갱신도 섞으세요.

8. 이 저장 구조가 못 하는 것

키로 페이지를 고르고 범위 조회도 할 수 있게 됐습니다. 하지만 키와 값은 정수 두 개뿐입니다. 이름·날짜·NULL·가변 길이 문자열을 가진 행도, 열 정의와 테이블 목록도 없습니다. 다음 장에서는 테이블과 레코드 형식을 만들어 이 저장 엔진 위에 관계형 데이터를 올립니다.

분할의 여러 페이지 쓰기는 아직 원자적이지 않습니다flush 성공 후 정상 재시작만 검증했습니다. 분할 중 I/O 오류나 프로세스 종료가 발생하면 일부 노드와 메타데이터만 바뀔 수 있습니다. 쓰기 오류 후에는 작업을 중단해야 합니다. 이 예제에는 WAL, 트랜잭션, 다중 프로세스 잠금과 자동 복구가 없습니다. Linux의 fsync 계열 동기화와 macOS의 F_FULLFSYNC 차이는 2장의 동기화 설명을 참고하세요. 7장에서 WAL과 복구 순서를 다룹니다.
