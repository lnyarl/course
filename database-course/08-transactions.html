트랜잭션과 동시성

BEGIN에서 읽을 상태를 고정하고, 변경은 작업공간에 모았다가 COMMIT에서 검증합니다. 두 세션이 명령을 번갈아 실행할 때 무엇이 보이고 어느 쓰기가 충돌하는지 직접 확인합니다.

1. 이번 장은 DB 전체를 스냅샷으로 복사한다

7장에서 만든 WAL 계층은 private workspace에서 변경한 뒤 커밋 파일 이미지를 내구성 있게 기록하고 적용합니다. 이번 장은 그 위에 여러 트랜잭션 ID와 수명을 관리하는 Transactions를 올립니다. BEGIN마다 같은 시점의 DB 데이터 파일 복사본과 시작 revision을 보관합니다.

실제 구현은 global revision OCC입니다행별 버전 연결 목록이나 잠금 관리자를 구현하지 않습니다. 작업공간은 DB 전체의 private copy이고, 쓰기 COMMIT은 그 사이 어떤 DB 쓰기라도 커밋되면 충돌합니다. 서로 다른 행을 바꿔도 두 번째 쓰기는 재시도해야 합니다. 아래 행 MVCC·잠금·write skew 도식은 비교를 위한 개념 모형입니다.

같은 Transactions 인스턴스에서 여러 ID가 동시에 살아 있을 수 있지만 각 메서드 호출은 하나씩 실행합니다. 9장의 서버는 외부 Mutex로 이 호출을 직렬화합니다. 트랜잭션 수명과 네트워크 요청은 서로 끼어들 수 있습니다. 독립 CLI 두 개를 같은 디렉터리에 열어 쓰기를 경쟁시키는 방식은 7장의 단일 협력 writer 잠금이 거부합니다.

2. 읽기와 쓰기 커밋의 조건이 다르다

BEGIN 후 SELECT는 자신의 시작 복사본과 그 안에서 수행한 자기 쓰기를 읽습니다. 다른 세션의 아직 커밋하지 않은 행은 보이지 않습니다. 다른 세션이 나중에 커밋한 행도 기존 복사본에는 들어오지 않습니다. 따라서 이 구현에서는 반복 조회와 조건 조회의 행 집합이 시작 시점에 고정됩니다.

dirty COMMIT은 snapshot.base_revision() == database.revision()일 때만 진행합니다. 그다음 7장의 WAL 내구화·파일 설치 경로를 사용하고 revision을 증가시킵니다. 충돌하면 base는 바꾸지 않고 트랜잭션을 E 상태로 유지합니다.

읽기 전용 COMMIT은 오래된 base라도 성공할 수 있습니다. 새로운 쓰기가 없으므로 WAL과 revision을 늘리지 않습니다. 반환값은 그때의 현재 revision이며 새 revision을 생성했다는 뜻이 아닙니다. 오래된 복사본의 읽기는 시작 시점의 직렬 순서로 볼 수 있습니다.

두 세션의 private copy와 COMMIT 충돌
모형은 커밋된 행 [1], revision 0에서 시작합니다. 실제 엔진의 whole-DB snapshot + global revision 검증 규칙을 작은 행 집합에 적용합니다. 중복 id=1도 넣어 실패 상태를 비교할 수 있습니다.

마지막 COMMIT을 예측하세요. 쓰기 스케줄은 B, 읽기 스케줄은 A가 대상입니다.

도식은 좌우로 스크롤할 수 있습니다. 행 id는 메커니즘 모형이며 실제 파일이나 SQL을 실행하지 않습니다.

서로 다른 행도 충돌합니다A가 id=2, B가 id=3을 쓰더라도 B는 A의 새 데이터를 포함하지 않는 과거 전체 복사본을 설치하려고 합니다. revision 검증을 빼면 A의 쓰기를 덮어 지울 수 있습니다. 이 구현은 행·읽기 집합 분석 대신 모든 동시 dirty writer를 충돌시키는 보수적인 방법을 사용합니다.

3. T·E 상태와 ROLLBACK

T · 활성SQL을 실행할 수 있습니다. 자기 작업공간에서 읽고 씁니다.
E · 실패SQL 오류·COMMIT 충돌·상위 계층 오류 뒤에는 추가 SQL과 COMMIT을 거부합니다.
I · 활성 ID 없음COMMIT 성공 또는 ROLLBACK 후 서버 세션은 트랜잭션 밖으로 돌아갑니다.

실패했다고 이전 성공 쓰기를 설치하지 않습니다. 명시적 트랜잭션은 E로 남고, 호출자가 ROLLBACK하면 HashMap에서 제거해 Snapshot의 Drop이 작업공간을 정리합니다. 읽기 전용 성공, 쓰기 성공, 연결 종료에도 해당 복사본을 해제합니다.

autocommit_with는 내부에서 BEGIN→query_with→COMMIT을 실행하고 어느 단계에서 오류가 나도 활성 ID를 정리합니다. mark_failed(id)는 9장 프로토콜 계층이 발견한 오류도 E로 유지할 수 있는 메모리 상태 전환입니다.

내구화 이후 오류는 결과가 불확실할 수 있습니다커밋 레코드가 WAL에 내구화된 뒤 파일 설치가 실패하면 Database는 poisoned 상태가 됩니다. 더 이상 새 BEGIN·SQL·COMMIT을 진행하지 않고 재열기 복구가 필요합니다. 이때 ROLLBACK은 작업공간만 정리하며 이미 내구화된 COMMIT을 취소하지 못합니다. 오류 응답을 ‘절대로 커밋되지 않음’으로 해석하지 마세요.

4. 행 MVCC와 잠금은 별도의 설계다

행 MVCC는 같은 행의 여러 버전과 가시성 규칙을 관리해 서로 다른 스냅샷을 제공하는 접근입니다. 이번 구현은 그 원리를 DB 전체 파일 복사로 단순화한 것이며 행 버전 체인·vacuum·가시성 인덱스를 구현하지 않습니다.

잠금 기반 접근에서는 읽기·쓰기 충돌을 기다리게 할 수도 있습니다. strict 2PL 같은 방식은 필요한 잠금을 얻고 쓰기 잠금을 트랜잭션 종료까지 유지합니다. 서로 잠금을 잡은 채 상대를 기다리면 deadlock이 생길 수 있으므로 대기 순환 탐지나 일관된 잠금 순서가 필요합니다. 아래는 두 배타 잠금만 쓰는 개념 모형입니다.

잠금 요청 순서를 바꾸고 대기 그래프 보기
A는 X→Y 순서로 요청합니다. B의 순서를 바꿔 A→B→A 순환이 생기는지 비교하세요. 마지막 단계에서 희생 트랜잭션을 취소해 잠금을 푸는 흐름을 보여 줍니다.

개념 실험: 실제 Transactions 구현에는 행 잠금·대기 큐·deadlock detector가 없습니다. 실제 쓰기는 기다리지 않고 COMMIT revision 검증에서 충돌합니다.

도식은 내부에서 좌우로 스크롤할 수 있습니다.

여러 잠금을 같은 순서로 얻으면 이 모형의 순환을 피할 수 있습니다. 실제 DB는 여러 잠금 모드·자원 종류·승격을 다뤄야 합니다. 더 자세한 예는 PostgreSQL deadlock 설명을 참고하세요.

5. 스냅샷만으로 write skew가 사라지지는 않는다

dirty read는 다른 트랜잭션의 미커밋 데이터를 읽는 현상입니다. nonrepeatable read는 재조회 값이 바뀌는 현상이고, phantom은 같은 조건의 행 집합이 바뀌는 현상입니다. serializable은 성공한 실행이 어떤 직렬 순서와 같은 효과를 내야 한다는 조건입니다. 격리 수준 정의에서 이 차이를 확인할 수 있습니다.

같은 시작 스냅샷에서 ‘근무자가 둘이니 나 하나는 빠져도 된다’고 두 세션이 판단한다고 가정합시다. 각자 다른 행을 비근무로 바꿔 둘 다 커밋하면 최소 한 명 근무라는 제약이 깨집니다. 행 단위 write-write 충돌만 확인하는 snapshot isolation은 이런 write skew를 허용할 수 있습니다.

직렬 실행·행 snapshot·global OCC 비교
초기에는 A와 B 모두 근무합니다. 최소 1명은 남아야 합니다. 어떤 조건이 두 번째 변경을 막는지 비교하세요.

근무 행의 boolean UPDATE는 개념 실험입니다. 현재 SQL 파서는 UPDATE를 지원하지 않습니다. global OCC 모드는 실제 구현의 ‘어떤 DB 쓰기도 revision 충돌’ 규칙을 보여 줍니다.

도식은 내부에서 좌우로 스크롤할 수 있습니다.

이 예제의 global 검증에서는 A가 커밋한 뒤 B의 dirty COMMIT이 거부되므로 위 두 변경이 함께 성공하지 않습니다. 그 대신 서로 관련 없는 테이블·행의 쓰기도 충돌합니다. 충돌 범위를 줄이려면 읽기·쓰기 집합, 행 버전과 인덱스 조건 범위를 실제로 추적하는 추가 설계가 필요합니다.

이 장은 새로운 행·WAL 바이트 형식을 추가하지 않습니다. 실제 파일 형식과 내구화 순서는 7장의 WAL을 사용합니다. Linux의 fsync와 macOS의 F_FULLFSYNC 차이와 전원 차단 보장도 7장의 범위를 따릅니다. 여기서 강제 프로세스 종료 재열기 검사는 실제 장치 전원 차단 실험과 다릅니다.

//! Single-process snapshot transactions. This is global-revision OCC, not row MVCC.
use std::{
    collections::HashMap,
    io::{self, BufRead},
    path::Path,
};
#[allow(dead_code)]
#[path = "../ch07/wal.rs"]
pub mod wal;
const MAX_ACTIVE: usize = 32;
fn bad(message: &str) -> io::Error {
    io::Error::new(io::ErrorKind::InvalidInput, message)
}
struct Active {
    snapshot: wal::Snapshot,
    failed: bool,
}
/// Owns the committed database plus independent workspaces for active sessions.
/// An external mutex must serialize calls when used by a network server.
pub struct Transactions {
    database: wal::Database,
    active: HashMap<u64, Active>,
    next_id: u64,
}
impl Transactions {
    pub fn open(path: &Path) -> io::Result<Self> {
        Ok(Self {
            database: wal::Database::open(path)?,
            active: HashMap::new(),
            next_id: 1,
        })
    }
    fn usable(&mut self) -> io::Result<()> {
        if self.database.is_poisoned() {
            for transaction in self.active.values_mut() {
                transaction.failed = true;
            }
            return Err(bad("database requires recovery before further operations"));
        }
        Ok(())
    }
    pub fn begin(&mut self) -> io::Result<u64> {
        self.usable()?;
        if self.active.len() >= MAX_ACTIVE {
            return Err(bad("at most 32 active transactions"));
        }
        let id = self.next_id;
        let next = id
            .checked_add(1)
            .ok_or_else(|| bad("transaction id exhausted"))?;
        let snapshot = self.database.snapshot()?;
        self.next_id = next;
        self.active.insert(
            id,
            Active {
                snapshot,
                failed: false,
            },
        );
        Ok(id)
    }
    pub fn query(&mut self, id: u64, sql: &str) -> io::Result<wal::engine::SqlReply> {
        self.query_with(id, sql, wal::engine::run_sql)
    }
    /// The callback runs only against this transaction's private workspace.
    /// It must execute the supplied SQL honestly; it is an internal engine hook.
    pub fn query_with<T, F>(&mut self, id: u64, sql: &str, runner: F) -> io::Result<T>
    where
        F: FnOnce(&Path, &str) -> io::Result<T>,
    {
        self.usable()?;
        let transaction = self
            .active
            .get_mut(&id)
            .ok_or_else(|| bad("unknown transaction"))?;
        if transaction.failed || transaction.snapshot.is_failed() {
            transaction.failed = true;
            return Err(bad("transaction is failed; ROLLBACK required"));
        }
        let result = transaction.snapshot.query_with(sql, runner);
        if result.is_err() {
            transaction.failed = true;
        }
        result
    }
    pub fn commit(&mut self, id: u64) -> io::Result<u64> {
        self.usable()?;
        let transaction = self
            .active
            .get_mut(&id)
            .ok_or_else(|| bad("unknown transaction"))?;
        if transaction.failed || transaction.snapshot.is_failed() {
            transaction.failed = true;
            return Err(bad("transaction is failed; ROLLBACK required"));
        }
        let result = self.database.commit(&mut transaction.snapshot);
        match result {
            Ok(revision) => {
                self.active.remove(&id);
                Ok(revision)
            }
            Err(error) => {
                self.active.get_mut(&id).unwrap().failed = true;
                if self.database.is_poisoned() {
                    for transaction in self.active.values_mut() {
                        transaction.failed = true;
                    }
                    return Err(io::Error::new(
                        error.kind(),
                        format!("database requires recovery; commit outcome unknown: {error}"),
                    ));
                }
                Err(error)
            }
        }
    }
    /// Rollback remains available after an in-doubt commit to release workspaces.
    /// It cannot undo a commit record that has already reached durable WAL.
    pub fn rollback(&mut self, id: u64) -> io::Result<()> {
        self.active
            .remove(&id)
            .map(drop)
            .ok_or_else(|| bad("unknown transaction"))
    }
    pub fn autocommit(&mut self, sql: &str) -> io::Result<wal::engine::SqlReply> {
        self.autocommit_with(sql, wal::engine::run_sql)
    }
    pub fn autocommit_with<T, F>(&mut self, sql: &str, runner: F) -> io::Result<T>
    where
        F: FnOnce(&Path, &str) -> io::Result<T>,
    {
        let id = self.begin()?;
        match self.query_with(id, sql, runner) {
            Ok(reply) => match self.commit(id) {
                Ok(_) => Ok(reply),
                Err(error) => {
                    let _ = self.rollback(id);
                    Err(error)
                }
            },
            Err(error) => {
                let _ = self.rollback(id);
                Err(error)
            }
        }
    }
    pub fn status(&self, id: u64) -> Option<char> {
        self.active.get(&id).map(|t| {
            if t.failed || t.snapshot.is_failed() || self.database.is_poisoned() {
                'E'
            } else {
                'T'
            }
        })
    }
    pub fn mark_failed(&mut self, id: u64) -> io::Result<()> {
        let transaction = self
            .active
            .get_mut(&id)
            .ok_or_else(|| bad("unknown transaction"))?;
        transaction.failed = true;
        Ok(())
    }
    pub fn revision(&self) -> u64 {
        self.database.revision()
    }
    pub fn active_count(&self) -> usize {
        self.active.len()
    }
    pub fn checkpoint(&mut self) -> io::Result<()> {
        self.usable()?;
        self.database.checkpoint()
    }
}
fn quote(s: &str) -> String {
    let mut out = String::from("\"");
    for c in s.chars() {
        match c {
            '"' => out.push_str("\\\""),
            '\\' => out.push_str("\\\\"),
            '\n' => out.push_str("\\n"),
            '\r' => out.push_str("\\r"),
            '\t' => out.push_str("\\t"),
            c if c < ' ' => out.push_str(&format!("\\u{:04x}", c as u32)),
            _ => out.push(c),
        }
    }
    out.push('"');
    out
}
fn command(sql: &str) -> &str {
    sql.trim().strip_suffix(';').unwrap_or(sql.trim()).trim()
}
fn run() -> io::Result<()> {
    let path = std::env::args()
        .nth(1)
        .ok_or_else(|| bad("usage: transactions DIRECTORY < one-SQL-per-line.txt"))?;
    let mut transactions = Transactions::open(Path::new(&path))?;
    let mut current = None;
    for line in io::stdin().lock().lines() {
        let line = line?;
        if line.trim().is_empty() {
            continue;
        }
        let cmd = command(&line);
        let result: io::Result<String> = if cmd.eq_ignore_ascii_case("BEGIN") {
            if let Some(id) = current {
                transactions.mark_failed(id)?;
                Err(bad("transaction already active; ROLLBACK required"))
            } else {
                transactions.begin().map(|id|{current=Some(id);format!("{{\"tag\":\"BEGIN\",\"transaction\":{id},\"status\":\"T\",\"revision\":{}}}",transactions.revision())})
            }
        } else if cmd.eq_ignore_ascii_case("COMMIT") {
            if let Some(id) = current {
                transactions.commit(id).map(|revision| {
                    current = None;
                    format!("{{\"tag\":\"COMMIT\",\"status\":\"I\",\"revision\":{revision}}}")
                })
            } else {
                Err(bad("no active transaction"))
            }
        } else if cmd.eq_ignore_ascii_case("ROLLBACK") {
            if let Some(id) = current {
                transactions.rollback(id).map(|()| {
                    current = None;
                    "{\"tag\":\"ROLLBACK\",\"status\":\"I\"}".into()
                })
            } else {
                Err(bad("no active transaction"))
            }
        } else if let Some(id) = current {
            transactions.query(id, &line).map(|reply| reply.json)
        } else {
            transactions.autocommit(&line).map(|reply| reply.json)
        };
        match result {
            Ok(json) => println!("{json}"),
            Err(error) => {
                let status = current
                    .and_then(|id| transactions.status(id))
                    .unwrap_or('I');
                println!(
                    "{{\"error\":{},\"status\":\"{status}\"}}",
                    quote(&error.to_string())
                );
            }
        }
    }
    if let Some(id) = current {
        let _ = transactions.rollback(id);
    }
    Ok(())
}
fn main() {
    if let Err(error) = run() {
        eprintln!("{error}");
        std::process::exit(2);
    }
}

핵심 요약

  • BEGIN 복사본은 다른 세션의 뒤늦은 커밋을 보지 않습니다.
  • dirty COMMIT은 global revision이 같아야 하며, readonly COMMIT은 쓰기가 없으므로 revision을 늘리지 않습니다.
  • 오류와 충돌 뒤에는 E를 유지하고 ROLLBACK으로 workspace를 정리합니다.
  • 행 MVCC·잠금 대기·deadlock은 비교 모형이며 실제 런타임 기능이 아닙니다.

7. 이 트랜잭션 계층이 못 하는 것

한 프로세스 안에서 여러 트랜잭션의 수명과 충돌을 관리할 수 있습니다. 하지만 아직 클라이언트가 네트워크로 접속하지 못하고, 기본키가 같은 SELECT도 어떤 접근 경로를 선택할지 설명하지 못합니다. 다음 장에서는 서버 연결과 실행 계획 선택을 붙이고, 세션 종료 시 rollback을 연결합니다.

작업공간은 DB 전체 복사라 디스크 사용과 BEGIN 비용이 크고, 최대 32개라는 제한은 행 수나 바이트 예산을 대신하지 않습니다. 행 MVCC·증분 스냅샷·교착 탐지·범위 잠금·여러 writer 프로세스는 구현하지 않았습니다. 커밋 직렬화와 coarse 검증으로 먼저 정확한 경계를 확인하는 학습용 계층입니다.
