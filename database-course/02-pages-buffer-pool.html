저장 엔진 · Chapter 02

페이지와 버퍼 풀

파일을 4KB씩 나누고, 필요한 조각만 메모리에 올립니다. 레코드를 넣을 자리와 메모리에서 내보낼 페이지를 직접 결정하는 저장 엔진을 만듭니다.

학습 목표

  • 페이지 번호를 파일 오프셋으로 바꾸고 정확히 4096바이트를 읽고 씁니다.
  • 슬롯 디렉터리로 가변 길이 레코드의 위치를 찾습니다.
  • pin count와 dirty flag를 구분하고 CLOCK으로 교체 대상을 고릅니다.
  • 재시작 후 데이터가 남는지 검사하고, 크래시 복구와의 차이를 설명합니다.

1. 로그에서 페이지로

1장은 덧붙이기로 최신 값을 기록했습니다. 값을 읽으려면 모든 키의 색인을 메모리에 두어야 했습니다. 이번 장에서는 파일을 고정 크기 페이지의 배열로 바꿉니다. 3장에서는 B+트리가 페이지 안에 키를 정렬하고, 다음으로 읽을 페이지를 가리킵니다. 그 전에 페이지 하나를 정확히 읽고 수정하는 기반이 필요합니다.

1장 파일은 그대로 보관하세요같은 프로젝트에 pages.rs 모듈을 추가하고 별도의 data.pages 파일을 사용합니다. 로그 파일을 페이지 파일로 열면 안 됩니다. 이 장의 실행 예제는 페이지 계층만 분리한 실행 파일입니다. 아직 set/get 명령이나 로그 데이터 변환은 제공하지 않습니다.

페이지 크기 4096바이트는 이 코스의 설계입니다. DB 페이지와 운영체제의 가상 메모리 페이지는 별개입니다. 예를 들어 PostgreSQL은 보통 8KB DB 페이지를 사용합니다. PostgreSQL 페이지 형식을 비교해 보세요.

페이지 번호 → 파일 위치
페이지 0은 파일의 첫 페이지입니다. 1, 2, 1024를 차례로 넣어 보세요.

파일에는 페이지 번호 자체를 저장하지 않습니다. offset = page_id × 4096으로 위치를 정합니다. 파일 길이가 4096의 배수가 아니면 마지막 페이지가 잘린 상태이므로 열기를 거부합니다. 페이지 쓰기에서는 append 모드를 사용하지 않습니다. 지정한 오프셋으로 이동한 뒤 write_all을 호출합니다.

2. 슬롯은 앞에서, 레코드는 뒤에서

가변 길이 레코드를 앞에서부터 이어 붙이면, 레코드의 위치를 알기 위해 앞의 길이를 모두 읽어야 합니다. slotted page는 앞쪽에 슬롯 디렉터리를 두고 각 슬롯에 위치와 길이를 저장합니다. 레코드 바이트는 페이지 끝에서 앞쪽으로 쌓습니다.

레코드의 식별자는 (page_id, slot_id)입니다. 바이트 오프셋을 직접 노출하지 않으면 나중에 페이지 내부를 압축해 레코드를 옮겨도 슬롯의 위치 값만 바꿀 수 있습니다. 이 장에서는 삽입과 조회만 구현합니다. 삭제·빈 슬롯 재사용·페이지 내부 압축은 실습 확장 주제입니다.

바이트 범위내용규칙
0..4magic: PG0250 47 30 32
4..6슬롯 수 nu16, little-endian
6..8upperu16, little-endian. 빈 페이지는 4096
8..8+4n슬롯 배열각각 offset(u16 LE) + length(u16 LE)
upper..4096레코드 바이트본문 형식은 아직 정하지 않음

lower = 8 + 4 × n, free = upper − lower입니다. 새 레코드 길이를 L이라 하면 L + 4 ≤ free일 때만 삽입합니다. 빈 레코드는 거부합니다. 빈 페이지에 넣을 수 있는 최대 레코드는 4096 − 8 − 4 = 4084바이트입니다.

슬롯 페이지에 레코드 넣기
같은 레이아웃을 4096바이트 비율로 그립니다. 길이는 UTF-8 글자 수가 아닌 바이트 수입니다. 레코드 내용은 생략합니다.
보라: 헤더 · 파랑: 슬롯 · 회색: 빈 공간 · 초록: 레코드
읽은 파일을 바로 구조체로 캐스팅하면 안 되나요?

Rust 구조체의 메모리 배치와 디스크 형식은 다릅니다. 패딩, 정렬, 엔디언에 의존하지 않도록 바이트 배열과 from_le_bytes를 사용하세요. 디스크에서 읽은 페이지는 magic, 경계, 슬롯 범위와 겹침을 검사한 뒤에만 접근합니다. 이 검사는 체크섬을 대신하지 않습니다.

본문 복사 → 슬롯 기록 → 헤더 갱신
페이지 삽입이 한 번에 끝나는 것처럼 보이지 않도록 메모리 내부의 변경을 나눴습니다. 문자열 길이와 기존 레코드 유무를 바꾸고 최종 빈 공간을 예측하세요.

폭은 개념도입니다. 문자열은 UTF-8 바이트로 셉니다. 공간 부족·빈 레코드는 어떤 바이트도 바꾸기 전에 거부합니다. 중간 단계는 크래시 후 안전하게 읽을 수 있다는 뜻이 아닙니다.

3. 버퍼 풀의 페이지와 프레임

페이지는 디스크의 논리 단위이고, 프레임은 메모리에서 페이지 하나가 머무는 자리입니다. 프레임 3개인 버퍼 풀은 최대 3페이지를 보관합니다. 페이지 8을 읽었을 때 이미 프레임에 있으면 hit입니다. 없으면 miss이며, 빈 프레임이나 교체 가능한 프레임을 확보한 뒤 읽습니다.

실제 시스템은 페이지 번호 → 프레임 번호 해시 맵을 둡니다. 이 장은 프레임 수가 작으므로 배열을 선형 탐색합니다. 페이지 형식과 교체 규칙을 먼저 확인하고, 매핑 최적화는 이후에 추가할 수 있습니다. 버퍼 풀 hit/miss는 OS 캐시 hit/miss와 다르므로 아래의 read 수를 물리 디스크 I/O 횟수로 해석하면 안 됩니다.

4. 사용 중인 페이지와 변경된 페이지

pin count는 현재 페이지를 사용 중인 요청 수입니다. fetch가 성공할 때마다 1 증가하고 작업이 끝나면 unpin으로 1 감소합니다. 0보다 크면 페이지를 내보낼 수 없습니다. 같은 페이지를 두 번 fetch하면 unpin도 두 번 필요합니다.

dirty flag는 메모리의 페이지가 파일에 쓴 내용과 달라졌다는 표시입니다. 수정에 성공한 직후 true로 바꿉니다. dirty 페이지를 교체할 때는 먼저 기존 페이지 번호의 위치에 씁니다. 쓰기가 실패하면 프레임과 dirty 상태를 유지하고 오류를 반환합니다.

pin을 빼먹으면

교체할 수 있는 프레임이 줄고, 모두 pin된 상태에서는 새 페이지 읽기가 실패합니다.

dirty를 빼먹지 않으면

변경한 페이지를 내보내기 전에 파일에 씁니다. 읽기 전용 페이지는 다시 쓰지 않습니다.

예제는 단일 스레드이며 프레임 번호를 수동으로 반납합니다. 반납한 프레임 번호는 다시 사용하지 마세요. 실제 API에서는 수명과 반납을 관리하는 page guard와 잠금이 필요합니다. pin은 교체 방지 장치이며, 동시 접근을 막는 mutex가 아닙니다.

5. CLOCK으로 교체 대상 고르기

LRU는 최근 사용 순서를 계속 갱신해야 합니다. CLOCK은 원형 배열과 손 하나로 근사합니다. 여기서는 참조 비트 R을 사용합니다. fetch가 성공하면 R=1로 만들고, 빈 프레임이 없을 때 손이 가리킨 프레임부터 검사합니다.

  1. 손을 다음 프레임으로 이동합니다.
  2. pin > 0이면 건너뜁니다.
  3. R=1이면 R=0으로 바꾸고 한 번 더 기회를 줍니다.
  4. pin=0이고 R=0이면 교체합니다. dirty이면 먼저 씁니다.

단일 스레드에서 검사 중 상태가 변하지 않으므로, 용량의 두 배만 검사하면 교체 대상을 찾거나 모두 pin되었다고 판정할 수 있습니다. 이 구현은 빈 프레임을 먼저 골라 쓰며, 그때는 손을 움직이지 않습니다.

3프레임 CLOCK 실험실
페이지 0~5는 이미 할당돼 있다고 가정합니다. fetch는 pin을 1 올립니다. 각 프레임에서 수정·unpin하고, 새 페이지를 요청해 교체 과정을 확인하세요. 초기화하면 모의 파일도 초기화됩니다.

예측하고 실행하세요0 fetch → 프레임 0 수정 → unpin → 1 fetch/unpin → 2 fetch/unpin → 3 fetch. 첫 순회에서 세 프레임의 R이 0이 되고, 다음 순회에서 페이지 0을 파일에 쓴 뒤 페이지 3으로 교체합니다. read=4, write=1입니다. 이후 0을 다시 fetch하면 저장된 수정 횟수 1이 돌아옵니다.

읽기·쓰기는 모의 성공 횟수입니다. dirty 쓰기 실패를 켜면 기존 프레임을 유지하는 오류 경로도 볼 수 있습니다. 위의 자유 조작 실험실과 상태를 공유하지 않습니다.

6. 파일에 쓰기와 크래시 복구

여기서 writeback은 write_all이 끝난 상태입니다. dirty를 해제해도 저장 장치에 영구 반영됐다는 뜻은 아닙니다. 예제의 명시적 flush는 pin된 프레임이 없는지 확인한 뒤 dirty 페이지를 모두 쓰고 File::sync_all의 성공 여부까지 확인합니다. 실패하면 호출자에게 오류를 반환합니다. Drop에서 자동 저장하지 않습니다.

Linux의 파일 동기화에는 fsync 계열 호출을 사용합니다. macOS는 fsync와 장치 캐시까지 비우도록 요청하는 F_FULLFSYNC를 구분합니다. 예제는 Rust 표준 라이브러리의 sync_all에 맡깁니다. OS별 세부 보장은 구현과 장치에 따라 확인해야 합니다. Apple의 동기화 설명도 참고하세요.

4096바이트 쓰기는 원자적 쓰기 보장이 아닙니다쓰기 도중 프로세스나 장치가 멈추면 페이지 일부만 바뀔 수 있습니다. 이 장에는 WAL, 체크섬, 트랜잭션, 다중 프로세스 파일 잠금이 없습니다. 정상 flush와 재시작 검사는 전원 차단 복구 검증을 대신하지 않습니다. 오류가 난 쓰기나 할당을 자동 복구하지 않으므로 실제 서비스 데이터에 사용하지 마세요. 7장에서 WAL과 복구 순서를 다룹니다.

접힌 참조 구현: pages.rs

pages.rs 저장. 아래 코드에는 12개 검사가 포함됩니다. fetch부터 unpin까지 사이에 오류가 발생한 경우도 반납을 보장하도록 개선하는 것은 실습 과제입니다.

use std::{fs::{File, OpenOptions}, io::{self, Read, Seek, SeekFrom, Write}, path::Path};
const SIZE: usize = 4096;
const HEADER: usize = 8;
const SLOT: usize = 4;
type PageId = u64;
fn invalid(message: &str) -> io::Error { io::Error::new(io::ErrorKind::InvalidData, message) }
fn busy() -> io::Error { io::Error::other("all frames are pinned") }

#[derive(Clone)]
struct Page([u8; SIZE]);
impl Page {
    fn new() -> Self {
        let mut p = Self([0; SIZE]);
        p.0[..4].copy_from_slice(b"PG02");
        p.put16(6, SIZE);
        p
    }
    fn u16(&self, at: usize) -> usize { u16::from_le_bytes([self.0[at], self.0[at+1]]) as usize }
    fn put16(&mut self, at: usize, value: usize) { self.0[at..at+2].copy_from_slice(&(value as u16).to_le_bytes()); }
    fn count(&self) -> usize { self.u16(4) }
    fn lower(&self) -> usize { HEADER + self.count() * SLOT }
    fn free(&self) -> usize { self.u16(6) - self.lower() }
    fn validate(&self) -> io::Result<()> {
        if &self.0[..4] != b"PG02" { return Err(invalid("bad page magic")); }
        let lower = self.lower();
        let upper = self.u16(6);
        if lower > upper || upper > SIZE { return Err(invalid("bad page boundaries")); }
        let mut ranges = Vec::new();
        for slot in 0..self.count() {
            let at = HEADER + slot * SLOT;
            let start = self.u16(at);
            let len = self.u16(at+2);
            if len == 0 || start < upper || start + len > SIZE { return Err(invalid("bad slot")); }
            ranges.push((start, start+len));
        }
        ranges.sort_unstable();
        if ranges.windows(2).any(|w| w[0].1 > w[1].0) { return Err(invalid("overlapping slots")); }
        Ok(())
    }
    fn insert(&mut self, bytes: &[u8]) -> io::Result<u16> {
        if bytes.is_empty() || bytes.len() > self.free().saturating_sub(SLOT) || self.free() < SLOT {
            return Err(io::Error::other("record does not fit"));
        }
        let slot = self.count();
        let end = self.u16(6);
        let start = end - bytes.len();
        self.0[start..end].copy_from_slice(bytes);
        self.put16(HEADER + slot*SLOT, start);
        self.put16(HEADER + slot*SLOT+2, bytes.len());
        self.put16(4, slot+1);
        self.put16(6, start);
        Ok(slot as u16)
    }
    fn get(&self, slot: u16) -> Option<&[u8]> {
        let slot = slot as usize;
        if slot >= self.count() { return None; }
        let at = HEADER + slot*SLOT;
        let start = self.u16(at);
        Some(&self.0[start..start+self.u16(at+2)])
    }
}

struct Disk { file: File, pages: u64 }
impl Disk {
    fn open(path: &Path) -> io::Result<Self> {
        let file = OpenOptions::new().read(true).write(true).create(true).truncate(false).open(path)?;
        let len = file.metadata()?.len();
        if len % SIZE as u64 != 0 { return Err(invalid("partial page file")); }
        Ok(Self { file, pages: len / SIZE as u64 })
    }
    fn offset(&self, id: PageId) -> io::Result<u64> {
        if id >= self.pages { return Err(invalid("page not allocated")); }
        id.checked_mul(SIZE as u64).ok_or_else(|| invalid("offset overflow"))
    }
    fn read(&mut self, id: PageId) -> io::Result<Page> {
        let offset = self.offset(id)?;
        self.file.seek(SeekFrom::Start(offset))?;
        let mut p = Page([0; SIZE]);
        self.file.read_exact(&mut p.0)?;
        p.validate()?;
        Ok(p)
    }
    fn write(&mut self, id: PageId, page: &Page) -> io::Result<()> {
        let offset = self.offset(id)?;
        self.file.seek(SeekFrom::Start(offset))?;
        self.file.write_all(&page.0)
    }
    fn allocate(&mut self) -> io::Result<PageId> {
        let id = self.pages;
        let offset = id.checked_mul(SIZE as u64).ok_or_else(|| invalid("offset overflow"))?;
        self.file.seek(SeekFrom::Start(offset))?;
        self.file.write_all(&Page::new().0)?;
        self.pages += 1;
        Ok(id)
    }
}

struct Frame { id: PageId, page: Page, pins: usize, dirty: bool, referenced: bool }
struct Pool { disk: Disk, frames: Vec<Option<Frame>>, hand: usize, reads: u64, writes: u64 }
impl Pool {
    fn new(disk: Disk, capacity: usize) -> io::Result<Self> {
        if capacity == 0 { return Err(io::Error::other("capacity must be positive")); }
        Ok(Self { disk, frames: (0..capacity).map(|_| None).collect(), hand: 0, reads: 0, writes: 0 })
    }
    fn victim(&mut self) -> io::Result<usize> {
        if let Some(i) = self.frames.iter().position(Option::is_none) { return Ok(i); }
        for _ in 0..self.frames.len()*2 {
            let i = self.hand;
            self.hand = (self.hand+1) % self.frames.len();
            let f = self.frames[i].as_mut().unwrap();
            if f.pins > 0 { continue; }
            if f.referenced { f.referenced = false; continue; }
            return Ok(i);
        }
        Err(busy())
    }
    fn writeback(&mut self, i: usize) -> io::Result<()> {
        if let Some(f) = &mut self.frames[i] {
            if f.dirty {
                self.disk.write(f.id, &f.page)?;
                self.writes += 1;
                f.dirty = false;
            }
        }
        Ok(())
    }
    // Every successful fetch owns one pin. Release it exactly once with unpin.
    fn fetch(&mut self, id: PageId) -> io::Result<usize> {
        if let Some(i) = self.frames.iter().position(|f| f.as_ref().is_some_and(|f| f.id == id)) {
            let f = self.frames[i].as_mut().unwrap();
            f.pins += 1;
            f.referenced = true;
            return Ok(i);
        }
        let i = self.victim()?;
        // Read before replacing: a failed read must not destroy the old frame.
        let page = self.disk.read(id)?;
        self.reads += 1;
        self.writeback(i)?;
        self.frames[i] = Some(Frame { id, page, pins: 1, dirty: false, referenced: true });
        Ok(i)
    }
    fn pinned(&self, i: usize) -> io::Result<&Frame> {
        self.frames.get(i).and_then(Option::as_ref).filter(|f| f.pins > 0)
            .ok_or_else(|| io::Error::other("frame is not pinned"))
    }
    fn insert(&mut self, i: usize, bytes: &[u8]) -> io::Result<u16> {
        self.pinned(i)?;
        let f = self.frames[i].as_mut().unwrap();
        let slot = f.page.insert(bytes)?;
        f.dirty = true;
        Ok(slot)
    }
    fn get(&self, i: usize, slot: u16) -> io::Result<Option<&[u8]>> { Ok(self.pinned(i)?.page.get(slot)) }
    fn unpin(&mut self, i: usize) -> io::Result<()> {
        self.pinned(i)?;
        self.frames[i].as_mut().unwrap().pins -= 1;
        Ok(())
    }
    fn flush(&mut self) -> io::Result<()> {
        if self.frames.iter().flatten().any(|f| f.pins > 0) { return Err(busy()); }
        for i in 0..self.frames.len() { self.writeback(i)?; }
        self.disk.file.sync_all()
    }
}

fn main() -> io::Result<()> {
    let path = std::env::args().nth(1).ok_or_else(|| io::Error::other("usage: pages FILE"))?;
    let mut disk = Disk::open(Path::new(&path))?;
    if disk.pages == 0 { disk.allocate()?; }
    let mut pool = Pool::new(disk, 2)?;
    let f = pool.fetch(0)?;
    if pool.frames[f].as_ref().unwrap().page.count() == 0 { pool.insert(f, b"abc")?; }
    println!("page=0 slot=0 value={}", String::from_utf8_lossy(pool.get(f, 0)?.unwrap()));
    pool.unpin(f)?;
    pool.flush()?;
    println!("reads={} writes={}", pool.reads, pool.writes);
    Ok(())
}

핵심 요약

  • 페이지 번호는 파일 위치를 정하고, 슬롯 번호는 페이지 내부의 레코드를 가리킵니다.
  • pin은 교체를 막습니다. dirty는 다시 써야 한다는 표시입니다.
  • CLOCK은 pin을 건너뛰고 참조 비트를 내린 뒤 교체합니다.
  • flush 후 재시작 성공과 크래시 복구 보장은 다릅니다.

확인 문제

빈 페이지에 레코드 하나만 넣을 때 최대 길이는?
헤더 8바이트와 슬롯 4바이트가 필요합니다.
같은 페이지를 두 번 fetch하고 한 번 unpin했습니다. 교체할 수 있나요?
fetch마다 pin을 얻습니다. 횟수가 대응해야 합니다.
CLOCK이 pin=0, R=1인 프레임을 만나면?
참조 비트가 있으면 한 번의 기회를 더 줍니다.
dirty 페이지의 write_all이 실패했습니다. 무엇을 해야 하나요?
쓰기가 끝나기 전에 기존 데이터를 버리면 안 됩니다.
버퍼 풀 read가 10회라는 것은?
OS 캐시가 요청을 처리할 수 있습니다. 물리 I/O와 별도 지표입니다.

실습 과제

  1. 반납 누락을 재현하세요. 용량 1에서 페이지 0을 fetch한 뒤 페이지 1을 요청합니다. 오류가 나고 페이지 0의 내용이 유지되어야 합니다. unpin 후 같은 요청은 성공해야 합니다. 두 번 fetch했다면 unpin 한 번으로 충분한지도 확인하세요.
  2. 삭제와 페이지 내부 압축을 추가하세요. 길이 0을 삭제 슬롯으로 예약하고 슬롯 수는 줄이지 마세요. 슬롯 0/1/2를 넣고 1을 삭제한 뒤 압축해도 0과 2의 슬롯 번호와 값이 같아야 합니다. 새 데이터를 넣을 때 빈 슬롯 재사용 여부를 정하고, 예전 식별자가 다른 레코드를 가리킬 수 있는 문제를 기록하세요.
  3. page guard API를 설계하세요. fetch 뒤 insert가 공간 부족으로 실패하는 경로를 만드세요. 오류를 반환해도 pin이 남지 않아야 합니다. 반납한 프레임 번호의 재사용을 타입으로 막는 방법을 검토하세요.

8. 이 저장 구조가 못 하는 것

이제 페이지를 저장하고 메모리에서 교체할 수 있습니다. 하지만 키로 레코드를 찾는 규칙이 없어, 모든 페이지의 모든 슬롯을 읽어야 합니다. 페이지 수가 늘어나도 검색량을 줄일 수 없습니다. 다음 장에서는 B+트리를 페이지에 배치하고 키의 범위에 따라 읽을 페이지를 선택합니다.
