# 동시성과 비동기, 밑바닥부터 · C#

[index.html](index.html)을 브라우저에서 엽니다. 빌드·로그인·외부 라이브러리 없이 작동합니다. 기존 Course Library에서도 들어올 수 있습니다.

주 4–6시간 × 8주. 각 장은 개념 설명, SVG 도식, 가상 실행 실험, C# 실습, 확인 문제 순서입니다. 실험에는 단계 실행, 재생·일시정지, 초기화가 있습니다. 진도와 퀴즈 응답은 브라우저에 저장됩니다.

| 주 | 주제 | 조작할 내용 |
|---|---|---|
| 1 | 명령 실행·호출 스택·힙 | 한 명령마다 변하는 프레임과 객체 |
| 2 | 프로세스·스레드·스케줄링 | 코어 수와 시간 할당량 |
| 3 | I/O·블로킹·비동기 | 같은 대기를 순차 처리하거나 겹치기 |
| 4 | 경쟁·락·데드락 | A/B 명령 순서와 락 획득 순서 |
| 5 | Task·async/await·상태 머신 | 미완료 await, 동기 대기, 완료된 await |
| 6 | 처리량·Channel·역압력 | 입력률, Worker 수, 처리 시간, 큐 상한 정책 |
| 7 | 타임아웃·취소·자원 수명 | 토큰 전달과 관찰, WaitAsync, 원격 작업 |
| 8 | 종합 작업 처리기 | CPU/I/O 비율, 동시 작업 상한, CPU 병렬성 |

웹 실험은 결정적 개념 모델입니다. 가상 틱은 실제 밀리초가 아니며, 실제 OS 스케줄러와 .NET 성능을 재현하지 않습니다. 5장의 단일 실행기는 직렬 실행 환경을 가정하며 일반 Console 앱의 실행 구조와 구분합니다. C# 실습은 .NET 10 SDK가 필요합니다. [실행 안내](examples/README.md)를 참고하세요.

## 매주 공부하는 방법

1. 목표와 설명을 읽고 도식에서 실행 주체·공유 자원·대기를 찾습니다.
2. 버튼을 누르기 전에 다음 상태를 예상합니다.
3. 한 단계씩 진행하고 예상과 다른 이유를 적습니다.
4. 입력 조건 하나만 바꾸고 비교합니다.
5. C# 예제를 실행해 브라우저 모델과 실제 출력의 차이를 기록합니다.
6. 확인 문제에 답하고, 결과가 나온 이유를 자기 말로 설명합니다.

## 마지막 주의 완료 기준

- CPU 작업과 I/O 대기에 맞는 처리 방식을 근거와 함께 선택합니다.
- Channel 용량과 실행 중 Worker 수를 각각 제한합니다.
- 일시 오류만 제한된 횟수로 재시도하고 영구 오류는 분리합니다.
- 취소 요청을 작업에 전달하고 모든 작업과 자원 정리를 기다립니다.
- 성공·실패·시도·타임아웃·지연·처리량을 기록합니다.
- 로컬 중복 방지와 외부 효과의 영속 멱등성을 구분합니다.

## 검증

```sh
node --check app.js
node --check content.js
node --check diagrams.js
node --check models.js
node --test models.test.cjs
```

모델 시나리오 11개가 통과했습니다. 스케줄러 중복 실행, I/O 대기 보존, 경쟁 상태·데드락, 큐 작업 수 보존·상한, 취소와 정리, 틱별 완료 건수를 검사합니다. 8장·16문제의 데이터 구조와 소스 링크도 확인했습니다.

제작 환경에는 .NET SDK가 없어 C# 컴파일·실행을 확인하지 못했습니다. 브라우저 제어 도구도 연결되지 않아 실제 화면·모바일·버튼의 브라우저 검증은 수행하지 못했습니다. JavaScript 구문과 모델 검증 통과는 이 두 검증을 대신하지 않습니다.
