코스 목록

C# 동시성과 비동기 심화

기본 8장의 실행·공유 상태·Task·큐를 실제 런타임 계약과 검증으로 확장합니다. 각 실험은 로컬 실습이며 예상 관측과 실제 실행 기록을 구분합니다.

기존 코스 목차

  1. .NET 메모리 모델과 안전한 공개

    카운터의 lost update를 막았더라도 “준비됨”을 본 소비자가 관련 데이터까지 안전하게 읽는지는 별도 문제입니다. 공유 상태 장의 원자성을 가시성과 공개 순서로 확장합니다.

  2. ThreadPool과 starvation 진단

    Task가 전용 스레드가 아니라는 사실을 알았는데도 CPU가 한가한 서버의 응답이 느릴 수 있습니다. 실행할 일이 없다는 상태와, 실행할 스레드가 대기에 묶인 상태를 구분합니다.

  3. async 상태 머신과 awaiter

    첫 미완료 await에서 호출자로 돌아오는 로그를 이제 컴파일러가 보존하는 상태로 설명합니다. 소스 한 줄과 재개 지점을 연결하면 예외와 자원 수명도 읽을 수 있습니다.

  4. 재개 위치와 실행 문맥

    await 뒤 스레드 번호가 바뀌어도 요청 ID는 유지될 수 있습니다. 재개할 실행 장소와 논리 호출 문맥을 분리해야 UI 교착과 컨텍스트 유실을 같은 문제로 오해하지 않습니다.

  5. 비동기 완료 신호와 상호 배제

    완료 신호를 보내는 순간 대기자의 코드가 실행된다면 생산자도 재진입을 고려해야 합니다. 카운터 락에서 완료·대기·수명의 계약으로 범위를 넓힙니다.

  6. Channel 파이프라인과 비동기 열거

    한 단계 큐의 상한을 정해도 다음 단계가 무한히 결과를 보관하면 전체 메모리는 제한되지 않습니다. 여러 단계의 완료와 오류를 한 수명으로 연결합니다.

  7. CPU 병렬화와 데이터 분할

    코어 두 개에서 실행이 겹치는 그림을 실제 계산 작업으로 옮깁니다. 작업 수를 늘리는 것보다 공유 갱신과 분할·병합 비용을 줄이는 일이 먼저일 수 있습니다.

  8. 동시성 결함의 재현과 검증

    가끔 통과하는 테스트는 경쟁 지점을 지났는지도 알려 주지 않을 수 있습니다. 실패·취소를 다룬 뒤에는 실행 순서를 통제하고 보존해야 할 결과를 검사합니다.
